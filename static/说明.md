# 前端资源

四个页面住在 `static/` 下，各自独立：没有打包器、没有依赖、没有共用底座。
这份说明管的是**它们与前端的约定**；页面的业务内容由服务端投影决定，
投影的出处是各命令组件的说明。

## 边界：web 只展示，数据都来自后台

四个页面都只是展示层，**页面上出现的每一个事实都由后台给**。页面负责的是 DOM、颜色、
排版，以及把后台给的数按中文习惯印出来（千分位、两位小数、时间格式）。

- 后台给的：文案与模板、名称、颜色、数值、分组（阵营 / 队伍）、状态、事件文本、
  图例取值、一块区域的海拔上下限。页面**不许**自己判断谁和谁是一方、也不许自己凑一句话。
- 页面可以算的：把后台列表的**条数**说出来这类不新增事实的算术（「11 个区域」），
  以及像素、坐标、缩放、标签避让这些纯渲染的东西。
- **凡是要遍历原始数据才得到的数，必须由后台给。** 这条以前破过：舆图页面自己在浏览器里
  按坐标带扫一遍 100 × 100 的地表栅格，算出各区域的海拔上下限再显示——那是展示层在算数据。
  第 86 轮挪回 `game/core/world`（区域的 `海拔范围`），页面只留格式化。

### 战报页面的地址约定

战报页面按「分享地址」设计：页面住在 `/battle/<战报编号>`，数据从**同前缀的一个接口**取——
`/battle/<编号>/data`，用 `view` 参数说明要哪一份：

| 取什么 | 请求 |
| --- | --- |
| 首屏（概览、演员表、花名册、片段表） | `/battle/<编号>/data` |
| 一个片段（时间线 + 参战者快照） | `/battle/<编号>/data?view=segment&index=<序>` |
| 一个片段的全部事件 | `/battle/<编号>/data?view=events&index=<序>` |
| 某一侧的参战者状态 | `/battle/<编号>/data?view=participants&index=<序>&snapshot=<before\|after>` |
| 一次行动的前后状态 | `/battle/<编号>/data?view=transition&index=<序>&sequence=<序>` |

**服务端是 `game/cmd/通用/战报/site.py` 那个二级组件**（第 118 轮补上）：它按编号从存档战报
**现算**画面，展示包本身不进存档——一次十五人对十五人的仗，展示包比战报还大，而它每一步都能
从战报算出来。

**画像是实时取的，服务端与页面都不缓存**（第 119 轮）：这类页面多半只看一次，而战报记录本身
只留很短一段时间；缓存一旦与存档错开，玩家看到的就是上一版画面。所以每次调用都按存档现算，
`Cache-Control: no-store`，翻片段、切模式都要重新要一次。**没有离线/预览模式**——那会把整场
数据再打一份包，与这一个接口互为副本。

在 `/battle/…` 之外打开时它由 `/static` 直接发出去，样式与脚本用的是相对路径（`./style.css`），
只在这个目录下有效。

## 缓存与版本

- 四个页面的 HTML 都由服务端 `no-store` 下发。
- `/static` 下的资源一律 `no-cache` + ETag（`launch/mount.py` 的 `NoCacheStaticFiles`）：
  每次回来问一遍，内容没变只回 304。
- 因此**不许在页面或模块导入里写 `?v=数字`**。以前那套手工版本号要在五个地方同步
  （`index.html` 的链接、`app.js` 的 `import "./ui.js?v=20"`……），漏一处就是老模块
  配新模块；现在由 ETag 负责，`检查静态资源.py` 会拦下新写进来的版本号。

## 页面策略

- 每个下发页面的 `site.py` 都要带 `Content-Security-Policy`；后台页面的策略常量是
  `CONSOLE_CSP`，放开的三处都是页面真实需要的：KaTeX 的样式、脚本与字体走
  `cdn.jsdelivr.net`（两个文件都带 `integrity`，内容被改就加载不出来），
  `img-src` 放开 http/https 是因为消息图片允许外链（本地图片已经由消息媒体目录
  物化成 `/game-console/media/`）。
- 页面的脚本策略不含 `unsafe-inline`，所以**页面里不许写内联脚本与内联样式**：
  内联会被浏览器静默拒绝，比报错更难查。
- KaTeX 的数学排版用的是行内样式，但那是脚本经 CSSOM 写上去的，不需要 `unsafe-inline`。
  这一条是在无头浏览器里拿**真正的 `CONSOLE_CSP`** 跑出来的：公式渲染成功、
  样式表 249 条规则生效、图片可加载、零条策略拦截。

## 样式

- 每个应用一份 `style.css`，各写各的。四个应用之间没有重复的规则块，
  别为了省几行去抽公共底座。
- 战报页面的参战者面板**收起时也印一份名录**（编号徽章 + 名字 + 血气/精神条），
  展开时才换成完整记录：面板收起来后左边那一栏本来会空成一片。
  宽屏（≥861px）上面板钉在左侧，读到后面也看得见血条。
- 类名必须真的有人建立：写进 CSS 而全工程没人加这个类，就是死样式。
  模板拼出来的前缀算活，两种写法都认——前端的 `` `tone-${…}` `` 与后端的
  `class="message-quote depth-{min(depth, 3)}"`。
- 判据见 `tools/架构审查/检查静态资源.py`（7 项），已登记在 `tools/全量核对.py` 的必过项里。

## 事件行是谁定的

战报页面的两处「内容」都不在前端：简要行（战斗记录）与明细行印什么，由后端投影决定
（`战斗/展示/战报.json` 的 `标准化.紧凑事实` 与 `标准化.内部明细`）。前端只把 `text`
与 `facts` 印出来——**别在前端加兜底文案**，那会让同一句话有两个出处。
判据是 `tools/架构审查/检查战报展示.py`（跑一场真实战斗核对七件事）。

## 一条信任边界

天道后台把服务端投影好的 `content_html` 直接插进页面，用 `innerHTML` 是安全的
**只因服务端已经转义**：`game/cmd/后台/天道后台/presentation.py` 只拼自己造的标签，
文本一律过 `html.escape`，链接另过 `_safe_url`。改那份投影时不能漏掉转义——
前端不会再兜一次。

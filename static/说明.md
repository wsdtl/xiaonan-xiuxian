# 前端资源

15 个页面住在 `static/` 下（3 个非工具页 + 12 个工具页，工具页含百科、意境与说明帮助页 `info/`），各自独立：没有打包器、没有依赖、没有共用底座。页面只做 DOM、颜色、排版和格式化，**每一个事实都由后台给**；说明帮助页是例外，它是纯静态介绍页。

## 边界

- 后台给：文案与模板、名称、颜色、数值、分组、状态、事件文本、图例、区域海拔上下限。
- 页面可算：条数这类不新增事实的算术，以及像素、坐标、缩放、标签避让。
- 凡要遍历原始数据才得到的数，必须由后台给。
- 页面不判断谁和谁一方，不自己凑句子，不写兜底文案。

工具类统一住 `static/tool/<页面>/`，非工具类留在 `static/<页面>/`；命令页对外地址不变，只改文件位置与静态资源前缀；`info` 的静态地址随目录变为 `/static/tool/info/index.html`。

## 样式口径

工具页共用一套墨底玉金模板：`#0a0e14` 墨底、`#e8eef7` 纸色、`#4fe0bb` 玉色、`#e6c184` 金色，衬线标题，`#app` 居中，`.bar`／`.target`／`.med`／`.cmd` 与胶囊控件，12/16 圆角、两级阴影，560px 断点。模板按页搬，不抽公共底座。

工具页（含百科、意境、说明帮助页）共用这套模板；非工具页不套它：舆图用暖纸底，后台与战报保持自己的浅色。**不要把墨底玉金的根令牌搬进非工具页。**

## 装配台接口

装配台是唯一允许提交纯编解码请求的页面；资格与资产消耗仍由服务端决定。

| 接口 | 用途 |
| --- | --- |
| `GET /assembly` | HTML，CSP 只允许本站资源 |
| `GET /assembly/data?scope=all` | 完整构筑目录 |
| `GET /assembly/data?scope=user:<身份>` | 已公开用户的候选与当前构筑 |
| `GET /assembly/content?section=<类别>&content_id=<编号>` | 按需读能力正文 |
| `POST /assembly/scheme` | 解析/生成公开方案，**不写存档**；请求体上限 32 KiB |

页面与 JSON 都是 `no-store`；关闭公开后新读取立即拒绝，已看过的内容与已分享的码无法追溯收回。

## 工具页：只挑不执行

八张工具页共用一副形状：页面只负责挑，挑完给出「要发的命令原文」让玩家复制回聊天。执行、地点门槛、守卫、扣料与事务全留在命令与核心；核心拒绝时页面照转原话。

工具页读全局开关 `网页资源公开` / `网页资源关闭`；浏览器记住上次选的人，也支持 `?scope=` 深链。

## 战报页面

| 取什么 | 请求 |
| --- | --- |
| 整场战报 | `/battle/<编号>/data?view=animation` |

页面只请求这一份，文本与动画共用同一份 `game.battle_animation`：单位、阵法、环境、事件。
服务端按编号从存档**现算**画面，展示包不进存档；不缓存，`Cache-Control: no-store`。

## 缓存与安全

- 页面 HTML 由服务端 `no-store` 下发；`/static` 走 `no-cache` + ETag，不写 `?v=数字`。
- 每个 `site.py` 带 CSP；页面脚本策略不含 `unsafe-inline`，所以不写内联脚本与内联样式。
- 后台的 `content_html` 已由服务端转义；前端不再兜底。

# 角色核心微服务

角色服务解释 `data/角色/规则`、`data/角色/定义`、战斗属性和境界，并拥有玩家角色资产的创建写入权限。本命武器的初始等级、攻击、经验、器阶和器律孔统一调用 `game/core/forging`，角色服务只保存人物自己的武器状态。玩家的行为、队伍和控制状态由 `game/core/player_state` 独立解释和变更，地表位置由 `game/core/location` 独立持有。

创建人物是一笔数据库事务，写入 `character/main`、`cultivation/main`、`weapon/main`、`player_state/main`、`player_location` 和初始丹药背包状态。普通物品状态键只保存 `编号:品级`，物品类别统一由 JSON 编号定义解析。服务只接收稳定用户编号、创建输入和出生地 `xy`，不读取命令文本，也不直接访问 JSON 文件系统。

角色资产不保存 `xy`，也不提供移动接口。`public_profiles()` 按一批稳定用户编号只读取姓名、性别、境界和等级，供附近展示使用，不加载背包、修行槽或本命武器。

`profile(user_id)` 一次读取该用户的全部资产快照，严格解释人物、修行槽、本命武器和背包摘要。缺少创建事务应当写入的任一主体状态时直接报错，不使用代码默认值补造人物资产；地点和行为、队伍、控制状态仍由玩法层分别向位置、世界与玩家状态服务取得。

## 整套装配

`assembly_limits()` 返回正式规则的全局槽位上限。`plan_assembly(user_id, build, retain_replaced=False)` 返回 `CharacterAssemblyPlan`，只规划不提交。按最终构筑判相冲，保留未变槽及借阅元数据，汇总变化槽库存消耗；资产、修行槽、本命武器的版本全部加入同一计划，由玩法提交。现有单项方法不改变。

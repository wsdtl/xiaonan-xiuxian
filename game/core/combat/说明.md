# 战斗核心微服务

`game.core.combat` 是战斗结算的唯一公共微服务，第 24 位装配（依赖 `data`、`formation` 与 `bloodline`）。它不读文件、不拥有角色资产，只消费已装载的「战斗定义」「战斗规则」「战斗展示」。

```text
CoreServices.data
  -> load_battle_foundation(data)
  -> BattleEngine / DamageEngine / MechanismRuntime
  -> CombatService
  -> CoreServices.combat
```

## 职责

- 行动条、技能冷却、伤害、状态、监听、事件链、召唤、构造物、整场模拟。
- 结构化战报与展示协议；展示对象由后端生成，页面只渲染。
- 功法、真意、气机、器律在装配时按编号取实体；卡片本身就是完整能力树，不做中间层回查。
- 阵法以战场级引用传入，由阵法核心解析；战斗核心只接收不可变快照。

## 不负责

- 创建人物、敌人、道侣或灵兽资产；
- 决定构筑的获取与装配限制；
- 发放玩法奖励或写玩法进度；
- 评分与平衡。

## 公共契约

其他业务只能从包顶层使用 `CombatRequest`、`CombatantSpec`、`CombatBuildRef`、`CombatGroupSpec`、`CombatResult`、`CombatService`；`engine.py`、`models.py`、`mechanics.py` 等是内部实现。

```python
result = await combat.execute(
    CombatRequest(
        left_team=(player,),
        right_team=(enemy,),
        seed=123,
        action_limit=2000,
    )
)
```

`CombatantSpec.build` 只带编号与实例；阵法和恢复丹分别用 `formation_id`、`medicine_id`。构筑形状由 `builds.py` 在装配时校验，越界即终止启动。

## 战报事实

- `战斗/定义/事件.json` 是事件全集；战报展示逐项声明分类与显示名，少项、多项或旧事件名都会拒绝启动。
- `战斗/展示/战报.json` 是名称、分类、颜色、文案与默认选项的唯一来源。
- 伤害、恢复、消耗与状态变化只按 `标准化.结算事件` 统计，不重复计前置判定与镜像事件。
- 展示时间线只重放前后数值；结束后血气、神魂、精神、护盾必须与 `CombatResult` 一致。

## 公共编组

`CombatGroupSpec` 是所有战斗模式共用的请求结构：每组保存成员与主战者编号，战斗核心只做边界校验、目标范围与结果归属。探险、宗门战与切磋都转成这份契约，不另造编组实体。

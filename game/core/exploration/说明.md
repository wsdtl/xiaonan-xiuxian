# 探险核心

探险开始时按正式战斗核心一次性计算全部真实战斗，并在一个事务中保存不可变会话、逐场记录、预计丹药消耗和所有参与者的`探险中`状态。发起者已经布下的待战阵法只进入首场战斗，并与探险开始事务一起清除；预计算或提交失败时不会误耗。每场代表120秒，最多15场；所有我方正式单位死亡时提前结束。

逐场结果只按时间解封，不重新计算。每名战败敌人只结算一次自身掉落；掉落按本场仍有角色存活的用户均分，不可拆分数量向下取整，余数丢弃。所有参与者都能查看进度，首次结算只能由发起者执行；结算完成后其他成员只能读取同一份结果。结算在实际结束时间后按公共结算契约一次写入最终血气、精神、本命武器经验、灵石、物品、空闲状态和结算事实。重启后从 SQLite 恢复同一会话和预计算结果。

人物和同行道侣的长期伤势在开始时分别读取。每场真实战斗结束后由伤势核心根据该场战果演化，下一场立即重新装配；探险本身不治疗伤势。最终伤势快照随会话保存，只在探险结算事务中与其他结果一同落库。

## 为什么逐场记录留在资产库（不搬去非资产库）

逐场记录**不是**对外分享用的战报，而是**玩法状态**：它与探险会话、预计消耗、参与者的状态变更写在**同一个事务**里，读取侧还有「逐场记录不完整就报错」的判据兜底。搬去非资产库就等于把它拆成**跨两个库的两阶段写**，会把「要么全成、要么全不成」这条保证打掉——所以它明确留在资产库，与分享用的战报（那才是非资产数据）分开对待。

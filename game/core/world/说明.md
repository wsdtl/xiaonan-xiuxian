# 世界地点服务

世界核心服务负责把正式 JSON 中的世界定义解析成地点查询结果、只读地图快照与即时行程规划。

- `LocationQuery.location_name`：按地点目录和主体文件名查询，返回地点业务数据、可用功能、派生资源池和单次遭遇数量。
- `LocationQuery.xy`：按 `xy` 查询，返回区域、地形和地表海拔；坐标不在命名地点时，视为野外地表。
- 地点目录和主体文件名就是唯一地点身份与玩家名称，不再维护第二个显示名称。
- `交易`、`锻造` 只作为地点功能事实返回，世界服务不实现交易或炼器流程。
- 地表海拔只从 `data/世界/内容/地势.json` 读取，坐标范围由同一文件声明。
- 区域与地形是两套独立坐标域：区域来自区域 JSON 的 `坐标带`，地形来自全局 `地形分区.json`，二者都完整覆盖全境且互不重叠。
- 灵植池和灵矿池由地形名称派生；道侣池和敌人池由地点功能及同目录同名内容文件派生。
- `plan_journey()` 按道路、地形、海拔和境界生成最优路线、十二项行程指标、压缩通行段与玩家叙事；排序严格采用“折算路程、道路段数、水平距离”。
- 道路边覆盖地形倍率；非道路边采用两端地形倍率平均；高差独立计入折算路程。规则全部来自 `data/行路/规则`（`地形通行.json` 与 `道路通行.json`）。
- 二十个境界各有独立的行路方式和起程、途中、抵达叙事，来自 `data/行路/展示/行程.json`，代码不按境界名称猜测文案。
- 服务不保存玩家位置，不创建行路状态，也不触发探险、修士或战斗。
- `map_view()`：按协议版本 2 一次性交付世界说明、坐标边界、100×100 高度场、11 个不规则区域、85 片独立地形、地点与道路；每个坐标域都带坐标带、外接边界、标签坐标和格数，展示层不再读取 JSON，也不得另写一份地图点位。
- 地图快照按数据坐标保存，Web 展示只负责把更大的 `y` 绘制到画面上方，因此北境在上、南境在下；镇岳防线的范围仍由区域 JSON 决定。

公开调用只经过 `game.core.world` 包顶层，业务命令不读取世界 JSON 内部结构。

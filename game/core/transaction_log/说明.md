# 事务流水（核心微服务）

**管什么**：已提交事务的幂等回执——落库、按（scope, 玩家, 请求号）回读、按玩家保留最近 N 条。

**为什么独立**：它原本住在 `game/core/database/storage.py` 里，与主库的状态存储混在一个 61 KB 的文件里。
2026-10-14 归位为独立核心微服务（委托方指示）。

**存在哪**：与消息流水、战报**同一个**非资产库（路径单一来源：`game/core/database/battle_report.py` 的
`runtime_log_database_path()`，最终来自 `game/config.py` 的 `GameRuntimeLogConfig`）。表：`log_committed_transactions`。

**协议**：SQL 原语成对提供——
`read_receipt` / `write_receipt`（自己开连接，日常用）；
`read_receipt_on` / `write_receipt_on`（收一个现成连接，供提交路径的两阶段事务用，别处不要用）；
另加 `count_receipts` / `prune_receipts`（保留策略）。

**保留策略**：每玩家最多 `_RECEIPT_LIMIT_PER_USER`（100）条，TTL 7 天（`RECEIPT_TTL_SECONDS`）。

**谁在用**：`game/core/database/storage.py` 的 `commit()`（两阶段舞，原子性写法未变）与
`committed_transaction()`；调用方 `game/core/alchemy/service.py`。

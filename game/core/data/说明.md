# JSON 数据核心微服务

当前布局为 `data/<组件>/{定义,规则,内容,展示}`。入口 `基础/读取规则.json` 登记组件，各包 `组件.json` 登记本包文件规则。清单为加载元数据，不计入业务文档数量。数据集名、实体编号和池文件名不变。

`game.core.data` 是核心微服务层的第一个正式成员。它在进程启动时读取一次 `data`，建立只读文档、实体、资源池和世界索引，并向其他微服务提供正式定义数据。

```text
game/app.py
  -> CoreServices.data
  -> JsonDataService.initialize()
  -> JsonDataReader 固定读取 基础/读取规则.json
  -> JsonDataReader 按规则唯一匹配并归档全部正式 JSON
  -> GameDataLoader 建立实体、直接编号池和源文件池索引
  -> 校验通用文档形态、编号前缀、池引用和循环引用
  -> 其他核心微服务和玩法微服务通过构造参数取得依赖
```

Python 只固定知道引导文件的位置和标准 JSON 语法。`data/基础/读取规则.json` 登记组件目录、全局编号和池引用字段；每包 `组件.json` 声明文件路径模式、数据集、结构、实体类别、编号类别、目录主体和目录归属。基础组件的规则唯一匹配读取入口。组件清单自身由加载器严格解析，不进入实体或池索引。

数据服务会递归冻结 JSON。初始化完成后的查询不再加读锁，也不复制完整正文；领域服务只在进入自己的运行态时通过 `materialize()` 取得可变副本。实体元数据通过 `entity_record()` 提供编号类别、源文件和读取规则声明的目录归属，普通实体无需重复保存目录已经表达的类别。

数据契约统一把稳定实体编号命名为 `entity_id`：`JsonEntity.entity_id` 表示实体索引键，`PoolEntry.entity_id` 表示候选编号，`PoolResult.entity_ids` 表示抽取结果编号序列。领域服务取得实体后应继续收窄为所属编号，如物品使用 `item_id`、战斗构筑使用 `content_id`，不得改回无所属的 `identity`。

`cmd` 是触发层，不得直接访问数据服务。玩法微服务通过构造参数取得 `JsonDataService`，且只能从 `game.core.data` 包顶层导入公共契约；`files.py` 与 `loading.py` 属于内部实现。其他服务不得保存或拼接 JSON 路径，应请求规则已经命名的数据集。

字段契约（`schema.py`）校验的是「整份文档合不合已声明的形状」，`fields.py` 管更小的一层：取单个字段时确认形状。`positive_int` / `nonnegative_int` / `mapping` / `nonempty_text` 四者都在包顶层导出，域错误用 `error=` 传自己的异常类型（命令层捕获的就还是各服务的错误）。这四个判定原先在服务里各抄一份、共 116 处，现由 `tools/架构审查/检查边界.py` 的 `check_field_validators_are_shared` 把关。

```python
from game.core.data import JsonDataService, positive_int

def read_count(raw: Mapping[str, object]) -> int:
    return positive_int(raw.get("数量"), "数量", error=SomeDomainError)
```

```python
from game.core.data import JsonDataService

def load_domain_data(data: JsonDataService):
    definitions = data.dataset("战斗定义")
    rules = data.dataset("战斗规则")
    technique = data.entity("功法", "400001")
    all_qi_patterns = data.entities("气机")
    full_qi_patterns = data.all_members("气机")
    entity_ids = data.pool_members(["入微敌方修士气机池"], "气机")
    weights = data.pool_fields(
        ["入微敌方修士气机池"],
        "气机",
        ["权重"],
    )
    return definitions, rules, technique, all_qi_patterns, full_qi_patterns, entity_ids, weights
```

编号池保存实体编号；源池保存其他内容文件名。内部契约将编号池形态称为 `ENTITY_ID_POOL`，避免使用无所属的 identity 命名。数据服务递归展开两者并校验类别，资源池微服务只请求候选编号和 `权重`，不会复制整份功法、真意或气机定义。玩家全池直接来自去重实体索引，不需要额外的全池 JSON；实体大类中的虚拟子池通过 `number_category_members()` 按编号类别取得，例如炼药所需的全部兽宝。

运行期间不扫描、不监听、也不重新加载 JSON。修改正式数据或读取规则后必须重启服务。完整校核、评分和平衡仍属于 `tools`。其他微服务负责解释所属数据集的玩法含义和业务引用，数据服务不替它们做战斗、世界或角色判断。

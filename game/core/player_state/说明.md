# 玩家状态核心微服务

本服务解释 `data/角色/规则/状态` 中的行为、队伍、控制、初始组合与状态守卫。数据库只保存一份 `player_state/main` 快照；快照保存状态编号和业务上下文，状态名称始终从当前 JSON 解析。探险和闭关的活动提示由行为状态中的结构化字段提供，守卫根据发起者与参与人数区分个人、领队和随行成员，不额外保存“跟随中”状态。

三个状态槽可以同时存在。例如玩家可以处于“探险中 + 组队中 + 托管中”。守卫对不同类型执行“并且”，同一类型的多个允许状态执行“或者”，没有声明的类型不参与判断。

创建人物时，角色服务把 `PlayerStateService.initial_mutation()` 并入同一事务。具体玩法通过本服务变更状态并提交数据库版本；命令守卫只读检查，不能代替玩法事务中的版本校验。

## 同笔事务的守卫保护

`plan_guard(user_id, rule_name)` 用同一次快照检查守卫，返回人物及状态的原值版本保护计划，供既有人物业务合并提交。禁止先校验再无版本保护地提交装配；不适用于创建新人物事务。计划包含 character/main 与 player_state/main，不可与同地址的其他写入计划重复提交。

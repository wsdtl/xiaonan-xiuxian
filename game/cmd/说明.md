# 命令层

`game/cmd` 只负责把玩家输入转换为玩法调用和协议中立回复。具体命令按职责放入 `通用`、`专属` 或 `后台`，二级组件继续使用中文目录；跨组件共享的命令基础设施使用英文文件名，业务代码不得导入其他中文组件目录。

## 二级组件

二级组件按职责而不是按函数数量拆分：

```text
组件/
  __init__.py   命令注册、文本输入解析、玩法调用、回复发送和 router 汇总
  reply.py      复杂消息与按钮构造，按需存在
  input.py      可独立测试的复杂命令语法，按需存在
  site.py       Web 入口，按需存在
```

`__init__.py` 是唯一允许声明 `GameCommand` 的组件文件。简单的去空白、拆词和页码转换属于命令协议，可以留在回调入口；人物状态解释、资格判断、资产统计、数值计算和事务编排属于业务，必须由 `features` 返回明确结果。`reply.py` 和 `input.py` 不得取得游戏服务，也不得反向调用命令回调。

不为统一外观创建空文件，也不在命令组件中建立游戏业务 `service.py` 或 `business.py`。组件没有复杂回复时可以只有 `__init__.py`。

### 维护者入口的例外边界

`后台/` 是维护者入口，不是玩家玩法，因此是唯一允许保留自身认证、短期存储、站点和 HTML 投影模块的命令组件。这条例外有硬边界：

- 不得导入任何 `game.core.*` 或 `game.features.*`，即不得读取游戏规则、玩家资产或战斗事实；
- 不得读写游戏数据库 `DATABASE_PATH`；消息观察只使用独立的 `RUNTIME_LOG_DATABASE_PATH`，两张库不得互相引用；
- 不得发放奖励、修改玩家状态或写回正式 JSON；
- 网页命令执行仍走公共消息驱动，不绕过状态守卫另开写入路径。

后台模块数量与体量受 `tools/架构审查/检查边界.py` 约束：例外只覆盖上述职责，不得借"后台"之名把游戏业务搬进命令层。

## 命令范围

- `通用/`：不依赖地点专属能力、特定 NPC 或玩法实例，玩家在任意合法地点都可触发。
- `专属/`：依赖具体玩法、地点能力或交互对象；能否执行由对应 `features` 业务服务判断。
- `后台/`：仅供开发者使用的隐藏入口，不进入玩家帮助分类。

每条命令必须在 `metadata` 中声明 `scope` 为 `通用`、`专属` 或 `后台`。scope 只管理代码归属，不承担地点守卫或业务校验。目录与 scope 是否一致由 `tools/架构审查/校验命令目录.py` 手动审查，不进入游戏启动；后台命令必须同时满足 `metadata["hidden"] = True` 且不提供 `metadata["help"]`，否则注册失败。不同组件注册同名命令时由 `game/startup` 阻止游戏启动。

## 公共基础设施

- `command.py`：统一封装 `fullmatch`、`command`、`regex` 三种注册器；底层只接收 `cmd`、`priority`、`block`、`metadata`，所有游戏自定义说明都由 metadata 传递。
- `access_guard.py`：从公共消息上下文取得稳定用户编号，调用 `core/player_state` 完成人物状态组合守卫。
- `help_registry.py`：保存命令注册时声明的公开帮助，不读取数据库或游戏 JSON。

公开命令必须在 `metadata["help"]` 提供帮助字典；后台命令不得进入帮助注册表。每条游戏命令都必须在 `metadata["guard_rule"]` 显式声明 JSON 中存在的守卫规则；不受人物是否创建和状态影响的入口使用 `始终可用`。托管命令按需在 `metadata["hosting"]` 提供活动和阶段。

命令层不得直接读写 SQLite，不得解释人物状态 JSON，也不得把 QQ 私有事件对象传入核心或玩法微服务。

动作命令使用明确动词。即时行路只注册 `command("去")`，因此只接受 `去 地点名` 或 `去 x y`；`去天衡城` 不会命中。命令层不计算路线、海拔或境界叙事，只展示 `features/xinglu` 返回的结构化结果。

位置组件严格注册 `位置` 和 `附近`。`位置`只展示当前落脚事实；裸命令`附近`展示周边概览，`附近 地点`与`附近 修士 [页码]`进入详细页面。范围、公开状态、分页、本地修士合并、玩家可见文案和按钮动作都由 `features/weizhi` 根据正式 JSON 交付，命令层不接触位置表或道侣池。

## 按钮归属

玩家回复只允许三类按钮：

- `位置`与`去`成功抵达展示当前地点完整操作面板；
- `专属/`组件在自身业务按钮之后复现当前地点操作面板；
- 其他组件只展示本业务内部存在直接下一步关系的强联动按钮。

三类之外的回复不得附加按钮。命令回调只组合玩法已经返回的动作，不解释地点功能或自行创造按钮；`reply.py`只负责转换并排列动作。错误回复不附加地点面板。地点按钮触发后仍须重新经过状态守卫、当前位置与对应业务校验。

按钮一致性、死命令和覆盖范围属于开发维护，不进入 `game` 启动流程；相关检查只能放在 `tools` 手动执行。

命令需要玩家身份时只接收 `user_id`；需要回复时调用 `manager.send(message)`，由当前 `reply_target` 决定实际发送目标。命令层不得重新命名用户编号，也不得把 `group_id` 或 `target_id` 当作游戏用户编号。

服务重载使用 Uvicorn `reload`：旧进程退出后由新进程重新导入 `__init__.py`，命令、帮助、QQ 和 Local 注册表从零建立。框架不提供同进程卸载或运行中热解释代码。

# 兑换码玩法微服务

## 功能

### 一、本包范围

1. **薄薄一层**：规范码、查码、校验发放、调人物与资产两个核心的计划、落**一笔**事务。
2. **一个入口**：`redeem`（玩家报码换取发放）。

### 二、口径

3. **幂等排在最前**：先按玩家与请求编号查已提交事务，命中就回放，业务类型不符按冲突拒绝。
4. **每人限次落在人物状态里**：靠 `已兑换码` 这张清单，**不看请求编号**——请求编号管的是同一条请求重放，
   换一条请求就能再兑一次，那是两回事。
5. **查不到与已兑换回同一句**（「码无效或已使用」），不给出「这个码存在但用过了」这种可探测的差别。
6. **发放边界**：只发纳戒物品与灵石；道藏、修行资粮、器藏、阵藏、所学、先天灵宝都不发。
   特殊丹可以发——它被约束的是「使用」（要人在归元观/太素坊），不是「拥有」。
7. **同址合并**：灵石与已兑换码都在 `character/main`，由人物核心出**一份**变更；纳戒是另一个地址，
   其操作拼在同一条事务里。分两次计划会各带同一个 base version，放一条事务会撞版本。
8. **数量与条数有上限**：单条 1 到 1000000，一次发放不超过 20 条；品级不给就取最低一档。
9. **随机物品走资源池核心**：`候选文件` 指一个内容文件（或一串），用 `pool.draw_pools` 抽取，
   种子由「码编号＋玩家编号」派生（同一玩家稳定、不同玩家各抽各的），去重抽取，抽到的编号写进回执载荷。
10. **启动期把发放查实**：每条码的物品编号必须在册、随机池非空且装得下抽取数量——数据写错当场拒绝启动，
   不等到玩家报码才炸。
11. **回执写物品名**（2026-10 加）：`发放` 由物品名拼成（如「小还丹×10」），不再只写「物品×N」——
   十个码之后，只写类型玩家根本不知道拿到了什么。物品名走物品目录（`item_catalog`），丹药与材料都在它的编号实体索引里。

### 三、文案与安全

9. **文案来自展示数据集**（`data/玩法/兑换码/展示/文本.json`）。
10. **码不许被查询到**：物品目录的字段表里没有兑换码表项，这条由 `检查兑换码.py` 守着。

## 数据集

| 数据集 | 本包路径 |
| --- | --- |
| 兑换码发放类型 | `data/玩法/兑换码/定义/发放类型.json` |
| 兑换码 | `data/玩法/兑换码/内容/兑换码.json` |
| 兑换码展示 | `data/玩法/兑换码/展示/文本.json` |
| 兑换码按钮 | `data/玩法/兑换码/展示/按钮.json` |

命令组只做一件事：把整段文本去掉首尾空白后交给本特性，大小写由特性统一处理；走「自主空闲或休息」守卫。
失败不泄露——码不在册与已兑换回同一句。

# 装配台玩法

公开 Web 辅助工具：全池是 JSON 中完整的功法、真意、气机、器律目录。
全池与已开启公开的用户是同一个列表中的平级选项，不是用户清单的并集。
切换清单只缩小候选范围；不绑定方案的目标用户，也不授予任何资产权限。

## 公共契约

- `page(scope="all")`：候选条目、公开用户列表、当前范围的槽位上限与装配。
  用户清单同时包含库存和已装入的内容，关闭后新请求拒绝读取。
- `scheme(build)` / `open_code(code)`：纯方案校验、编解码与可读明细，不读写玩家资产。
- `current(user_id)`：按人物有效构筑导出整套装配。
- `toggle_public(user_id, request_id)`：单一开关，默认不公开；保存关闭记录以保留版本线。
- `import_code(user_id, request_id, code)`：根据执行者实际道藏、资粮、器藏、
  武器孔位、器阶、状态守卫、最终构筑相冲与先天灵宝规则生成计划，并在一笔事务里提交。

## 导入边界

人物核心拥有槽位与规则；资产核心拥有库存；数据库拥有原子提交和请求回执。
本玩法只编排公共接口，不调用核心私有方法。字符编号与品级来自 JSON，不由网页解释。

功法检查个人道藏；真意、气机与器律的每个变化槽按现有规则扣库存。
相同内容留在相同槽位不再次扣减。空槽表示清除，不代表“保持原值”。
卸下不返还已消耗资粮；返真七妙树仅在新资粮替换旧资粮时回补旧内容。
把已消耗的资粮或器律移到另一槽，需要该新槽所需的一份库存。
器律可重复，但按孔位汇总消耗，不能凭一份库存覆炼多孔。
借阅功法原槽不变时保留借阅元数据，不把借阅转换为永久所有权。
相冲按整套最终状态检查，允许不会出现在最终方案里的临时相冲被整体替换掉。

先生成全部计划再提交；库存不足、相冲、孔位不符或并发版本变化时不提交任何部分。
同一请求编号和装配码重放回执，不重复扣料；同请求不同操作或不同码拒绝。
码与用户、公开开关、清单来源均无关，其他人可以使用，但要通过自己的实际资产校验。

## 装配码协议

`ZP1.` + 无填充 Base64URL：版本字节、按功法/真意/气机/器律排列的四段槽位、
CRC16 复制差错校验。内容编号为变长整数，零表示空槽，修行项另带品级字节。
尾部空槽规范化省略，中间空槽和顺序保留。仅六位正数内容编号与两位非零品级可编码。
不含签名、用户、时间、范围、目录指纹；相同装配的码稳定，新增内容不让旧码作废。
解码后仍按当前正式内容定义校验；已删除的内容会报错，不静默替换。

文案由 `培养展示/装配台` 读取；HTTP 与聊天适配在 `game/cmd/通用/装配台`。
`tests/test_zhuangpei.py` 核协议，`tests/test_zhuangpei.py` 使用临时 SQLite 验证
公开范围、原子导入、库存、幂等、并发、规则、HTTP 与聊天消息。

`detail(section, content_id)` 使用战斗核心公共 `render_body` 与规则层按需生成真实能力正文，不另造描述逻辑。守卫的 `plan_guard` 与灵宝的 `plan_effect` 共同保护检查到提交的窗口，不能在并发切换后套用旧资格或旧效果。

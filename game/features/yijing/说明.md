# 意境特性包

## 功能

### 一、本包范围

1. **只做薄薄一层**：取视图、调人物核心的意境计划、落一笔事务；判断与校验都在人物核心里。
2. **三个入口**：`inspect`（看六条路各自的阶与共享的道行）、`point`（给**某一条路**点一阶）、
   `refund`（到坐忘台服忘境丹退点：六路清零、道行退回已发总额）。
3. **道行来自境界突破到头**，发放在人物核心里，本包只负责花；六条路**共享**同一份道行
   （总额一百一十二，刚好点满一条），所以取舍在怎么分配，不在「只能选一条」。

### 二、口径

4. **取值只走核心的公开口**：阶价 `yijing_cost`、阶上限 `yijing_cap`、道行 `yijing_points`——
   `character/main` 那一格的解释权在核心，玩法层不自己解。
5. **六条路各自记阶、并存**：点第二路不动第一路；每条路各自受境界给的阶上限约束。
6. **投进去的道行不退，想重排就走坐忘**：在坐忘台服一枚忘境丹（特殊丹 160007）——
   六条路练过的阶全部抹去、道行退回到**已发总额**（按当前境界的阶上限算阶价累计），扣丹与退点写在同一笔事务里；
   丹药编号与状态守卫从 `坐忘` 的地点功能配置读，代码里不硬编码。
7. **落库一笔事务**：业务类型「意境点阶」，载荷只记意境编号。
8. **幂等排在最前**：先按玩家与请求编号查已提交事务，命中就**不再算计划**、直接回看现状——
   状态已经改过，再算会得到另一份计划（甚至撞上境界上限直接报错）；编号用于别的业务时按冲突拒绝。
9. **未点过的路不在人物档案里**：`profile.yijing` 只含点过的路（按编号排序），一条都没点过就是空元组；
   六条路的完整清单由本包按数据现取（`_routes`），面板与装配台据此决定整块显不显示。

**页面（`/yijing`）**：独立一页，不挤在装配台里——`page(玩家)` 就是它的数据口：六路全表（每路的阶、下一阶的价、还差多少）
＋阶价阶梯 `costs` ＋道行余额 ＋当前境界的阶上限；六路那一份直接复用 `inspect`（单源，页面与命令看到同一套数）。
页面只挑不发：它渲染出 `意境 点 <路名或编号>` 与 `坐忘` 的命令原文，由玩家发到群里执行；读谁的数据由网页资源开关说了算。

命令组只做两件事：看（六条路各自的阶、共享的道行、距下一阶还差多少）、
点（`意境 点 <路名或编号>` 给那一条路点一阶）。

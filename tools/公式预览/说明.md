# 公式预览（已归档）

这是 QQ 消息协议**兼容性验证组件**，曾位于仓库根目录，现已归档到 `tools/` 下留档。

它已经完成自己的价值：逐项验证过 QQ 客户端对 Markdown 外框、公式内文、正文无边框命令和
keyboard 按钮的兼容性。结论已经落到正式实现里，所以**不再默认装载**。

保留原因只有一个：那些兼容性样本本身是可回溯的记录——以后 QQ 客户端升级、公式语法调整或
消息协议改写时，可以照着这批样本重新对一遍，不必从头设计用例。

## 为什么归档，而不是留在根目录

它靠框架的 `ROUTER_FOLDERS` 被当作**普通包导入**才生效：`launch/load_router.py` 只导入
配置声明的包，`__init__.py` 在导入时注册命令。默认 `.env` 只登记 `game.cmd`，所以它本来就
不在运行链路里。

它不读游戏 JSON、不写数据库、不实现玩法，也不属于正式消息协议——按 `系统架构.md`
"目录规范、发布校核、评分、平衡模拟和内容生成只属于 `tools`" 的口径，验证与留档件归 `tools`。

## 原使用方式

装载时它注册一条 QQ 命令（`@QqEventHandler.command("公式预览")`）：

```text
公式预览
公式预览 1
公式预览 2
```

测试项分为公式原子能力、真实游戏消息组合、正文与按钮三组。公式原子能力必须逐项确认，
避免一个复杂样板失败时无法判断具体不兼容的语法。

## 要重新启用它

1. 把 `tools.公式预览` 加进 `.env` 的 `ROUTER_FOLDERS`：

   ```ini
   ROUTER_FOLDERS=["game.cmd","tools.公式预览"]
   ```

2. 重启服务。启动日志里会出现 `已导入业务模块 module=tools.公式预览`。

`launch/load_router.py` 把配置里的点号模块名直接当作项目内路径（`tools.公式预览` →
`tools/公式预览/`）并检查 `__init__.py`，所以这个包在 `tools/` 下**仍可被正常导入**，
归档不改变它的可装载性。

## 现状

- 默认不装载：`.env` 的 `ROUTER_FOLDERS` 只有 `game.cmd`。
- `game` 与 `launch` 都不引用它；`game` 不得导入 `tools`。
- 本目录不是 pytest 测试集，没有自动判据——它是靠人手动发命令、看客户端渲染的验证件。

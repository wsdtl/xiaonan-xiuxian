# 工具目录

本目录放**检查、测量与一次性迁移**脚本，不放游戏数据。数据在 `data/`，规则语义在
`data/战斗/规则/说明.md` 与各领域 `说明.md`，文本标准在 `data/战斗/内容/文本规范.md`。

统一跑法：`.venv/Scripts/python.exe -X utf8 tools/<脚本>.py`

## 四类脚本，用途不同，别混用

| 类别 | 在哪 | 回答什么 | 量级 |
| --- | --- | --- | --- |
| 结构审查 | `架构审查/` | 数据形状合不合契约 | 秒级 |
| 语料验收 | `语料对照.py`、`战前状态对照.py`、`渲染正文对照.py`、`查看结果对照.py`、`战报对照.py` | 改了之后**行为、卡面正文、查看页与战报**变没变 | 秒到分钟级 |
| 平衡测量 | `战斗统计.py`、`平衡扫描.py` | 这套数值**打起来**是什么样 | 分钟级 |
| 顺序盘点 | `盘点监听顺序.py`（静态）、`实测共现.py`（实测） | 哪些监听的**先后**会改变结果 | 秒 / 分钟 |
| 结构测量 | `重复与耦合.py` | 哪些代码是抄出来的、哪些包依赖最多 | 秒级 |

## 结构审查

`架构审查/` 下六支，覆盖启动契约、命令目录、数据驱动、构筑形状、词条作用域、边界。
**非零退出即失败**，改动数据后先跑这一组。

`架构审查/说明.md` 里有一张**规则与检查的落差表**：规范里每一条可机械判的禁令对应
哪个检查、口径是什么，都记在那里；规范写了却还没检查的条款也列在那里。
**当前 G1–G10 已全部补完，落差清零**——「审查全绿」现在等于「规范里可机械判的部分
都成立」。加功能前先看那张表。

## 语料验收：五条通道 + 入库基准

战前状态（战丹、长期伤势）走 `CombatantSpec.prepared_statuses`，与构筑完全不是一条路，
**只跑一条会留盲区**——`清惰性节点.py` 就在这里留下过 64 条整段监听被摘空而无人察觉。

渲染正文是第三条，管的是另一件事：前两条读**战斗结果**，正文多一行、少一行它们看不出来。
渲染器此前完全没有入库判据，所以「删掉一个渲染分支」可以是零报警的。`渲染正文对照.py`
把渲染器对 2314 个实体的输出做成摘要（只收现算正文与未支持项，不收人写的 `说明`），
差异按行报出。

查看页是第四条：前三条都读不到命令层为查看页拼的结构化行（`items.py` 的
`_definition_lines` 与 `_build_description_lines`）。`查看结果对照.py` 对全部 3859 个正式
编号实体各构造一次真实回复，收下冻结后的消息——**对照的是玩家实际看到的东西**，不是
中间结构。

战报是第五条，起因正好相反：`语料对照.py` **刻意**把战报排除在摘要之外（它的摘要把状态名
抹成 `*`，好让词条改名不算行为变化，而战报是长篇措辞，收进去会让那条通道对改名过敏）。
排除是对的，代价是 `report.py` 与 `presentation.py` 的战报构造完全没有判据。`战报对照.py`
用同一套语料、同一批种子，收的却是战报本身；`generated_at` 固定传入（它默认取
`datetime.now()`），每场只存 16 位哈希——战报单场 16 到 31 万字符，全文入库不合适。

```powershell
.venv/Scripts/python.exe -X utf8 tools/语料对照.py --对照 tools/基准/语料摘要   # 1264 场
.venv/Scripts/python.exe -X utf8 tools/战前状态对照.py                          # 170 场
.venv/Scripts/python.exe -X utf8 tools/渲染正文对照.py                          # 2314 个实体
.venv/Scripts/python.exe -X utf8 tools/查看结果对照.py                          # 3859 个实体
.venv/Scripts/python.exe -X utf8 tools/战报对照.py                              # 1264 场
```

基准在 `基准/`，**入库跟踪**，所以换一个会话也能直接对照。重新取基准（改平衡之后）：

```powershell
.venv/Scripts/python.exe -X utf8 tools/语料对照.py tools/基准/语料摘要
.venv/Scripts/python.exe -X utf8 tools/战前状态对照.py --写基准
.venv/Scripts/python.exe -X utf8 tools/渲染正文对照.py --写基准
.venv/Scripts/python.exe -X utf8 tools/查看结果对照.py --写基准
.venv/Scripts/python.exe -X utf8 tools/战报对照.py --写基准
```

**退出码约定：0 = 一致，1 = 有差异，2 = 有抛错或基准缺失。** 只有零抛错时才写基准——
把带错误的运行固化成基准，等于把坏状态当成正确。另：这些工具**不明确要求就绝不写盘**，
无参数运行一律是「与入库基准对照」。

判据看改动性质：纯结构等价（改名、搬位置）应当 **100% 一致**；补内容或改平衡则是
「差异 ⊆ 本次授权的卡」。正文、查看页与战报对照同理：动内部结构（删分支、抽方法、把一张
大分派拆成每领域一个函数）应当 **100% 一致**，改措辞或改字段则差异必须恰好是你要改的那批
实体。语料是报警器，不是设计评审——它能说「变了」，不能说「变得对」。

## 平衡测量

- `战斗统计.py`：现在是什么样。`--满构筑` 按人物槽位（功法6/真意6/气机6/器律4）拼满构筑，
  `--空白` 只靠普通攻击量数值底座，`--等级 L` 按等级现算属性。
  注意 `未决` 读的是引擎 `战斗结束` 的结论，不是「双方血气都大于 0」——有的卡会让一方
  `active=False`（遁走、入定、放逐），那时引擎已判出胜负而血气还满着。
- `平衡扫描.py`：改哪个数会变成什么样。在 `输出倍率` × `恢复倍率` 上扫格子。
  **它在 `data/` 的临时副本上跑**，源目录不改动——早先版本直接改真实文件、跑完在
  `finally` 里还原，被强杀一次就把线上数值留在了扫描途中某一格。

## 顺序盘点：静态与实测必须分清

- `盘点监听顺序.py` 是**静态 triage**，列出「可能冲突」。它有三层已知虚报（键粒度、
  可交换的写入、能否共存），实测下来 **861 张待办里真的只有 1 对**。
- `实测共现.py` 才是**实测**：跑真实战斗、按事件派发实例分组，只列真的同场同事件触发过的卡对。

**不要按静态表批量改数据。** 先后是作者意图，静态表判不出来。

## 一次性迁移

`一次性迁移/` 是**已跑完**的脚本，留档用，不要重跑。目录内的 `说明.md` 记了每支做过什么。
`tools/` 根下另有两支历史脚本名称是英文（`audit_combat_descriptions.py`、`audit_data.py`），
它们同样属于数据审查，非零退出即失败。

## 不与脚本同类的文件

- `基准/`：五条摘要（`语料摘要.sem` 1264 场、`战前状态摘要.json` 170 场、
  `渲染正文摘要.json` 2314 个实体、`查看结果摘要.json` 3859 个实体、`战报摘要.sem`
  1264 场），入库跟踪。
- `未接入效果.json`：从功法与真意的被动槽位**移出**的死效果（正文是「记录战斗事实 →
  保存结果 → 计量+13」，而那个事实全卡无人读取）。移出前后运行时行为一致；要接回时
  先补正确的监听事件，再把节点放回对应被动技能的 `效果[]`。文件内有同样的说明。

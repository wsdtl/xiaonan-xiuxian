# 工具目录

本目录放**检查、测量与一次性脚本**，不放游戏数据。数据在 `data/`，规则语义在
`data/战斗/规则/说明.md` 与各领域 `说明.md`，文本标准在 `data/战斗/内容/文本规范.md`。

统一跑法：`.venv/Scripts/python.exe -X utf8 tools/<脚本>.py`

## 跑全套：`全量核对.py`

**别靠记性挑着跑**——`验证启动顺序.py` 就因此在
十几轮改动里一次都没被跑过（它一直是通的，只是没人知道该跑它）。

```powershell
.venv/Scripts/python.exe -X utf8 tools/全量核对.py        # 必过 18 项，并发跑
.venv/Scripts/python.exe -X utf8 tools/验收/发布验收.py    # 慢通道，发布前手动
```

必过项每一支在**独立进程**里并发跑、各自计时，末尾给一行总账；任一失败则整体非零退出。
慢通道（语料 / 各种对照 / 基准回归）合计十几分钟，属发布验收，不进必过项。

`验证启动顺序.py` 验的是**框架不变量**：驱动器必须在业务服务就绪之后启动——webhook 路由
在 lifespan 之前就挂好了、WebSocket 建连后立即收消息，所以顺序反了的话，启动窗口内到达的
每一条玩家消息都会撞上「微服务尚未初始化」。它用一个不访问网络的探针驱动器卡住这件事。

## 语料验收：十条通道 + 入库基准

十条通道各读一层，别只跑一条——**盲区是靠通道数量收掉的**。

- **语料（1967 场）**：`语料对照.py` 的摘要把状态名抹成 `*`，所以词条改名不算行为变化；
  `--摘要 行为` 是它的第二个口径，只留事件骨架与胜负，措辞怎么改都不动它。
- **战前状态（298 条）**：战丹与长期伤势走 `CombatantSpec.prepared_statuses`，与构筑完全
  不是一条路。历史上这条路上留下过 64 条整段监听被摘空而无人察觉。
- **战场环境（55 条）· 阵法（188 条）**：这两层各有独立的准备与生效路径，前面几条读不到。
- **卡面正文（2442 个实体）**：前面几条读**战斗结果**，正文多一行、少一行它们看不出来。
  `渲染正文对照.py` 把渲染器的输出做成摘要（只收现算正文与未支持项，不收人写的 `说明`），
  差异按行报出。
- **查看页（3628 个实体）**：命令层为查看页拼的结构化行（`items.py` 的
  `_definition_lines` 与 `_build_description_lines`）前面几条都读不到。`查看结果对照.py`
  对每个正式编号实体各构造一次真实回复——**对照的是玩家实际看到的东西**，不是中间结构。
- **战报（1967 场）**：起因正好和语料相反——`语料对照.py` **刻意**把战报排除在外（战报是
  长篇措辞，收进去会让那条通道对改名过敏）。`战报对照.py` 用同一套语料、同一批种子，收的
  却是战报本身；`generated_at` 固定传入，每场只存 16 位哈希。
- **装配规划（28545 条）**：唯一一条**状态驱动**的通道——在临时库里建人物、授予道藏，再跑
  `plan_equip`。
- **交叉对局（5901 条）**：同一批构筑两两对上，专门盯构筑之间的先后与克制。
- **协议适配（59 例）**：唯一一条**样本不是真实语料**的通道。仓库里没有真实 QQ 报文，样本
  按协议形状与代码里的兼容分支造；它冻住「每个分支现在什么行为」——最容易被悄悄砍掉的就是
  那些看着没用的兼容分支，砍掉不报错，只是某类消息从此不响应。

```powershell
.venv/Scripts/python.exe -X utf8 tools/交叉对局对照.py --写基准
.venv/Scripts/python.exe -X utf8 tools/协议适配对照.py --写基准
```

**退出码约定：0 = 一致，1 = 有差异，2 = 有抛错或基准缺失。** 只有零抛错时才写基准——
把带错误的运行固化成基准，等于把坏状态当成正确。另：这些工具**不明确要求就绝不写盘**，
无参数运行一律是「与入库基准对照」。

判据看改动性质：纯结构等价（改名、搬位置）应当 **100% 一致**；补内容或改平衡则是
「差异 ⊆ 本次授权的卡」。正文、查看页、战报与协议适配对照同理：动内部结构（删分支、抽方法、把一张
大分派拆成每领域一个函数）应当 **100% 一致**，改措辞或改字段则差异必须恰好是你要改的那批
实体。语料是报警器，不是设计评审——它能说「变了」，不能说「变得对」。

## 平衡测量

- `战斗统计.py`：现在是什么样。`--满构筑` 按人物槽位（功法6/真意6/气机6/器律4）拼满构筑，
  `--空白` 只靠普通攻击量数值底座，`--等级 L` 按等级现算属性。
  注意 `未决` 读的是引擎 `战斗结束` 的结论，不是「双方血气都大于 0」——有的卡会让一方
  `active=False`（遁走、入定、放逐），那时引擎已判出胜负而血气还满着。
- `平衡扫描.py`：改哪个数会变成什么样。在 `输出倍率` × `恢复倍率` 上扫格子。
  **它在 `data/` 的临时副本上跑**，源目录不改动——早先版本直接改真实文件、跑完在
  `finally` 里还原，被强杀一次就把线上数值留在了扫描途中某一格。

## 顺序盘点：静态与实测必须分清

- `盘点监听顺序.py` 是**静态 triage**，列出「可能冲突」。它有三层已知虚报（键粒度、
  可交换的写入、能否共存），实测下来 **861 张待办里真的只有 1 对**。
- `实测共现.py` 才是**实测**：跑真实战斗、按事件派发实例分组，只列真的同场同事件触发过的卡对。

**不要按静态表批量改数据。** 先后是作者意图，静态表判不出来。

## 一次性改写脚本

**维护目录里不留一次性改写脚本。** 历史数据改写只存在于 git 历史里，不作为日常入口，
也不重跑——重跑多半会重复追加，或把后来重设计过的内容覆盖回旧写法。

`公式预览/` **名字骗人**：它不是试算公式的小工具，而是一支**已归档的 QQ 消息协议兼容性
验证组件**（只验证消息协议兼容性，不读游戏 JSON、不写数据库、不实现玩法）。它默认不装载，
需要复验时把 `tools.公式预览` 登记进 `.env` 的 `ROUTER_FOLDERS` 再重启，用法见
`公式预览/说明.md`；`README.md` 与 `message/消息协议说明.md` 里都记了这件事。**别按名字
猜它的用途，也别把它的命令当作游戏功能。**

## 不与脚本同类的文件

- `说明与实现对照.md`：**维护侧导航表**——负责人在说明里改一条中文逻辑时，看它对上哪些
  实现模块与哪支形状判据。它只是导航，不进 `data/`，也不参与任何判据；新增核心服务或玩法
  目录时要跟着补。
- `基准/`：十一条通道的摘要（`语料摘要.sem` 1967 场、`语料行为摘要.sem` 1967 场、
  `战报摘要.sem` 1967 场、`交叉对局摘要.sem` 5901 条、`战前状态摘要.json` 298 条、
  `战场环境摘要.json` 55 条、`阵法摘要.json` 188 条、`渲染正文摘要.json` 2442 个实体、
  `查看结果摘要.json` 3628 个实体、`装配规划摘要.json` 28545 条、`协议适配摘要.json`
  59 例），入库跟踪；另有 `机械化基线.json`（`机械化盘点.py` 的棘轮）。
- `装配规划对照.py` 是唯一一条**状态驱动**的通道：它在临时库里建人物、授予道藏，再跑
  `plan_equip`。因此它自带 `--抽样 N`（先小样本验证 harness，不写盘、不对照）。
- `数据/构筑分值表.json`：`构筑分值.py --校准` 的产物。**刻意放在 `tools/` 而不是 `data/`**
  ——它是工具侧的标定产物，放进 `data/` 会被加载器当成「没有匹配读取规则」的数据文件。
- `未接入效果.json`：从功法与真意的被动槽位**移出**的死效果（正文是「记录战斗事实 →
  保存结果 → 计量+13」，而那个事实全卡无人读取）。移出前后运行时行为一致；要接回时
  先补正确的监听事件，再把节点放回对应被动技能的 `效果[]`。文件内有同样的说明。
- `样板_400004.txt`：一张卡的写法样板，供对照，不参与任何流程。
- 根目录下的 `_输出/` 收了全部**运行产物**（`战斗文本预览.md`、`语料日志.txt`、`词条作用域.txt`、
  `_*.py` 临时探针 …），`.gitignore` 里 `/_输出/*` 已忽略、只留 `_输出/说明.md` 入库。每次跑对照
  都会重写，不要手工编辑。

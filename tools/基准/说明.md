# 基准与欠账

这份是**欠账台账**：器律 64 条逐条重做（2026-10）之后，仓库里还挂着什么、当初为什么挂、
以及处置意见。维护规矩两条——

1. 每条都要有**实测**（数字或命令），不许写「疑似」「可能」；
2. 每条都要有**复现命令**，让人能当场核对，而不是相信这份文档。

基线本身不在这里：器阶阶梯与档位强度写在 `data/物品/炼器/规则/器则.json`（口径见
`data/物品/炼器/说明.md` 的「器律强度口径」），机械化集中度基线在 `tools/基准/机械化基线.json`。
现状读数用 `tools/报告与生成/盘点器律.py` 一条命令重算，不另存静态基线。

## 一、器律能力倍率还没接战斗侧

**实测**：`器律能力倍率` 在 `game/` 里只出现 2 次，都在 `game/core/forging/service.py`（装载期校验：
随阶序严格递增），**没有任何服务读取它来缩放**——也就是说档位强度目前是「数据有、引擎校、无人用」，
玩家体验零变化。

**复现**：`rg 器律能力倍率 game/`

**影响**：`检查器律形状.py` 检查「每条至少一处可缩放字段」，所以接的时候有作用点；不接则四档同强。

**处置意见**：接的方式按口径来——倍率作用于**器律整门内容一层的威力倍率**，不改数据里的逐个数字、
不改卡面正文（与品级同一条禁令）。落点应在一个地方（器律参与战斗结算的入口），不要散到各效果里。
属于玩法改动，需要单独一轮并跑战斗语料对照。

## 二、敌人「ID 化候选」——实测是误报，撤销

**实测**：80 份敌人实体文件共 160 个名字；全库存档（`player_state.state_json`，3 个玩家）里出现
敌人名 **2 处**，上下文都是战报文案：

```json
{"回合": 0, "数值": 0.0, "文本": "小明与回声溪蝠、涧齿岩獾进入战斗", "来源": "小明"}
```

名字出现在**叙事文本**里，不是引用字段——那里本来就该是名字。

**复现**：`tools/报告与生成/盘点器律.py` 同目录的读库脚本思路见提交记录；等价做法是拿敌人名扫
`select state_json from player_state`，看命中的上下文。

**处置意见**：撤销该候选，不需要 ID 化。

## 三、器阶在存档里按名字存（保留）

**实测**：存档里出现器阶名 3 处，全是同一形状：

```json
"value": {"名称": "无名器胚", "器律": [], "器阶": "凡器", "等级": 1, "经验": 0}
```

**处置意见**：**保留**。器阶没有编号，它是 `器则.json` 里 5 个名字构成的枚举，名字就是它的身份，
而且装载期现在会校验整条阶梯。唯一的风险是将来**改档位名**需要一次存档迁移——留作已知成本。

## 四、编号登记表里 主体/类别 两组语义相反

**实测**（`data/基础/定义/编号.json` 的 `编号前缀`，共 22 条）：

| 组 | 前缀 | 主体 | 类别 |
| --- | --- | --- | --- |
| 1x（4 条） | 10/12/14/16 | 恢复丹 / 战丹 / 突破丹 / 特殊丹（具体） | 丹药（大类） |
| 其余（18 条） | 20…73 | 基础物品 / 修行 / 人物 / 炼器（大类） | 灵植 / 功法 / 种族 / 器律（具体） |

也就是**反的是 1x 那 4 条**（不是某一组反了），而 2026-10 新加的 `55 角色/种族` 跟着的是多数派。
**没有任何运行时代码语义读取这两列**：只有 `检查编号登记.py` 查它们非空、`检查炼丹形状.py` 拿
前缀↔主体做一次交叉核对。

**复现**：读 `data/基础/定义/编号.json`；`rg 编号前缀 game/ tools/` 看谁读它。

**处置意见**：低优先级（纯文档层面）。以多数派为准（主体=大类、类别=小类），1x 那 4 条择机归一；
在归一之前，不新增按 1x 写法的条目。

## 五、模板库里 57 个器律模板已成孤儿

**实测**：`data/` 下 1784 份 json；模板库定义 328 个模板，被引用 271 个；孤儿 **57 个，全部归属器律**；
悬空 0 个。其余归属自洽：战丹 178/178、战场环境 32/32、真意 26/26、功法 19/19、伤势 16/16。
原因：64 条器律由「模板引用」改为内联，生成物没跟着重生成。

**复现**：`tools/报告与生成/盘点模板库.py`

**处置意见**：消除孤儿只有一条路——重生成模板库，而它要求先 `--展开`（把 `data/` 里的引用展开成
原文并**原地落盘**，会重写功法/真意/战丹/战场环境/伤势约 4690 处引用），属于**数据形态变更**，
需要单独决策。备选：把它挂进 `tools/验收/发布验收.py`（慢通道）而不是每轮跑的门禁。

## 六、`优先级` 的两组读数对不上（待核对，本轮没改）

**实测**：`data/战斗/规则/说明.md` 写「`优先级` 当前声明了 **82 处：功法 57 · 真意 23 · 器律 2**」，
而我按「监听节点带 `优先级`」扫出来是：真意 **204** 处、器律 **0** 处（器律那两条要么已被重做消掉、
要么本来就不是监听节点上的声明）。两组数字差得远，说明**度量口径不同**——按这个仓库的规矩，
口径不同时不许擅自改文档，先把差异记下来。

**复现**：走模板展开后，数 `监听事件` 节点里带 `优先级` 的个数。

**处置意见**：先确认原文那 82 处按什么口径数的（可能是「按卡」或「按不同的优先级值」），
确认后再统一到一种口径；在那之前两处都不动。

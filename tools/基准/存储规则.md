# id 化规则（唯一入口）

来源：委托方 2026-10-13～10-15 口径、原 id化存储.md 与 记录存储.md、core/asset/ref.py 的实现。
本目录**只保留这一份**规则文件。

## 一、三个区间（先定「谁用中文、谁用编号」）

| 区 | 范围 | 写法 |
| --- | --- | --- |
| help 区 | 只有「帮助」命令输出的那段文本 | 编号优先；但源文写中文，输出时由转换函数翻成编号 |
| 存储区 | 落进存档／数据的指称（键、值里的指称） | 编号 |
| 展示区 | 其余玩家看得见的一切 | 中文优先 |

展示区具体含：卡面标签与字段、候选提示、报错文案、**usage 与 summary／side_effect 等元数据文本**、
按钮标签、按钮携带的联动参数（点得到的东西）、@ 交互输入的命令；测试夹具与基准语料同理。

三条最容易搞错的边界：

1. **usage 属展示区，不属 help 区**：它住在命令的 help 元数据里，但身份是给人看的文案；
2. **help 区的编号不是手写的**：由 帮助/reply.py 的 id_converter 在渲染时把「命令写法里的中文名与品级」
   翻成编号（命令词不翻）；
3. **不能 ID 化就中文**：没有编号的东西（无编号灵植、命令词、地点名、玩家名等）一律写中文。

## 二、语法（编号形态 ↔ 中文形态，同形同构，只换 token）

最终形式：[品级编号]物品编号[[灵宝编号]]{扩展位}  ←→  [品级名]物品名[[灵宝名]]

| 组合 | 编号形态举例 | 中文形态举例 |
| --- | --- | --- |
| 有品级、无灵宝 | 02410137 | 玄品枯海锁元 |
| 无品级、无灵宝 | 410137 | 七星草 |
| 有品级、有灵宝 | 02410001[410002] | 玄品八卦阵[乾坤鼎] |
| 无品级、有灵宝 | 410001[410002] | 八卦阵[乾坤鼎] |

形状四条（两侧通用）：① 品级永远在最前、定长 2 位；② 连写、不加分隔符、不加空格；
③ 不许用短名（要写 黄品，不能写 黄）；④ 没有品级就不写前缀（不补 00、不占位）。
灵宝写在物品之后、方括号里。

认前缀的判据：开头 2 位是数字、且剩下的正好 6 位编号，才算品级前缀；否则整串就是物品编号
（否则 410137 会被误读成「品级 41 ＋ 物品 0137」）。

扩展位（给特殊物品兜底，圣品阵法是第一个用户）：{名称=值,名称=值} —— 自描述、逗号分隔、
名称按字典序、可省；解析方必须原样保留不认识的字段。分界：**投入**进扩展位，**数量**进值。
扩展位只用于存储、不接受手打；展示侧用位置参数或候选点选代替
（例：炼阵 圣品周天星斗大阵 1944 5832 3888，后三个数是唯一的特殊照顾）。

## 三、机制（不要在错的地方写编号）

1. 源文写中文：卡面、文案、usage、示例 —— 人写的地方一律中文（品级写全名）；
2. 输出时转换：只有「帮助」命令的输出走 id_converter；
3. 存储时编号：落进存档／数据的指称一律编号；
4. 全库只有一个构造口、一个解析口：core/asset/ref.py 的 format_item_ref 与 parse_item_ref；
   别处不许自己拼字符串、拆字符串；同一条指称里不许混搭（物品用编号 ⇒ 品级与灵宝也必须编号，反之亦然）；
5. 禁止：中文名拼键、冒号拼键、任何第二套形状。

## 四、覆盖面

资产库：纳戒／库存、道藏、器藏、资粮、阵藏、宗门资产（万珍殿／灵藏）、道侣身上的物品、
探索产出、活动奖励暂存。
记录库（战报、探索战斗记录）：键是记录编号（一条记录一个键，键里不拼物品／玩家／时间）；
记录体内部的运行期写法不改，但物品指称写法仍按本规则。

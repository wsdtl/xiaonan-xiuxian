# id 化存储规则（唯一依据）

委托方 2026-10-13 口径，**本文件是存储规则的唯一依据**，改造与迁移都按它办。

## 一、最终形式

```
[品级编号]物品编号[[灵宝编号]]
```

- **有品级**就写在**最前面**（定长 2 位）；**没有品级**就**不写前缀**（不补 00、不占位）；
- **有灵宝加成**就在物品后面挂方括号写灵宝编号；**没有灵宝**就**不写**后面的方括号；
- 两段各自可选，**四种组合都合法**：

| 品级 | 灵宝 | 最终形式 | 例 |
| --- | --- | --- | --- |
| 有 | 无 | 品级编号 + 物品编号 | `02410137` |
| 无 | 无 | 物品编号 | `410137` |
| 有 | 有 | 品级编号 + 物品编号 + [灵宝编号] | `02410001[410002]` |
| 无 | 有 | 物品编号 + [灵宝编号] | `410001[410002]` |

**认前缀的判据**：开头 2 位是数字、且**剩下的正好是 6 位编号**，才算品级前缀；否则整串就是物品编号
（否则 `410137` 会被误读成「品级 41 + 物品 0137」）。已落在 `game/core/asset/ref.py` 并有往返验证。

## 二、规则

1. **存 id，不存名字**：凡落进存档的物品／品级／灵宝指称，一律存编号——以后改中文名，存档一个字都不用动；
2. **形状只有一种**：就是上面的最终形式（与卡面同形，只有 token 不同：卡面用中文名，存档用编号）；
3. **全库只有一个构造口、一个解析口**：别处不许自己拼字符串、不许自己拆字符串；
4. **覆盖面 = 凡存了这些东西的地方**：纳戒／库存、道藏、器藏、资粮、阵藏、宗门资产（万珍殿／灵藏）、
   道侣身上的物品、探索产出、活动奖励暂存……**不是只改 asset 一处**；
5. **禁止**：中文名拼键、冒号拼键、任何第二套形状；
6. **迁移**：老键→新键 ＋ 旧新映射（可整体回滚）＋ 先在**存档副本**演练 ＋ **每个解析点各核一遍**；
   认不出的键**拒绝执行并报原键**，不猜着改。

## 三、迁移前的旧形状（待改造对象）

| 旧 | 新 |
| --- | --- |
| 物品编号:品级编号 | 品级编号物品编号（无品级则只留物品编号） |
| 阵法编号:品级编号 | 品级编号阵法编号 |
| 阵法编号:品级编号:灵宝编号 | 品级编号阵法编号[灵宝编号] |

## 四、验收

1. 形状：所有落存档的指称都能由 `parse_item_ref` 往返解析成同一形式；
2. 读点：每个解析点迁移后各跑一次读取，拿得到东西（不只"键看起来变了"）；
3. 可逆：迁移→回滚→再迁移，最终状态与首次迁移后逐字节相同；
4. 三证：总闸全绿 ＋ 回执逐字节相同 ＋ 零信息通过。

## 五、数量怎么放（委托方 2026-10-13 追问后定）

**键只放指称，数量只放值；对外文本里数量永远是指称之后独立的一段；显示用 `× N`。**

| 场合 | 数量怎么表达 | 例 |
| --- | --- | --- |
| 存档键 | **不进键**（键＝纯指称，`数量` 在值里） | 键 `02410137` ＋ 值 `{"数量": 3}` |
| 命令参数 / 兑换码文本 | 指称之后的**独立一段数字** | `赠送 玩家 黄品小还丹 3`；兑换码 `物品:02410137:3` |
| 卡面显示 | `× N` 跟在指称后面（中文名优先） | `玄品枯海小还丹 × 3` |

**为什么数量不进键**：键是身份、数量是计数。数量进键会把同一件东西拆成多条（`…×3` 与 `…×2` 并存），
堆叠失效、每次买卖都要改键名；旧实现里阵藏键也从来不含数量，正是因为如此。

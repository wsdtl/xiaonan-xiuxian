# id 化存储规则（通用：资产库与非资产库）

委托方 2026-10-13／14 口径。**两个库共用这一套写法**，区别只在"写到哪、要不要背历史"：

- **资产库**（纳戒／道藏／资粮／阵藏）：**键＝指称**，一字不差按本规则；改键要迁移＋可回滚。
- **非资产库（记录）**：战报、探索战斗记录等**整条 zlib+base64 打包**存储（core/database/storage.py），
  键＝**记录编号**；记录里的**物品指称仍用本写法**，其余（用户／时间／来源）是**字段**；
  记录库周期性清理、不背历史兼容，内部形状以"整块读写最快"为准，所以不按资产那样拆键。

## 一、最终形式

```
[品级编号]物品编号[[灵宝编号]]{扩展位}
```

- **有品级**就写在**最前面**（定长 2 位）；**没有品级**就**不写前缀**（不补 00、不占位）；
- **有灵宝加成**就在物品后面挂方括号写灵宝编号；**没有灵宝**就**不写**后面的方括号；
- 两段各自可选，**四种组合都合法**：

| 品级 | 灵宝 | 最终形式 | 例 |
| --- | --- | --- | --- |
| 有 | 无 | 品级编号 + 物品编号 | `02410137` |
| 无 | 无 | 物品编号 | `410137` |
| 有 | 有 | 品级编号 + 物品编号 + [灵宝编号] | `02410001[410002]` |
| 无 | 有 | 物品编号 + [灵宝编号] | `410001[410002]` |

**认前缀的判据**：开头 2 位是数字、且**剩下的正好是 6 位编号**，才算品级前缀；否则整串就是物品编号
（否则 `410137` 会被误读成「品级 41 + 物品 0137」）。已落在 `game/core/asset/ref.py` 并有往返验证。

## 一之二、非资产库（记录）的补充

适用：战报（`log_battle_reports`）、探索战斗记录（`exploration_*`）这类**记录**。
背景：记录库**周期性清理**，不背历史兼容；设计目标只有一条——**增删改查最快**。

1. **键＝记录编号**：一条记录一个键（如 `exploration_battle/<会话>:<序号>`、战报 `<编号>`），查改删都是 O(1)；
   **不许把物品、玩家、时间拼进键** ✗ —— 那会让人误以为它是物品身份（`01100002|用户编号` 就是这么来的）；
2. **记录体扁平**：谁、何时、什么东西、几个，各是**平级字段**；物品明细用 `{物品指称: 数量}` 或条目数组，
   **不再套一层自己拼的字符串键**；
3. **不存可重算的东西**：能从别处算出来的不落盘（记录薄，写才快）；
4. **清理靠时间字段**：每条带写入时间，清理按它批量删，**不做全表扫描**；
5. **物品指称只借资产规则的"写法"**（唯一形式），**不借"键就是指称"那一套**；
6. **读写路径上不碰资产库**：记录只读写自己；要发放就走资产库自己的口。


## 二、规则

1. **存 id，不存名字**：凡落进存档的物品／品级／灵宝指称，一律存编号——以后改中文名，存档一个字都不用动；
2. **形状只有一种**：就是上面的最终形式（与卡面同形，只有 token 不同：卡面用中文名，存档用编号）；
3. **全库只有一个构造口、一个解析口**：别处不许自己拼字符串、不许自己拆字符串；
4. **覆盖面 = 凡存了这些东西的地方**：纳戒／库存、道藏、器藏、资粮、阵藏、宗门资产（万珍殿／灵藏）、
   道侣身上的物品、探索产出、活动奖励暂存……**不是只改 asset 一处**；
5. **禁止**：中文名拼键、冒号拼键、任何第二套形状；
6. **迁移**：老键→新键 ＋ 旧新映射（可整体回滚）＋ 先在**存档副本**演练 ＋ **每个解析点各核一遍**；
   认不出的键**拒绝执行并报原键**，不猜着改。
7. **适用面**（2026-10-14 补：就是这里漏过——候选提示里多了个空格）：凡把品级与物品/阵法写在**一起**的地方，
   一律用这一种形式——**卡面、候选提示、报错文案、请求／幂等表达式、数据模板**都算；
   **不许加空格、不许换顺序（品级永远在前）、不许用短名**（`黄` 要写 `黄品`）、不许加括号或其它修饰。
8. **扩展位**（2026-10-14 追认，给特殊物品兜底；圣品阵法是第一个用户）：
   `{名称=值,名称=值}` —— **自描述**键值对、逗号分隔、名称按**字典序**、可省；
   **解析方必须原样保留不认识的字段**（否则将来加字段就要再改一次规则）。
   **分界**：**投入**（这一件之所以是这一件的属性，如圣品阵法的兽宝/灵矿/灵植）**进扩展位**；
   **数量**（同样的几件堆在一起）**进值**——同样的投入就是同一件东西，第二件把数量加上去。

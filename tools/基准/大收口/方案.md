# 晓楠修仙 · 大收口与新基线（方案）

## 一、目标与不做什么

**目标**：把**边界**（能碰／不能碰）、**规则**（顶层＋项目＋判据口径）、**代码与说明**四类做一次归并清理，产出一条**可复跑的新基线**（总闸 ＋ 三证 ＋ 工具快照 ＋ 一页基线条目）。

**不做**：不改游戏行为（数值、文案语义、命令输出不动）；不新建组件或微服务；不碰 `database/` 与 `launch/`；不推送；不为过判据而改判据。

## 五、风险与回滚

- **最大风险：重录基线会把漂移洗白**。规则：**重录前必须逐条解释差异**（尤其回执那 2 条新命令），差异与理由写进台账；解释不清的不重录。
- 台账 408KB 分卷有丢史风险：**只归档不删除**，归档文件保留在 `tools/基准/` 并在正文留索引。
- 回滚：本任务**只增文档、重录工件**；代码类改动逐项单独提交、每项可 `git checkout` 退回。
- 收口期间若总闸红：**先修**，不带着红继续下一步。

## 六、花费

每步一条命令级验证；总闸一次约 2 分钟（本机，不联网）。预计 8～10 步。

不要在 JSON 根节点再包一层“功法”“气机”或“道侣”。完整实体文件使用字典列表；只保存编号或源池名的引用池使用字符串列表。个人池中的编号是实体引用，不是重复实体定义。

## 文件池与实体索引

编号实体池和命名实体池同时产生两种运行视图：

```text
文件名 -> 此文件包含的实体编号或名称        用于资源池
实体编号 -> 唯一实体定义                    用于具体引用和存档
```

同一实体可以出现在多个池中，但同一编号的完整实体定义必须一致。池内重复是否保留，由展开调用方显式选择；实体本身不保存“来自哪个池”。

引用池分成两种根节点形态，均直接使用字符串列表：

```text
道侣个人池 -> 六位实体编号列表
敌人/灵兽阶段池 -> 实体源文件名列表
```

数据服务会在启动时递归展开源文件池，并拒绝悬空编号、悬空文件、类别不匹配、混合引用和循环引用。无法识别的内容文件不能静默跳过。

玩家直接使用功法、真意和气机的去重实体索引作为虚拟全池。264名道侣分别通过功法池、真意池和气机池引用稳定编号；敌方修士与灵兽分别使用自己的六阶段定向池。不维护额外全池 JSON。

## 内容依赖

- 世界地点通过坐标派生地形材料池，通过同目录同名内容文件派生道侣池、敌人池、商店和地点主持实体。
- 晓楠修仙界引用地势和道路文件；道路引用地点名与地势水平坐标。
- 地点的 `地形` 按名称匹配唯一战场环境；秘境默认引用无相境。
- 敌人只保存额外物品池；所在地灵植、灵矿和灵兽独有兽宝均由世界关系派生。
- 道侣喜好引用灵植池。
- 炼药通过 `物品/炼丹/规则/丹则.json` 确定兽宝药引类别，通过编号类别虚拟全池取得全部兽宝，再由丹药自己记着炉法与炼制难度。
- 炼器通过 `物品/炼器/规则/归引.json` 取得兽宝兽脉，通过 `归脉.json` 取得灵矿本脉和旁脉；器律引用铸法，并自带被动能力树。
- 阵法通过 `物品/阵法/规则/炼制.json` 确定灵矿、兽宝、灵植与阵基、阵眼、节点的唯一对应关系；地点业务后续只引用阵法编号。
- 功法、真意、气机、器律各自携带完整能力树，不再引用任何编号机制。
- 气机引用战斗属性名。
- `战斗/规则/构筑/相冲.json` 用卡片编号分组约束功法和真意组合。

阵法内容已建立稳定实体索引，并由阵法核心解释、炼阵与布阵玩法编排；战斗侧通过战斗核心的战场阵法协议执行。被 JSON 微服务加载不等于已经形成可玩业务，新增内容仍须先有对应服务再登记为可用。

## 修改检查

1. 新内容文件名必须在整个 `内容` 树中唯一。
2. 新编号必须符合 `基础/定义/编号.json` 的类别前缀。
3. 改池文件名时必须全库更新所有池引用。
4. 改属性名时必须检查功法、真意、气机与构筑规则。
5. 内容可以改展示名称，但数据库和具体引用必须继续使用稳定编号。

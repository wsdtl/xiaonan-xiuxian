# 规则 JSON 关系说明

`规则` 保存跨实体复用的计算方式和流程参数。规则不枚举具体人物、地点、商店或主持者；地点专属开放范围和主持实体一律由 `世界/内容/<区域>/<地点>/` 承载。

## 编写契约

规则 JSON 只保存服务能够直接判断或计算的数据。字符串只能承担稳定编号、数据集名、文件名、字段名或有限枚举；运行规则不得依赖代码解析自然语言句子。

- 数据引用使用包含 `数据集`、`文件`、`实体类别`、`对象` 或 `字段` 的字典，不使用 `文件.字段` 拼接字符串。
- 计算使用明确算法名、操作符和输入数组，不保存公式字符串。
- 生命周期使用事件、阶段、偏移量和布尔开关，不使用“某事之后再做某事”的句子。
- 覆盖、保留、清除、丢弃等行为只作为有限操作枚举，并由所属服务逐项校验。
- 世界观解释、设计原因和示例流程写入同目录 `说明.md`；实体自身需要展示的名称与说明可以留在内容 JSON。

## 依赖方向

```text
定义 -> 规则 -> 内容实例/运行实例
```

规则可以引用定义中的属性、资源和事件名，但不能反向定义新属性、新事件或新内容实体。内容可以选择使用哪条成长规则，但不能复制一份规则后偷偷分叉。

## 角色关系

道侣规则与世界道侣实体的关系是：

```text
世界道侣实体
  + 角色/主体/道侣.json 的关系规则
  + 角色/主体/道侣.json.修行槽位
  + 角色/成长/修士修炼.json
  + 战斗/定义/属性.json 默认值
  -> 未来持久化道侣实例
```

角色自身的 `修行槽位` 只声明功法、真意和气机的槽位数量，不提供候选池。角色候选池必须以后单独用池引用定义；器律孔属于本命武器，不得写入角色修行槽位。

人物、道侣和敌方修士共同引用 `角色/定义/性别.json`，但分别采用创建选择、实体固定和生成随机。道侣主体额外规定首次邀约双方性别不同，成功邀约后不再重复检查；灵兽不引用修士性别定义。

构筑生成规则与角色槽位相互独立：角色先给出需要生成多少项，`构筑/生成.json` 再引用 `构筑/相冲.json` 检查组合。战斗核心不参与这一步。

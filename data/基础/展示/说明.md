# 展示 JSON 总览

> 本说明只写现行规则与边界；历史变更见 git 历史，待补事项与缺功能见 [待补内容.md](../../战斗/内容/待补内容.md)。

`展示`只决定已经发生的游戏事实怎样命名、着色和组织，不参与战斗、行路、资产或位置裁定。每个一级目录对应一个消费领域，根目录不再平铺业务 JSON。

展示目录只保存模板、按钮、图标、分页和排序，不保存地点商店目录、主持者、价格、开放阵法或任何可执行业务事实；这些事实由世界和领域核心从内容 JSON 返回后再套用展示模板。

| 目录 | JSON 职责 | 消费服务 |
| --- | --- | --- |

| `行路` | 路线事实的行程措辞与境界叙事 | 世界核心、行路玩法 |
| `纳戒` | 玩家资产的大类、小类、排序与分页 | 玩家资产核心、纳戒玩法 |

**这张表是示例，不穷举。** 它还缺 `宗门` 与 `宗门` 下的 `山门`、`宗门同行`、`灵藏`、`万珍殿`、`藏经阁`、`宗门设施`，缺 `炼丹`、`炼器`、`阵法`、`交易`、`先天灵宝`、`切磋`、`培养`、`归元`、`托管`、`易形`、`服丹`、`补天`、`讨伐`、`赠送`、`铜雀台`、`队伍` 等展示域；**权威清单不看这张表，看下面逐个组件清单登记的 `数据集`／`路径`／`结构`**——任何一个领域的展示数据集都以那份清单为准，新增或改名时只改清单。

按当前各 `组件.json` 现数，三种口径各自是（口径不同、数就不同，所以写清楚）：

- **数据集名里带「展示」**的登记条目 **38** 条，去重后 **34** 个数据集名；
- **路径里有 `展示/` 这一段**的登记条目 **54** 条（这是交付面的全部，也包含按钮类数据集），去重后 **50** 个数据集名；
- `data/` 下的 `展示` 目录 **27** 个：`基础/展示` 是这份说明自己所在的文档目录、不交付数据，其余 **26** 个是数据展示域（`宗门/展示` 一处分出 `山门`、`宗门同行`、`灵藏`、`万珍殿`、`藏经阁`、`宗门设施`、`宗门生产`、`宗门战` 8 个子域，另加 `宗门/展示` 根目录本身；`世界/位置/展示` 与 `玩法/道侣/展示` 各自再分 `规则`／`按钮` 两层）。

## 公共边界

- 展示 JSON 只能格式化已经产生的结构化事实，不能创造事件、改变查询范围或修改结算结果。
- 玩家可见文案、图标、颜色、按钮名称和命令来自 JSON，前端与命令层不维护第二份展示定义。
- 按钮只声明动作编号、名称、完整命令、行为和样式；触发后仍须重新经过状态守卫和业务校验。
- 修改 JSON 后先运行 Prettier、JSON 数据服务初始化和对应消费服务测试。

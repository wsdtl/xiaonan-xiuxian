# 基础数据包

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、启动期的引导校验
1. **先读引导文件**：`JsonDataReader` 固定读 `基础/读取规则.json`，解析出的 `DataReadRules` 是后续所有扫描的输入；读不到或根值不是对象即 `JsonDataError`。（`game/core/data/files.py`）
2. **入口字段定死**：引导对象只允许 `扫描目录`、`编号定义`、`文件名唯一`、`资源池字段`、`归属规则` 五个键，多一个少一个都拒绝启动；`读取规则` 是各组件清单汇总后补进来的。（`读取规则.json`、`game/core/data/files.py`）
3. **禁止游离 JSON**：`data/` 根目录下出现任何 `*.json` 直接报「正式 JSON 必须归属组件」；扫描得到的大类目录集合必须与 `扫描目录` 首段集合完全相等。（`game/core/data/files.py`）
4. **目录语义固定**：`扫描目录` 共 29 个组件相对路径，允许一层 `大类/组件`；`文件名唯一` 只声明 `内容` 一个作用域；`编号定义` 必须指向唯一匹配一条读取规则的文件。（`读取规则.json`、`game/core/data/files.py`）
5. **父目录跳子组件**：`世界/位置`、`世界/行路` 这类更深的扫描目录，其首段在父目录扫描时整段跳过，否则子组件文件会被判成没有匹配规则。（`game/core/data/files.py`）

### 二、组件清单与读取规则
6. **组件自证身份**：每个扫描目录下必须有 `组件.json`，只允许 `组件`、`读取规则` 两个键，`组件` 必须等于目录名，每条规则的 `路径` 必须以 `组件名/` 开头——组件不能注册别人的文件。（`组件.json`、`game/core/data/files.py`）
7. **必须声明语义分类**：除引导文件自身外，每条规则的路径至少要到 `组件/定义|规则|内容|展示` 这一层，否则报「数据必须声明组件内语义分类」。（`组件.json`、`game/core/data/files.py`）
8. **规则字段与形状**：规则行的键限于 `数据集`/`路径`/`结构`/`实体类别`/`编号类别`/`目录主体`/`归属目录层级`；`结构` 只认对象、字典列表、编号实体列表、编号实体池、命名实体池、命名实体、编号池、源池八种组合，路径不许绝对、不许 `..`、只允许 `*` 通配。（`game/core/data/files.py`）
9. **形状与字段互锁**：实体类结构必须给 `实体类别`，非实体结构不许给；编号实体列表/池必须给 `编号类别`，其他结构不许给；`归属目录层级` 必须是非负整数且小于路径段数。（`game/core/data/files.py`）
10. **引导自匹配**：读取规则之间不允许重复路径；`基础/读取规则.json` 与 `编号定义` 都必须恰好被一条规则命中，零条或多条都拒绝启动。（`game/core/data/files.py`）

### 三、装载校验与快照
11. **文件唯一归属**：每份 JSON 按首段分桶取候选规则，用 `ReadRule.matches` 全匹配筛；零条命中报「没有匹配的读取规则」，多条命中报「匹配多条读取规则」；`目录主体` 为 true 时还要求文件名等于父目录名。（`game/core/data/files.py`）
12. **读入即冻结**：`json.loads` 用 `object_pairs_hook` 拒绝重复键，随后递归把对象转 `MappingProxyType`、数组转 `tuple`；文件系统或语法错误统一裹成「数据文件读取失败」。（`game/core/data/files.py`）
13. **数据集内数据名唯一**：同数据集内 `file_id` 重复即报错；`文件名唯一` 声明的 `内容` 作用域再按文件名全局去重，路径也按大小写不敏感去重。（`game/core/data/files.py`）
14. **内容形态校验**：编号实体列表根值必须是非空数组、每项是对象、有非空 `编号` 且文件内不重复；命名实体集合必须是非空对象；命名实体的 `名称` 若写了必须等于文件名。（`game/core/data/loading.py`）
15. **实体身份冲突**：同一 `实体类别` 下同编号重复定义，只有正文逐键相同时才容忍，否则报「实体身份冲突」并给出两个来源文件。（`game/core/data/loading.py`）
16. **编号前缀比对**：装载末尾拿 `编号定义` 的 `编号前缀` 建「类别 → 前缀集合」，逐份编号文档检查编号长度等于 `位数` 且全是数字、前 `前缀位数` 位落在该 `编号类别` 的集合里，否则报错。（`定义/编号.json`、`game/core/data/loading.py`）
17. **资源池展开**：编号池只允许六位数字编号，源池只允许源文件名（两者互斥）；展开按 `section` 校验池类别一致，遇到循环引用报出完整链条；池为空、引用不存在的实体都报错。（`game/core/data/loading.py`）
18. **池引用字段白名单**：递归扫每份文档里以 `池` 结尾的字段，字段名必须登记在 `资源池字段`，值是文件名或文件名数组，指向的内容文件必须是同一类别的资源池。（`读取规则.json`、`game/core/data/loading.py`）
19. **一次性快照**：`initialize()` 全程持锁，第二次调用直接 `RuntimeError`（数据更新必须重启服务）；快照冻结前跑 `game.core.combat.service.expand_build_section` 把构筑模板引用展开成完整能力树，并同步改写 `entities` 与 `entity_records` 两份索引。（`game/core/data/service.py`）
20. **读取接口**：`dataset(name)` 返回文件名到不可变正文的视图，缺名即「数据集不存在」；`entity`/`entities`/`entity_record` 按类别取，未登记类别报「未知实体类别」、缺编号报「实体不存在」；`entity_fields`/`pool_fields` 只复制点名字段，字段为空、重复或实体缺该字段都报错。（`game/core/data/service.py`）
21. **只读与可变副本**：运行期不加读锁、不复制完整正文，领域服务要改只读值必须过 `materialize()` 转成可变副本；`replace_entities` 只给装载期展开用，写回前逐个实体重新裹回只读。（`game/core/data/service.py`）

### 四、编号与品级的消费口径
22. **编号前缀表**：`编号前缀` 共 21 条，每条是 `前缀`/`主体`/`类别` 三元组；`AssetService._load_prefixes` 初始化时读入并按前缀建索引，前缀重复即拒绝启动。（`定义/编号.json`、`game/core/asset/service.py`）
23. **前缀反查类别**：`_number_identity(content_id)` 取编号前两位查表，查不到报「资产编号前缀未定义」；类别为 `丹药` 时返回 `主体`，其余返回 `类别`，第二个返回值始终是 `类别`。（`game/core/asset/service.py`）
24. **品级表装载**：`_load_grades` 把 5 条品级读成 `AssetGrade(编号, 名称, 阶序, 能力倍率, 价格系数)`，`阶序`、`权重` 走正整数校验，`能力倍率`、`价格系数` 走数值校验；简称（`黄` 与 `黄品`）去重后建反查索引，重复即报「品级简称重复」。（`定义/品级.json`、`game/core/asset/service.py`）
25. **品级解析入口**：`AssetService.grade(grade_id)` 先按 `编号` 精确查，再按归一化简称查，两轮都空抛「未知物品品级」；掉落抽取用 `权重` 的倒数做 `random.choices`，`阶序` 只用于排序。（`game/core/asset/service.py`）
26. **品级数值的落点**：`能力倍率` 只在协议明确允许缩放的能力数值上生效，`价格系数` 只用于价格；交易类服务用 `类别基础价格 × 品级.价格系数` 算单价，与 `阶序`、`权重` 无关。（`定义/品级.json`、`game/core/asset/service.py`）

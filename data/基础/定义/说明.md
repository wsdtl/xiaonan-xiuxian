# 定义 JSON 关系说明

> 本说明只写现行规则与边界；历史变更见 git 历史，待补事项与缺功能见 [待补内容.md](../../战斗/内容/待补内容.md)。

`定义` 描述游戏数据可以使用哪些稳定身份和底层概念。它不保存某个具体人物、物品或技能，也不描述玩法流程。

地点功能的同目录内容由 `世界/定义/地点功能.json` 声明；商店、炼器工匠、炼丹师和阵师属于地点内容，不得登记在炼器、炼药或阵法的全局主持目录。

## 文件关系

| 文件 | 定义什么 | 直接约束谁 |
| --- | --- | --- |
| `基础/读取规则.json` | 组件相对路径、数据集、路径匹配、结构、实体类别和池引用字段 | JSON 数据微服务及所有数据消费者 |
| `基础/定义/编号.json` | 六位实体编号、类别前缀、两位品级编号 | 道侣、普通物品、丹药、功法、真意、气机、境界、阵法、器律 |
| `基础/定义/品级.json` | 品级编号、阶序、抽取权重、能力倍率、价格系数 | 物品实例及需要品级的能力实例 |
| `角色/定义/性别.json` | 修士允许使用的稳定性别取值 | 人物创建、世界道侣、敌方修士生成与首次邀约 |
| `战斗/定义/属性.json` | 39 项战斗属性及默认值、范围、单位 | 初始人物、成长、敌人、道侣、气机、战斗计算 |
| `战斗/定义/资源.json` | 血气、精神、护盾与各自上限属性 | 参战快照、恢复、消耗、伤害和战报 |
| `战斗/定义/事件.json` | 66 个事件窗口、事实和可修改项 | 监听节点、事件改写、战报事件 |
| `战斗/定义/原子能力.json` | 65 种能力节点的字段协议和执行器 | 功法、真意、气机、器律、状态反应 |
| `世界/行路/定义/行程指标.json` | 路线高度剖面和路程的稳定指标 | 世界道路、全地表自动选路、行程展示 |

战斗定义的详细组合关系见 [战斗/定义/说明.md](../../战斗/定义/说明.md)。
行路定义的详细组合关系见 [世界/行路/定义/说明.md](../../世界/行路/定义/说明.md)。道路和地形通行倍率属于规则，不属于行程指标定义。

## 数据读取规则

读取器唯一硬编码的入口是 `基础/读取规则.json`。其中每条 `读取规则` 都把一组文件交付为一个数据集：

| 字段 | 作用 |
| --- | --- |
| `扫描目录` | 启动时扫描的正式数据根目录 |
| `编号定义` | 六位实体编号规则的来源文件 |
| `文件名唯一` | 要求文件名全局唯一且允许按文件名引用的目录 |
| `资源池字段` | 池字段名到实体类别的对应关系 |
| `数据集` | 其他微服务请求的稳定集合名 |
| `路径` | 相对 `data` 的路径模式 |
| `结构` | 对象、字典列表、编号实体列表、编号实体池、命名实体池、命名实体、编号池或源池 |
| `实体类别` | 需要建立实体或池索引时使用的类别 |
| `编号类别` | 编号实体应命中的 `编号.json` 类别 |
| `目录主体` | 区域、地点等文件名必须等于父目录的额外约束 |
| `归属目录层级` | 数据服务从目录结构提取实体归属并作为元数据交付，业务服务不解析文件路径 |

一份正式 JSON 必须且只能匹配一条规则。路径顺序不用于掩盖重叠规则；出现零条或多条匹配都会阻止启动。新增服务时应优先复用现有数据集，确需新增数据集时先修改这份 JSON，再让服务通过统一 JSON 数据服务按数据集名请求它。

## 编号关系

```text
编号前缀 + 四位流水号 = 六位稳定实体编号
品级编号 = 独立两位字符串
```

丹药按用途分流前缀：恢复 `10`、战斗 `12`、突破 `14`、特殊 `16`；**丹药自己就是处方**，没有单独的丹方数据集。境界使用 `51`，不与角色实例编号混用。

六位编号只表达实体身份，不表达品级、强度、地区或方向。资源池使用文件名，不使用编号；具体实体引用使用编号，不使用名称。

新增一种编号实体时必须同时检查：

1. `编号.json -> 编号前缀` 是否已有类别；
2. 读取规则中的 `编号类别` 是否与前缀一致；
3. `读取规则.json` 是否声明了正确的数据集、实体类别和编号类别；
4. 数据库是否只保存编号而非展示名称。

## 品级关系

`品级.json` 自身不属于物品池。运行期先得到实体编号，再独立得到品级编号，最后形成实例：

```json
{
  "编号": "400001",
  "品级": "03"
}
```

`能力倍率` 只应作用于协议明确允许缩放的能力数值；`价格系数` 只用于价格。不得遍历所有数字进行无差别缩放。

## 修改边界

- 新增或移动正式 JSON 时，必须先修改 `读取规则.json`，并保证文件只匹配一条规则。
- `结构` 只描述通用根值与索引方式，不承载战斗、世界或角色业务；业务解释属于消费该数据集的服务。
- 删除属性前，必须检查成长、初始覆盖、敌人、道侣、气机、器律和展示摘要。
- 删除资源前，必须检查 `资源.json`、原子能力、行动恢复和战报资源配置。
- 删除事件前，必须检查全部监听节点与事件改写节点。
- 修改编号前缀会破坏存档身份，已有前缀和编号不得重排。

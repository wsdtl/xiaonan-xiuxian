# 丹药 JSON 关系说明

丹药是炼丹领域的可堆叠成品，按用途分配编号前缀：恢复丹使用 `10`，战丹使用 `12`，突破丹使用 `14`，特殊丹使用 `16`。四类丹药分目录维护，共 359 个实体：恢复丹 6 个、战丹 160 个、突破丹 189 个、特殊丹 4 个。

```text
丹药/
  恢复丹/  # 血气、精神
  战丹/    # 基础、单监听药性与复合监听药性
  突破丹/  # 十九个突破节点的正丹、单属性丹与复合属性丹
```

## 关系

```text
丹药实体.编号 <-------- 角色/规则/主体/人物.json.物品[].编号
丹药实体       <-------- 敌人掉落或未来其他物品池
使用效果       --------> 服丹、突破与特殊地点业务
恢复量/恢复百分比 --------> 血气或精神资源
战丹.战前状态  --------> 下一场正式战斗的预置状态
战丹.监听    --------> 自带完整文本的监听事件节点
战丹.强度 -------------> game/core/alchemy/service.py -> 允许炼制难度
突破丹.目标境界 -------> 角色/内容/境界.json.编号
突破丹.永久属性 -------> 战斗/定义/属性.json
九霄补天丹.补正来源 ----> 同目标境界且只有一项永久属性的突破丹
守真定契丹.护持道契 ---> 世界/内容/云京州/铜雀台/铜雀台.json.功能配置.夺元
两仪易形丹.转变性别 ---> 角色/定义/性别.json
参考价         --------> 基础/定义/品级.json.价格系数
```

`使用效果.类型` 必须登记于 `物品/基础物品/定义/使用效果.json`，不等同于战斗原子能力；物品微服务按登记的执行器解释，不能把文字说明当规则解析。`寄存战丹` 只保存下一场战斗需要的状态定义和监听节点正文，炼药服务校验寄存规则，战斗核心只解析已经准备好的状态。

恢复丹统一使用相对资源上限的恢复百分比，当前血气三档为 `8% / 15% / 25%`，精神三档为 `6% / 12% / 20%`。若实例带品级，品级能力倍率怎样作用于恢复量必须由正式物品协议统一执行，不能在每种丹药上写不同代码。

每枚丹药自己记着怎么炼（炉法、炼制难度）。不同丹药可以复用炉法，由炼制难度、药引、炉法与辅材实际组合共同决定成丹；战丹额外受强度约束，不再要求一枚丹药机械对应一种专用炉法。突破丹只负责突破与立即结算永久属性，不承载事件监听、随机成长或未来每级成长。

两仪易形丹只作用于玩家本人，在男、女之间转换；既有道侣关系、好感、赠礼历史、同行关系、属性、成长、构筑和本命武器数据均保持不变。

九霄补天丹支持人物和当前同行道侣，只作用于未补正的纯突破节点。执行时从同目标境界、且 `永久属性` 只有一个字段的突破丹中选择一枚；属性立即写入角色，突破记录保存来源编号，后续修改 JSON 不追溯已有角色。复合属性突破丹不能作为补正来源。

## 修改检查

- 编号必须按用途使用 `10`、`12`、`14` 或 `16` 前缀，读取后仍统一归为丹药。
- 恢复目标必须对应已登记资源。
- `寄存战丹` 必须声明 `战前状态`，且状态持续单位必须是 `整场战斗`；若声明 `监听`，每个节点必须是自带完整文本的 `监听事件`。
- `境界突破` 必须引用存在的目标境界；永久属性若存在，只能使用正式战斗属性且数值必须大于零。
- 改编号会破坏初始物品和未来存档引用，禁止重排。
- 新增使用效果类型时必须同步建立通用执行语义和测试。

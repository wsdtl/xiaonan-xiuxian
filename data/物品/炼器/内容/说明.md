# 炼器内容

> 本说明只写现行规则与边界；历史变更见 git 历史，待补事项与缺功能见 [待补内容.md](../../../战斗/内容/待补内容.md)。

`器律-*.json` 是可锻入本命武器的具体器律。每条器律使用六位稳定编号，声明所需器阶、铸法、兽引和战斗能力。

器律自带完整被动能力树，不引用任何编号中间层。炼器服务负责校验兽宝、灵矿和四孔覆炼；战斗核心只按器律编号装载最终能力，不读取锻造材料。

当前首批 64 条器律按战斗用途拆成八个文件，每个用途均覆盖灵器、法器、法宝和后天灵宝。后续增加器律只需增加 JSON 实体并引用已登记铸法，被动效果直接按 `战斗/定义/原子能力.json` 写完整文本。

`池/` 按器阶保存四个编号池，每池 16 条器律，并完整覆盖对应器阶。自动生成本命武器时，第一至第四孔依次从灵器、法器、法宝和后天灵宝池抽取；玩家主动炼器仍然按器律编号选择，不受随机池限制。

## 监听时点

器律是**器物本体反应**，只观察持有者与武器的交互界面；战场叙事归真意。实测 64 条器律用到 29 个时点，全部是真意 55 个时点的子集，偏重在 `恢复后`、`受到伤害后`、`命中后`、`技能冷却变化后`、`添加状态前`。

`战斗对象入场后/退场后`、`战场规则变化后`、`形态切换后`、`复活后` 这五个**语义上不属于器物**，器律不应监听。完整判据与分布见 `data/战斗/规则/说明.md` 的「真意与器律的监听分工」——那是约定，不是启动校验。

## 词条命名

器律的计量与状态名字逐条唯一，取「器律名前两字 + 器物场景词」：计量用 `回元 / 裂锋 / 凝印 / 引诀 / 化盾 / 蓄势`，状态用 `器印 / 器契 / 器兆`（正面）与 `器痕 / 器隙 / 器纹`（负面）。名字只描述这条器律自己的池子，不许引用别的器律定义的名字。撞名检查见 `tools/架构审查/检查词条作用域.py`。

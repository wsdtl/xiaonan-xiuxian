# 炼器内容

`器律-*.json` 是可锻入本命武器的具体器律。每条器律使用六位稳定编号，声明所需器阶、铸法、兽引和战斗能力。

器律的能力树**直接内联写在实体里**，不引用构筑模板——装载期展开仍支持模板格式，但当前 64 条一条都没用（库里那批器律模板因此成了孤儿，见 `tools/报告与生成/盘点模板库.py`）。炼器服务负责校验兽宝、灵矿和四孔覆炼；战斗核心只按器律编号装载最终能力，不读取锻造材料。

当前首批 64 条器律按战斗用途拆成八个文件，每个用途均覆盖灵器、法器、法宝和后天灵宝。后续增加器律需增加 JSON 实体并引用已登记铸法；被动效果使用已登记原子能力，内联成完整能力树。

`池/` 按器阶保存四个编号池，每池 16 条器律，并完整覆盖对应器阶。自动生成本命武器时，第一至第四孔依次从灵器、法器、法宝和后天灵宝池抽取；玩家主动炼器仍然按器律编号选择，不受随机池限制。

## 监听时点

器律是**器物本体反应**，只观察持有者与武器的交互界面；战场叙事归真意。实测 64 条器律用到 **25** 个时点（187 处），偏重在 `受到伤害后`、`行动开始`、`恢复后`、`行动结束`、`事件转化后`、`技能冷却变化后`。它与真意是**分工**而不是子集关系：真意同样是 25 个时点，两边重合 14 个，器律另有 11 个（`格挡后`、`护盾吸收后`、`格挡判定前`、`恢复前`、`恢复后`、`行动结束`、`资源消耗后`、`添加状态前`、`添加状态失败后`、`事件转化后`、`受到致命伤害`）——这些是「器物与持有者交互界面」上的事，真意不管。

`战斗对象入场后/退场后`、`战场规则变化后`、`形态切换后`、`复活后` 这五个**语义上不属于器物**，器律不应监听。完整判据与分布见 `data/战斗/规则/说明.md` 的「真意与器律的监听分工」——那是约定，不是启动校验。

## 词条命名

器律的计量与状态名字逐条唯一，取「器律名前两字 + 器物场景词」：计量用 `回元 / 裂锋 / 凝印 / 引诀 / 化盾 / 蓄势`，状态用 `器印 / 器契 / 器兆`（正面）与 `器痕 / 器隙 / 器纹`（负面）。名字只描述这条器律自己的池子，不许引用别的器律定义的名字。撞名检查见 `tools/架构审查/检查词条作用域.py`。

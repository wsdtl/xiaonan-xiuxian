# 组件数据包

data 分两层：**顶层是六个大类；大类要么本身是一个组件，要么是容纳组件的一层**。

```text
data/
  基础/   组件.json  定义/ 规则/ 内容/ 展示/
  角色/   组件.json  定义/ 规则/ 内容/ 展示/
  战斗/   组件.json  定义/ 规则/ 内容/ 展示/    内容下分：构筑 功法 真意 气机 战场环境 意境 血脉
  物品/   组件.json  定义/ 规则/ 内容/ 展示/    规则下分：基础物品 丹药 炼器 阵法
                                               内容下分：灵植 灵矿 兽宝 灵石 丹药 器律 阵法
  世界/   组件.json  定义/ 规则/ 内容/ 展示/    内容下分：区域 地点（含 地点/特殊地点/） 人物 设施 敌人 道路
  玩法/   查看与工具/ 修行/ 关系/ 行动/ 战斗/ 炼制/ 宗门/ 特殊地点/ 后台入口/   只装组件，自己没有面
```

## 硬规矩

1. **一个目录要么是组件，要么是容器，不能两者兼是。** 组件只有定义、规则、内容、展示四个面；容器只有子组件。
2. **内容面只放实体与关系，不放裁定参数。** 裁定参数住 `规则/`，字段契约住 `定义/`。
3. **类别多时可在面下再分一层**（如 `内容/功法/<书脉>/`）。这一层只影响文件放哪，不影响数据集名与编号——数据集名是公共读取契约。
4. **数据归属看「谁拥有规则」，不看谁消费。** 器律是炼器产物，归物品包，虽然战斗把它当构筑读；丹药同理。
5. **地点的归属由坐标决定。** 目录按「州/地点」分只为方便看地图，「属于哪个州」的真值是坐标落在哪个区域的坐标带，两者必须一致。
6. **规则里的每个键都要有人读。** 没人读的声明要么接上消费者，要么删掉——留着比没有更坏。
7. **编号实体一件一个对象。** 文件名是 `编号-名称`；所在目录就是池/分组；需要随机时由核心按目录合成列表，不再写多实体池文件。命名实体（世界、区域、地点、商店）按名称一档；资源池、道路关系、按钮/文本等成组数据才用列表。

## 说明怎么写

说明分两层，各管各的，不重复：

- **组件说明**（`<组件>/说明.md`）：这一包**行为的唯一出处**。开头一节 `## 功能`，按点写中文逻辑；文末 `## 数据集` 表列本包读过哪些文件。
- **领域说明**（`<面>/说明.md` 及更深）：只讲**数据形态与分组**——这个目录放什么、按什么分组、改动时同步什么。

写法要求：

- **一条只说一件事**，条目编号全篇连续；段标题只分节，不重编号。
- **讲逻辑，不讲代码**：不出现 `game/...`、`.py`、函数名、类名、异常名、变量名。
- **反引号只留给数据**：数据键与取值（`有效秒数`）、数据文件路径（`规则/切磋.json`）。
- **只写真实存在的逻辑**，没实现的不写。
- **字段名、数值、上限照抄数据**，不改写、不约等。说明与实现对不上时，**以说明为准**，实现照它改。
- **排版交给判据**：标题级别不跳级、前后留空行、代码块写语言并闭合、无连续空行与行尾空白。

## 主要归属

| 大类 | 组件 | 内容 |
| --- | --- | --- |
| 基础 | 基础 | 全局编号、跨领域品级、读取入口与编写规范 |
| 世界 | 世界、位置、行路 | 地势、区域、地点、道路，以及位置页与行程 |
| 角色 | 角色 | 性别、主体、成长、突破、伤势、人物状态 |
| 战斗 | 战斗 | 原子定义、结算规则、构筑形状、环境、功法、真意、气机及战报 |
| 物品 | 基础物品、炼丹、炼器、阵法 | 物品分类与材料、丹药与丹方、器律与器阶、阵法与炼制设施 |
| 宗门 | 宗门 | 宗门规则及园区事务、灵藏、藏经阁、设施、生产、宗门战展示 |
| 玩法 | 交易、先天灵宝、切磋、培养、归元、托管、探险、易形、服丹、补天、赠送、道侣、采矿、采药、铜雀台、闭关、队伍 | 各自的通用玩法规则与展示 |

数据归属与服务解释权可以不同：世界包的敌人由敌人核心解释；炼器包的器律由战斗核心执行最终能力。目录不要求与代码一一对应。

## 体量

战斗构筑卡片在内容里保存卡头与**完整能力树**；模板机制已于 2026-10-16 拆除，装载期不展开任何引用，战斗与文本渲染读到的就是文件里写的那棵树。

卡片 `说明` 只放卡头（风味与五行），规则正文由能力树现拼现显示，不会出现「JSON 改了说明没改」的漂移。

## 加载契约

1. 唯一入口是 `基础/读取规则.json`，取得组件相对路径、编号定义与池引用字段。
2. 每包必须有 `组件.json`，只注册本包路径；未登记目录、清单身份错误、越界规则一律拒绝加载。
3. 正式 JSON 必须唯一匹配一条规则。
4. 按稳定数据集、实体类别与池文件名交付；领域服务不解释目录布局。

组件清单是加载元数据，不计入业务文档数。所有组件的内容文件名仍全局唯一；实体引用保存稳定编号，池引用保存不带扩展名的文件名。目录迁移不改变身份或状态所有权。

## 验证

改正文或清单前先读所属说明；新增组件要同时登记入口；运行期不热重载，改完重启进程。

```powershell
.venv/Scripts/python.exe -X utf8 tools/全量核对.py
.venv/Scripts/python.exe -X utf8 -m pytest -q tests
```

`pytest` 不在 `requirements.txt` 里，全新克隆要先补装。维护目录不留一次性改写脚本；历史改写只在 git 历史里。

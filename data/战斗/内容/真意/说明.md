# 真意 JSON 关系说明

真意是修士在修行与战斗中领悟的被动战斗规律，使用 `41` 前缀编号。当前 20 个分类池、600 道真意。真意归角色自身承载，不依附本命武器，也不占用器律位置。

## 结构关系

```text
真意实体
-> 恰好一项被动技能
-> 效果[] 全部是监听事件节点
```

真意没有主动技能，不形成完整功法循环。被动技能与监听节点必须符合 `战斗/定义/原子能力.json`，所监听事件必须存在于 `战斗/定义/事件.json`。真意的监听效果可通过战斗构筑模板保存；数据装载时展开为完整能力树，模板不定义新的战斗语义或玩家显示名称。

## 与其他 JSON 的关系

- 各角色自身 JSON 中的 `修行槽位.真意` 决定角色真意槽数量；本命武器只承载器律；
- `战斗/规则/构筑/相冲.json` 保存真意参与的卡片相冲；
- `基础/定义/品级.json` 为真意实例提供独立品级；
- 玩家从解析全部真意实体文件后按编号合并的虚拟全池随机，不维护全池 JSON；
- 道侣不使用公共定向总池；每个角色从 `池/道侣/` 的个人真意池随机；
- 敌人通过 `池/敌方修士/` 的六个阶段源池取得杀伐、压制和控制候选池；
- 灵兽通过 `池/灵兽/` 的六个阶段源池取得追击、状态、御灵和绝境候选池。

真意不保存评分、方向、兼容标签或词条表。每道真意在实体根节点保存自身逆权重；定向池不复制真意实体：道侣个人池直接保存真意编号字符串，敌人阶段池直接保存源池文件名字符串。六个敌人阶段池彼此独立，不隐式继承前一阶段。

## 定向随机池

三个池目录各管一件事，**根节点一律是字符串列表**，不套 `资源池` 字典，也不复制实体定义、名称、评分、权重或方向标签。

- `池/道侣/`：不保存公共总池。264 名道侣各自一份以「道侣编号-真意池」命名的个人池，每份 24 个稳定编号，文件名不含可变的角色名称；选材口径与功法个人池相同，运行时以道侣实体的 `真意池` 引用定位。**不得用全库随机或公共道侣池作隐式兜底**。
- `池/敌方修士/`：按六阶拆成六份独立源池，由 `角色/规则/主体/敌方修士.json` 各阶梯的 `真意池` 引用；池内直接保存 `真意-*` 实体源文件名字符串，数据服务递归展开并校验编号。
- `池/灵兽/`：同样按六阶拆分，由 `角色/规则/主体/灵兽.json` 的 `真意池` 引用；候选从状态、追锋和行气逐步扩展到御灵、阵域、绝境、献祭与归墟。
- 敌人阶段池**不继承上一阶段**，业务只展开当前阶段文件列出的源池。

## 监听时点

真意是**战场叙事**，观察范围覆盖整个战场：他人入场退场、战场规则变化、行动管理（`行动开始/结束`、`行动条变化后`、`行动意图变化后`、`行动跳过后`）、技能本体变化（`技能施放前`、`技能施放失败后`、`技能变化后`）、以及各类结算前改写点（`资源消耗前`、`资源恢复前`、`移除状态前`、`获得护盾前`）。这些时点器律一律不用。

实测 600 道真意覆盖 55 个时点、1287 个监听节点，平均每张 2.15 个；器律的 29 个时点是它的真子集。判据与分布见 `data/战斗/规则/说明.md` 的「真意与器律的监听分工」——那是约定，不是启动校验。

## 修改检查

- 编号必须使用 `41` 前缀。
- 权重必须是正整数；同名实体权重必须一致，异名实体权重不得重复。
- 根能力必须是被动技能，且恰好一项；效果里出现主动技能或非监听节点都属于越界。
- 每道真意的模板引用与参数共同决定其完整效果；不得复制其他真意的实际构筑，也不靠改名制造新效果。
- **计量与状态的名字逐条真意唯一**：名字 = 真意名前缀 + 场景词（`返真/养真/意痕`），全库不重名，也不引用别的真意定义的名字。撞名检查见 `tools/架构审查/检查词条作用域.py`。
- 新增、删除或改名源池时同步更新敌人阶段池；改真意编号时同步检查道侣个人池。

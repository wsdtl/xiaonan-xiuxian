# 气机 JSON 关系说明

气机是修士周天运转形成的固定属性倾向，使用 `42` 前缀编号。当前 68 套构筑、408 道气机。气机归角色自身承载，不依附本命武器。

## 结构关系

```text
气机实体.能力[0]
-> 固定属性加成
-> 属性名必须来自 战斗/定义/属性.json
-> 装配后合并到参战者快照的属性
```

气机不监听事件，不生成主动或被动技能，也不引用任何编号中间层。双属性气机只是一个节点中的两个属性，不是两道单属性气机的运行时拼接。

## 与其他 JSON 的关系

- 各角色自身 JSON 中的 `修行槽位.气机` 决定角色气机槽数量；
- 气机数量只由角色自身的修行槽位决定；
- `基础/定义/品级.json` 为气机实例提供品级能力倍率；
- 玩家从全部 408 道气机按编号取用，不维护额外的全池 JSON；
- 道侣实体用 `构筑` 引用构筑模板，模板的 `气机` 列表固定编号；
- 敌方修士用 `构筑` 引用模板，按自己的 `修行槽位` 取气机；
- 灵兽没有构筑，不出气机实例。

气机实体一件一文件，根值是一个对象，字段与权重都写在实体上；不再有 `池/` 目录、道侣个人池或敌人阶段池。

同一编号无论装配到谁身上，属性定义和权重都必须完全相同。文件分类和名称都不能改变实体实际属性。

单属性气机承担专精溢价，其数值约为同属性在双属性气机中单项数值的 `2.5` 倍，并按属性最小单位取易维护整数。双属性气机承担广度，不因单属性的专精溢价同步放大。

## 构筑直配

- 道侣用 `构筑` 引用模板，模板的 `气机` 列表是稳定编号，不随机重抽；
- 敌方修士用 `构筑` 引用模板，按自己的 `修行槽位` 取卡；灵兽没有构筑；
- 玩家装配时从全部气机实体按编号取用，品级由实例单独决定。

## 修改检查

- 编号必须使用 `42` 前缀。
- 每道气机只能有一个 `固定属性加成` 根节点。
- 属性名、数值边界必须符合属性定义。
- 双属性组合不区分排列顺序，不能同时新增“攻击防御”和“防御攻击”。
- 气机不保存评分、方向或分类标签；每道气机在实体根节点保存自身逆权重。
- 权重必须是正整数；同名气机权重必须一致，不同名称的气机不得与任何功法、真意或其他气机使用相同权重。
- 改气机编号时同步检查构筑模板的 `气机` 列表；模板被哪些道侣/敌人引用，由实体上的 `构筑` 编号反查。

# 功法 JSON 关系说明

功法是完整战斗循环的二次对象，使用 `40` 前缀编号。当前 30 个分类池、600 门功法。

## 结构关系

```text
功法实体.能力
  ├─ 主动技能 -> 精神消耗、冷却行动、目标与效果
  └─ 被动技能 -> 监听和响应效果
          │
          └─ 引用战斗机制.机制 -> 内容/战斗机制中的六位编号
```

主动技能和被动技能根节点来自 `战斗/定义/原子能力.json`。其嵌套效果可以直接使用原子能力，也可以引用机制。属性、资源和事件名继续受战斗定义约束。

## 与其他 JSON 的关系

| 关系 | 数据 |
| --- | --- |
| 机制组成 | `战斗/内容/战斗机制/*.json` |
| 品级倍率 | `基础/定义/品级.json` |
| 角色修行槽位 | 各角色自身 JSON 中的 `修行槽位.功法` |
| 机制相冲 | `战斗/规则/构筑/相冲.json` |
| 精神、冷却、行动 | `战斗/定义/资源.json`、`战斗/规则/行动.json` |
| 玩家候选池 | 解析全部功法实体文件后按编号合并的虚拟全池，不维护全池 JSON |
| 道侣候选池 | `池/道侣/` 下按道侣编号命名的个人池 |
| 敌人候选池 | `池/敌方修士/` 下六个阶段源池 |
| 灵兽候选池 | `池/灵兽/` 下六个阶段源池 |

功法不再拥有随机词条，也不保存评分、方向或兼容标签。每门功法在实体根节点保存自身逆权重；玩家从解析器合并去重后的全部功法中按权重随机。定向池不复制实体：道侣个人池直接保存功法编号字符串，敌人阶段池直接保存源池文件名字符串。

## 两仪双相

只有明确编写两仪分支的少数功法可以读取修士性别。男性运转乾相，女性运转坤相；两相必须具有相同效果数量和接近的战斗预算，只改变战斗节奏，不改变能否修炼、装配槽位或功法权重。

两仪分支必须通过通用 `类型条件` 读取战斗快照的性别，不得为某门功法增加专用执行器。性别为空的参战者不命中乾相或坤相；不允许按敌方性别增加伤害，也不允许男性或女性专属修炼。

## 定向随机池

- 道侣不使用公共定向总池；每个角色从自己的个人功法池随机；
- `池/敌方修士/` 按初窥、登堂、入微、圆融、镇域、天灾拆为六个独立源池，偏向杀伐、压制、控制和反制；
- `池/灵兽/` 同样按六阶拆分，偏向肉身、扑杀、元素、毒雷、御灵和绝境能力；
- 敌人阶段池不继承上一阶段，业务只展开当前阶段文件列出的源池；
- 所有引用池的根节点都是字符串列表，不为每个字符串再套 `编号` 或 `资源池` 字典。

## 修改检查

- 编号必须使用 `40` 前缀且全库唯一。
- 权重必须是正整数；同名实体权重必须一致，异名实体权重不得重复。
- 所有机制编号必须存在，主动和被动引用类型必须匹配。
- 修改机制组合时重新检查 `战斗/规则/构筑/相冲.json` 的递归相冲。
- 新增、删除或改名源池时同步更新敌人阶段池；改功法编号时同步检查道侣个人池。
- 改功法名称不会改变身份；改编号则会破坏实例和存档，禁止修改。
- 增加新字段前先在原子能力 Schema 中证明它属于通用语义。

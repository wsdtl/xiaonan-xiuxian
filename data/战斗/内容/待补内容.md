补法是统一三步，不是逐卡手写：

1. 每张卡为它引用的那个名字造一个**本卡专属**状态，名字按现行规范取
   （卡名前缀 + 场景词，全局唯一，偶数前缀阶梯）；
2. 把该卡所有引用改指到新名字；
3. 在该卡对该状态的**第一个操作之前**插一个 `添加状态`，目标跟着那个操作的目标走。

状态参数（`补缺失状态.py` 顶部可调）：`类别=中性`（注册表默认值，也最保守——不会被动用
「正面/负面」的泛选状态意外扫到）、`持续单位=状态承受者行动`、`剩余行动=3`、`层数上限=5`。

上一批里有 8 张只有「读取目标身上的层数」、没有可锚的操作节点，单独收在
`补目标层数状态.py`：它们形状统一为
`主动技能.效果[N] = 条件执行(…, 成立效果=[造成伤害(数值=读取 当前目标的层数)])`，
补法是在含这条读取的**那门主动技能效果列表最前面**插一个 `添加状态`（目标=当前目标），
让这门技能每用一次就给目标记一层。

## 三、补完怎么验

两条通道都要跑，只跑一条会留盲区。**两条都已有入库基准，直接对照即可**，不必再手工留一份改动前的数据目录：

```powershell
# 构筑侧（功法/真意/器律，1264 场）
.venv/Scripts/python.exe -X utf8 tools/语料对照.py --对照 tools/基准/语料摘要
# 战前状态侧（战丹/长期伤势，170 场）
.venv/Scripts/python.exe -X utf8 tools/战前状态对照.py
```

两者都是**有差异就非零退出**，可以直接当检查用。基准入库跟踪（`tools/基准/`，48 KB + 6 KB），所以换一个会话也能直接对照；只有在**零抛错**时才会写基准，免得把坏状态固化成正确。

重新取基准（改平衡之后）：

```powershell
.venv/Scripts/python.exe -X utf8 tools/语料对照.py tools/基准/语料摘要
.venv/Scripts/python.exe -X utf8 tools/战前状态对照.py --写基准
```

**判据看改动性质，不能一概而论：**

| 改动性质 | 判据 |
| --- | --- |
| 纯结构等价（改名、搬位置、去冗余） | 两边摘要 **100% 一致** |
| 补内容 / 改平衡 | 差异 **⊆ 本次授权的卡**，授权卡之外 **0 处** |

改平衡时语料只是报警器，不是设计评审——它能说「变了」，不能说「变得对」。
所以每批补完都要有一份**授权卡清单**（`补缺失状态.py` 的报告就是），拿它当判据的边界。

对照本身可信度做过验证：把 `伤害.json` 的 `输出倍率` 从 300 改成 301，
语料侧检出 **1242/1264 差异**、战前状态侧检出 **170/170 差异**，退出码均为 1；
数据不改时两边都是 0 差异、退出码 0。

## 四、平衡：全局两个闸

### 症状与排除过的假设

100 级满构筑（功法6/真意6/气机6/器律4，40 套）跑 60 行动上限，**30/39 未分胜负**，
行动中位数直接撞在上限上。逐个量过四个假设，全否：

| 假设 | 量到的结果 |
| --- | --- |
| 行动上限太短 | 上限本身就够（`--上限` 抬到 120 只是把撞上限往后推） |
| 判定轴没开（命中/暴击/格挡） | 陪练默认 `闪避率/暴击率/格挡率` 都是 0，命中率实测 99.9%——不是这里 |
| 防御成长太快 | 空白组（无卡）23 行动就打完，防御不是主因 |
| 攻击成长太低 | 每级攻击 0.5→2.0（攻击翻近四倍），**单次伤害中位恒为 3.62**，均值 7.69→17.08 |

最后一行是关键：伤害事件的**中位数不读攻击**。p10 恒为 1.00 是 `最低伤害` 的地板，
中位 3.62 是「每层 1 点真实伤害」「0.35 倍追加」这一类固定小量。调攻击成长只动尾部，不动主体。

### 真因：输出与恢复恰好抵消

把一场仗按资源拆开（`对敌伤害` / `自伤` / `血气恢复` / `精神恢复`，且每方除以**自身**上限）后：

```
对敌伤害 / 血上限  : 中位 139%（双方合计）→ 单方约 70%
血气恢复 / 血上限  : 中位 134%
两者都是「1.1% 每行动·血池」——正好抵消。
```

所以既不是「打不疼」，也不是「太肉」，是**恢复把输出按比例抵消掉了**。
恢复里很大一部分是**伤害触发**的（反哺、承伤转愈、治疗型战域）：`恢复/血池` 随 `输出倍率`
一起涨（135.8% → 215.9%），这也是为什么单抬输出没用。

### 两个闸

对称的一对，都在 `data/战斗/规则/伤害.json`，都是百分比，100 = 不生效：

- **`输出倍率`**（`game/core/combat/damage.py`）——乘在 `raw` 上，同比例缩放整条流水线，
  所以卡的相对强弱不变。只放大**跨阵营**的伤害：自伤（血祭代价一类）是成本不是输出，
  跟着一起放大等于把成本也乘几倍，会让代价型卡整体失真。
- **`恢复倍率`**（`game/core/combat/mechanics.py`）——只闸**血气与护盾**。
  精神是出手预算，把它一起闸掉会让「治疗太强」表现成「技能放不出来」，那是另一个问题，
  而且会盖住真正的症状（实测：闸精神时 `单方伤害` 在输出 300 以上就饱和在 1400）。

### 审完：未决的 12 套里只有 构筑7 是真 bug

对 12 套未决逐套量了「对敌 / 自伤 / 恢复 / 命中判定 / 终局血」。构筑7 是硬锁
（已修，见「五」），其余都是**慢，不是坏**。两个看着可疑的查完是这样：

**构筑27（对敌 0 / 自伤 2486 / 恢复 0）不是 bug，是镜像局里「打自己」这一族的必然结果。**
把 `source == target` 的伤害按卡点名：`借祸` 54、`分厄` 54、`万劫回首` 54、
`万象归身` 21，还有**19 次普通攻击**。普通攻击也打自己，来自
`400506 地脉翻龙厚土经` 的 `修改行动意图 {字段: 目标, 范围: 敌方}`：
`范围: 敌方` 相对**监听者**解析（`enemies_of(source)`，`source` 是挂监听的人），
所以敌人行动时它选中的是「我的敌人」——**就是它自己**。镜像双方都这么干，
于是全场没有对敌伤害，只能靠互相自损慢慢分（终局血 0.03）。

我先前说「31 张 `字段=目标` 只是嘲讽引战、不构成问题」**只对了一半**：
`范围: 自身` 是引战，`范围: 敌方` 是让对方自伤，后者强得多。语义已写进
`战斗/规则/说明.md` 的「行动意图改写」一节。

**构筑0（自伤是对敌的 8.8 倍）** 是同一族的另一半：自伤主要来自 `无医战场` 这类
「造成伤害后触发自身伤害」的战场规则，属于设计内的代价。

| 普通攻击前 | `400503 五岳镇界镇岳诀`、`410128 万象回声` | 目标改为自身 + 自身恢复 12 护盾 + 计量 +2 |
| 行动决策前 | `400026 浮光掠影身法`、`410272 同袍改策` | 目标改为自身 + 计量 +4 |

四张统一改成**代付**：事件换成 `资源消耗前`、观察角色换成 `承受者`，两张
`修改行动意图` 的换成 `修改事件目标`，**护盾与计量一概不动**（不借机改数值）。
改完与既有的 4 张代付卡（`400334`、`400226`、`400474`、`410472`）读起来完全同形。

为什么是 `资源消耗前` + `修改事件目标{自身}`——`_ability_consume_resource` 里
`destination = frame.target` 是**在派发 `资源消耗前` 之后**才取的，而且
「够不够」与「扣谁」都用改写后的目标，所以把承受者改成自身就是「我付，
不够则队友那一手失败」。这正是代付语义。

**队伍战实测**（L1 带 `400503`、L2 带一门耗神功法、R 是靶子）：
出现 4 次 `资源消耗后`「来源 L2 → 承受者 L1」的精神消耗，
**L2 终局精神 694/694（一点没花）**，L1 终局 666/694 并替 L2 付了 4 次。
1v1 里整类仍不触发（没有「其他己方」），所以两条语料通道对照基准都是 0 差异
——这也是「只改了触发条件、没碰别处」的证明。

要注意跟它们区分开的是 **`转移伤害{自身}`（4 张：`400507`、`400462`、`410109`、`410198`）**：
那是「队友挨打时我把伤害接过来」，是真正的保护，属于设计。判据是**改的是目标还是伤害**。

顺带修掉一个由它揪出来的渲染错误：`修改行动意图` 原先渲染成
`〈目标〉的行动意图‹字段›改为〈值〉`，而 `目标` 字段是**意图被改成的新目标**，
不是意图的归属者。于是 `{字段: 取消}` 渲染成「自身的行动意图取消本次行动」——
而它取消的是**对手**的行动，**玩家读到的意思正好相反**（`400012 游龙贯日枪经`、
`410275 孤注误导` 都受影响）。现在主体统一为「该次行动」。`文本规范.md` 对应那行同步改掉。


### 撤回：精神不是下一道约束

我先前据 `tools/平衡扫描.py` 的 `精神余` 中位 0.00 判断「再抬输出会变成精神饿死」。
实测下来这个判断**站不住**：

- 全 40 套满构筑跑完，**终局精神余中位 1.00**，归零的只有 11/40。
- 精神收支**净额中位 0**，收入/上限中位 75%。

之所以看着像「刚好够用」，是因为**技能的精神消耗被立刻等额返还**：同一个行动里有
一条 `减少 −11.28（消耗）`，紧跟一条同额、同来源的 `增加 +11.28（恢复）`。
这批构筑带了「免费施法」的卡，所以消耗只是名义上的。

口径差异也要记一笔：`平衡扫描` 报的是**双方取最小**的精神余，`战斗统计` 报的是逐方；
前者会把「某一边干了」读成「这套构筑饿死」。判断预算紧不紧要看逐方分布。

**真正的设计事实**（不是 bug）：`血气恢复` 与 `精神恢复` 在 `属性.json` 里默认值都是 0，
`人物.json` 的属性覆盖与 `修士修炼.json` 的成长表也都没给值——所以
`行动.json -> 行动开始恢复` 这条机制**在任何角色的基准值上都是空转**。
供给全部来自**气机方向**：`血气恢复` 37 处、`精神恢复` 37 处（`回血`=8、`回神`=5、
`命中回血`=3、`命中回神`=2、`回血回神`=3/2…），另有 2 处状态在压恢复（`太乙气痕`、
`太阴气纹` 各 −20）。

也就是说**回复是气机的构筑选择**：一套不投回神的气机，整场精神预算就是精神上限
694 点，按每发 11–17 点算约够 45 发；而 60 个行动里每行动放一发需要 60 发，
所以会在后段开始缺水。这个量级本身是合理的张力，不需要现在动。

顺带记下**真正的施放失败原因**（40 套满构筑合计，同一套里双方都算）：
`行动限制` **173**、`被取消` **73**，**没有任何一条是缺精神**。
所以卡住出手的不是预算，是「技能被封」——44 处状态写了 `行动限制: ["技能"]`。
这个才是值得往下查的方向。

### 查清：技能封禁与阵法轮转都不是未决的原因

**技能封禁**。44 张卡用同一模板给**自己**挂一个 `XX气痕`（负面、`剩余行动: 1`、
`行动限制: ["技能"]`），40 张打 `自身`、4 张打 `当前目标`——这是「施法留痕、
短暂封自己技能」的代价机制，有时限、不是锁。40 套对局里 `行动限制` 触发 173 次，
看着像与未决相关（封得最多的 6 套里 4 套未决），但**那是反向因果**：
未决组 `行动中位 60`、`施放 38`，已决组 `行动 17`、`施放 13`——**打得久所以封得多**。
封印最多的 `构筑38`（38 次）是**已决**的（54 行动打完）。两组的封印中位都是 0。

**阵法轮转**。先前写「首轮在第 12 行动、短局轮不到」时我读错了数据路径
（`传导` 在 `品级[].节点.传导`，阶段倍率在 `品级[].地势阶段[]`，不在顶层），
于是错判成「46 个阵法完全相同」。按正确路径，四条品级的 `传导` 是
1.0 / 1.45 / 2.1 / 3.05，**首轮按品级递进：黄 12、玄 9、地 6、天 4 行动**，
首轮之后的间隔还由周期倍率（0.44–1.53）逐段改变。覆盖率：黄 82%、玄 85%、
地 88%、天 92%，没走到的都是「1 行动就结束」那种自我退场局。

顺带把写死在 `engine.py` 里的基准周期搬进了 `时序.json -> 阵法轮转.基准周期`
（值仍是 12，行为逐位不变），并给校验补了正整数检查（含 `bool` 是 `int` 子类那个坑）。


### 未决判据本身修过一次

按血气判会把这类**已结束**的战斗错记成未决。现在统一读引擎 `战斗结束` 事件的 `结果`

`tests/test_combat_entry_surfaces.py` 的阵法断言也踩过同一个坑的另一面：

## 五、`修改行动意图` 的取消写法：必须带每场上限

`行动决策前` 上做 `修改行动意图 {字段: 取消}` 会直接掐掉对手的一次行动。全库共 7 张卡这么做，其中 **6 张写法一致**：

```
效果: 修改行动意图{字段: 取消} + 清空自己的计量
条件: 自己的计量 ≥ 8        （数值条件门槛）
每场战斗最多触发: 1
优先级: 80
```

功法的 5 张（`400012 游龙贯日枪经`、`400024 百鸟朝凤枪谱`、`400131 白虹贯月枪经`、`400132 一苇渡虚录`、`400463 北冥玄水沧海诀`）与真意的 `410210 万法先机` 都是这个形状。

**唯一的例外是 `410275 孤注误导`**：它写的是 `每次行动最多触发: 1`、没有门槛、没有优先级。而在对决里**每个行动只有一次决策**，所以「每次行动最多触发 1」等于**每次都取消**——对手永远动不了。镜像双方都带它时，就是双方都动不了：构筑7 曾出现 60 个行动、零施放、零命中判定、零伤害，整场什么事都没发生。

已按其余 6 张的写法对齐：`每场战斗最多触发: 1` + `优先级: 80`，去掉 `每次行动最多触发`。它的计量是 `孤注返真 +9`、结算门槛也是 `9`，**触发一次就立刻结算**，所以「一场只触发一次」本来就是它的设计意图。注意这里**不能**再加 `计量 ≥ 9` 的门槛——那个计量只在取消成功时才增长，加门槛会变成死锁。

修完的效果（镜像口径、行动上限 60、seed 20260911）：构筑7 的 `行动跳过后` 从 **60 降到 2**，`技能施放后` 从 **0 涨到 58**。

**但它仍然未决**，而且其余 11 套未决构筑的 `跳过` 本来就是 0、从未受这个锁影响——所以这次修的是**一个硬锁**，不是未决比例。未决 12/40 没有变化。

### 写这类效果时的检查项

`行动决策前` + `阵营关系: 任意敌方` + `修改行动意图` 是一个**每行动都会触发**的位置。字段为 `取消` 时，`每次行动最多触发` 挡不住任何东西（每个行动只有一次决策），必须用 `每场战斗最多触发`。字段为 `目标` 时只是把对手的行动引到自己身上（嘲讽/引战），在决斗里往往本来就是自己，不构成锁。


## 六、机械化盘点与改造目标（1967 张构筑卡）

**起因**：卡面被认为"机械"。先量，再改——量的口径是「被谁重复」而不是「写了多少字」。

所以「把数值改花」和「把链改散」都是白费功——问题在**用词集中**，不在取值集中。

### 改造目标（可量化，改完拿同一张表复量）

1. `行动结束` 在**监听节点**里的占比从 48.7% 降下来，散到使用率个位数的事件上（先把 20 余种低用事件各抬到几十张）。**注意单位是节点，不是卡**——卡级只有 5.7% 是单触发，没有「整张卡都要改」这回事。

4. **标签要立起词表**：现在只有 `群体` 一种，等于没在用；立一套（单体/连击/回响/代价/守势…）

### 实测：`行动结束` 上的触发上限是装饰性的（第 6 轮）

**做法**：取 20 张无相功法卡，**只**把 `事件=行动结束` 的监听节点上的 `每次行动最多触发`
从 1 抬到 3（7 张样本里共 57 个节点），跑战斗判据。

**结果：1264 场一字未变，差异 0。** 改动已撤回。

**结论**：`行动结束` 每次行动只发生一次，上限 1 永远碰不到——那个上限是**非约束的、装饰性的**。
所以「`每次行动最多触发=1` 占 91.4%」这个读数里**有一大块是噪音，不是设计**。

**这对改造计划的影响**：原来把「限额形态」列成第一优先轴，现在要拆成两件事：

1. **清噪音**（零强度代价）：删掉那些不可能生效的声明。既让集中度读数说真话，也让**剩下那些
   真正会生效的上限**对读者有意义——现在满屏 `=1` 反而让人看不出哪里在限流。
2. **让上限真正起作用**（平衡改动）：只在**可多次触发**的事件上做（`受到伤害后` 224 个节点、
   `状态层数变化后` 90 个、`造成伤害后` 96 个…），因为这些事件一次行动里可能发生多次，上限
   在那里才真的限流。改这些必须先用 `战斗统计.py`/`平衡扫描.py` 量强度，再决定放不放。

**下一步要做的决定性测量**：拿同一批卡、只把 `受到伤害后` 节点的上限从 1 抬到 3。若这次
战斗判据**变了**，机制就确认了——可多次触发的事件上上限是活的，那里才是真正该多样化的地方；
若还是不变，说明上限在引擎里根本没被读，那就是另一类问题（该查引擎而不是查数据）。


### 确认：上限在「可多次触发」的事件上是活的（第 7 轮，与上一轮正反对照）

| 实验 | 事件性质 | 改动 | 1264 场判据 |
| --- | --- | --- | --- |
| 第 6 轮 | `行动结束`（每行动只发生一次） | 20 张卡 / 57 个节点，上限 1 → 3 | **差异 0** |
| 第 7 轮 | `受到伤害后`（每行动可能多次） | 9 张卡 / 14 个节点，上限 1 → 3 | **差异 5** |

第 7 轮变化的是 `功法:400018`、`400020`、`400077`、`400160`、`400261` —— **5 张 ⊆ 我改的 9 张**，
正好落在授权的卡集内。两次实验都已撤回。

**结论（机制已确认，不用再猜）**：

- **单次事件上的上限是死的**：`行动结束` 有 2332 个节点（占全部限额声明的**一半以上**），
  那上面的 `=1` 永远碰不到。**这一块是噪音**。
- **多次事件上的上限是活的**：`受到伤害后` 224 节点、`技能施放后` 154、`造成伤害后` 96、
  `状态层数变化后` 90、`添加状态后` 76、`恢复后` 60、`资源变化后` 59、`移除状态后` 58……
  这些事件一次行动里可能发生多次，上限在那里真的限流。

### 因此「限额形态」这一轴的正式做法

1. **清噪音（零强度代价，可批量做）**：删掉单次事件上不可能生效的上限声明。做完之后
   `每次行动最多触发=1` 的 91.4% 会掉到一个**真实**的水平，而且剩下每一条都在真的限流——
   读者一眼能看出哪里在限流，这正是「机械化读数」该有的样子。
2. **多样化真上限（平衡改动，必须量）**：只在多次事件上动，且每批先用
   `战斗统计.py --满构筑 --等级 100` 量强度、必要时用 `平衡扫描.py` 扫，再决定放不放。
   第 7 轮已经证明这类改动**会**改变战斗结果（5/1264），所以不能当形状改。

### 实测：原来的「五行 → 时点」映射是个增益，不能按原样铺开（第 12 轮）

试点：`功法-体术.json` 的 20 张无相卡、59 个监听节点，`行动结束 → 行动开始`。
机制验收通过（语料差异 20 张，**恰好等于授权集，一张不多**），但强度测量否决了它：

| 指标 | 前 | 后 | 漂移 |
| --- | --- | --- | --- |
| 打到行动上限仍未分胜负 | 12 / 40 | **13 / 40** | 多一场打不完 |
| 每场行动数 中位 | 25.50 | **35.00** | **+37%** |
| 单次造成伤害 中位 | 9.05 | **7.24** | −20% |
| 每场技能施放次数 中位 | 22 | **27** | +23% |
| 总伤害 / 双方血上限之和 中位 | 1.03 | 1.08 | +5% |
| 终局精神余量占上限比 中位 | 1.00 | 1.00 | 0 |

**20 张卡就把战斗拖长 37%、并多出一场打不完。** 原因是清楚的：`行动开始` 比 `行动结束` 更早，
效果提前上线就是增强；而「打不完」本就是已知痛点，这个方向是往坏里推。试点已撤回。

**结论：这一轴必须按「强度中性」重新设计，不能只改时点。** 三条可行路子（都要量）：

1. **配对更晚或更稀的时点**：`行动结束 → 行动决策后`（同频但更晚，效果延后＝略减）、
   或换成条件性时点（`受到伤害后` 这类不一定每次都发生）——用**发生频率**抵掉提前的收益。
2. **改时点同时改数值**：提前上线就下调量，晚点或条件化就上调量——按量出来的漂移定价。
3. **只在已经偏弱的卡上做**：先用 `战斗统计` 找出偏弱的构筑，把时点提前当补偿；强的卡往后挪。

**这一轮真正的收获是流程本身**：上一轮我因为强度没量完而撤回试点；这一轮量出来发现
「幸好撤了」——**机制改动的强度门槛不是形式，它真的会拦下错误的轴**。


### 门槛调整：强度不再是否决票（第 13 轮，按负责人口径）

上一轮因为强度漂移（行动中位 +37%、多一场打不完）把试点撤回了。负责人明确：
**强度没必要卡得那么死**——这一轮的目标是去机械化、增加多样化，**平衡可以让路，事后再调**。

所以规矩改成：

- **仍然照量照报**（`战斗统计.py` 每批前后各跑一次，漂移写进批次记录），但**不用它否决批次**；
- 漂移攒到需要收的时候，用全局两个闸（`输出倍率` / `恢复倍率`）或 `平衡扫描.py` 统一找补，
  比逐卡定价省事得多；
- **仍然不许零差异假象**：机制改动的验收依旧是「战斗侧差异 ⊆ 授权卡集」——这条是判断
  「改的是不是该改的地方」，与强度无关，不放宽。

首批落地：`功法-体术.json` 20 张无相卡、59 个节点，`行动结束 → 行动开始`。
本批漂移（已量，接受）：未分胜负 12/40 → 13/40；每场行动数中位 25.50 → 35.00；
单次伤害中位 9.05 → 7.24；技能施放次数中位 22 → 27。


### 第三条轴（效果动词）的取证：原先的表述不成立（第 20 轮）

原表述是「把 `修改构筑计量` 的 56% 额度分给机制性动词」。取证否掉了它：

| 读数 | 值 |
| --- | --- |
| `修改构筑计量` 节点 | 11160 次 |
| 其中打在**共享属性**（攻防速等，取自 `data/战斗/定义/属性.json` 的 20 个名字）上 | **0 次** |
| 打在**卡内私有计数器**上 | **11160 次** |
| 用到私有计数器的卡 | 1185 张 |
| 「写进去但本卡从不读」的卡 | **0 张** |

**结论：这个 56% 不是「偷懒用同一个动词」，而是同一个缩放惯用法**——每张卡把自己的计量写进去，
后面再读出来当缩放系数。所以**不能把它替换成 `转移状态` 之类**：那会打断卡自己的逻辑
（它后面要读那个数）。原表述把「惯用法统一」误当成了「词汇贫乏」。

**重新表述：这一轴真正能做的是「换缩放来源」**，而不是换动词。可用的缩放来源至少有：

1. **卡内计数器**（现状，1185 张全用它）；
2. **状态层数**（`添加状态` + `增加状态层数`，读层数缩放——现在 387 + 85 次）；
3. **已损失血气 / 当前血气比**（`读取数值` 换来源属性即可，纯数据改动）；
4. **行动数 / 轮次**；
5. **对方的属性**（现在多为读自身属性）；
6. **事件数值**（本次伤害多少，`事件数值` 是现成来源）。

其中 **3 与 5 是纯数据改动**（只换 `读取数值` 的 `来源`），可以像前两轴一样批量做、可精确验收；
1 → 2 需要改卡的结构（写计数器的节点换成加状态层数，读取处换成读层数），属于逐卡重写。

**优先级建议**：先做 3 / 5（安全、可批量、能立刻把「来源」这一维散开），再做 1 → 2。
要有一个「缩放来源」分布读数才能量这条轴的进展——现有 `机械化盘点.py` 只管事件、动词、限额，
需要加第四个口径。


### 第三条轴的判据盲区：镜像语料看不见「自身 ↔ 目标」的来源切换（第 22 轮）

试批：`功法-体术.json` 的 8 张卡、14 处 `读取数值`，把 `来源: 自身属性`（`精神上限` / `护盾上限`）
改成 `来源: 目标属性`。这是**形状合法**的纯数据改动（`目标属性` 与 `自身属性` 字段形状相同，
现网已有 4 处在用），两种形状审查与词条作用域审查都过。

结果：

| 读数 | 变化 |
| --- | --- |
| 语料 1264 场 | **差异 0** |
| 强度（未决 / 行动中位） | 11/37 · 39.00 —— 双双未变 |
| 棘轮·缩放来源熵 | 0.951 → 0.964（数据确实变了） |

**原因：语料是镜像局**（同一张卡两边都装），所以「读自己的精神上限」与「读对方的精神上限」
**数值完全相同**——这条改动在现有判据里天然不可见。它对镜像局无影响，**但对真实对局
（双方构筑不同）有没有影响，无法用现有手段证明**。

**所以撤回，并记下这个盲区**：第三条轴若要走「自身 ↔ 目标」这一类切换，**先得有一条非镜像的
判据**（例如双方装不同卡的对局语料），否则等于在测不到的地方改 1185 张卡。
这与此前「战报没有判据」「查看页没有判据」是同一类问题——**判据的覆盖面决定了能安全改什么**。


### 纠正第 22 轮的归因：那不是判据盲区，是改动本身中性（第 24 轮）

第 22 轮把「换来源试批在语料里差异 0」归因为「镜像语料是盲区」，并据此建了交叉对局判据。
第 24 轮带可见输出重跑同一次试批，把两件事分清了：

| 检查 | 结果 |
| --- | --- |
| 数据是否真的改了 | **改了**（`目标属性` 0 → 14 处，git diff 14 行） |
| 镜像语料 | 差异 0 |
| 交叉对局（双侧卡与属性都不同） | **差异 0** |

**所以那次「看不见」的原因是这次改动本身行为中性**，不是判据盲区。可能的机制：那 14 处读的是
资源上限，读数被 `最高值` 夹住；或者那些效果在这三名对手面前根本没触发。**第 22 轮的归因是错的**，
已在文档里以本节更正。

**对第三条轴的直接结论**：`换缩放来源` 要挑**真正会生效的读数**——判据是读数节点里**没有 `最高值`**
（不被夹住）、且所在效果确实参与结算。资源上限那一类先排除。候选筛选口径：

1. `读取数值` 且**不含** `最高值`；
2. 其值流向 `造成伤害` / `恢复资源` 的量（而不是只写进计数器再被夹）。

**交叉对局判据本身仍然成立且已入库**（3792 场、自比 0），但「它能看见而镜像看不见」这件事**尚未被
任何改动证实**——第一个候选恰好是两边都中性的。要证明它的独有价值，得等一个只在双侧不同时显形的改动。

**方法论教训**：决定性验证的实验步骤不能把输出丢掉——第 23 轮我把试批输出丢进 `> $null`，
于是「没施加」与「施加了但中性」两种情况无法分辨，白跑一轮。


### 交叉判据的阳性对照成立，但「换来源」不能无差别做（第 25 轮）

按第 24 轮收紧的口径选真候选：`功法-剑诀.json` 里 **48 处** `读取数值`（`来源: 自身属性`、
不含 `最高值`），涉及 **18 张卡**，整批换成 `目标属性`。

| 检查 | 结果 |
| --- | --- |
| 镜像语料 1264 场 | **差异 0** |
| 交叉对局 3792 场 | **差异 22 条，涉及左方卡片 8 张 ⊆ 授权 18 张**，新增/缺失 0 |
| 棘轮·缩放来源 | 最大项 63.2%（未升）· 熵 0.951 → **0.986**（未降） |
| 强度（8 张卡 × 3 对手 × 24 种子 = 576 局） | 胜率 0.7309 → **0.4896（−24.1pt）** |

**两件事同时被证实：**

1. **交叉对局判据的独有价值成立。** 同一个改动，镜像判据报 0、交叉判据报 22 条——这是它的
   第一个阳性对照。第 22 轮说它「补盲区」当时只是推测，现在有据：盲区的成因是**双方属性相同**
   （镜像局两侧都读同一套 `ATTRS`），不只是卡片相同。第 24 轮的试批之所以两边都 0，
   是因为那批恰好行为中性，不是因为判据没用。
2. **「换缩放来源」是纯数据改动，但强度代价可以极大。** 48 处节点、18 张卡就换掉 **24 个百分点**的
   胜率。第 13 轮定的「强度不否决批次」不等于「不看方向」——**−24pt 不是漂移，是把卡的归属改错了**。

**回滚，并记下这个轴的正式口径。** 把剑诀这 48 处按**读的是哪个属性**分组，只有三类：

| 属性 | 次数 | 卡 | 性质 |
| --- | --- | --- | --- |
| `攻击` | 19 | 8 | **输出侧自身属性**——换成读目标 = 自废武功 |
| `精神上限` | 18 | 13 | 资源上限，用作缩放基准时两种归属都讲得通 |
| `血气上限` | 11 | 8 | 同上 |

**没有一处是目标侧属性**。所以无差别换来源，实际效果就是「用自己的攻击算伤害」变成「用敌人的
攻击算伤害」。轴的正式做法改成**带语义筛选**：

- 只换**目标侧可读属性**（`防御` / `速度` / `闪避率` / `格挡率` / `抗暴率` 之类）——那才是
  「越硬的目标越吃亏」这类针对性设计，语义成立且是真实多样化；
- `攻击` / `伤害加成` / `暴击率` 这类**输出侧自身属性**一律不动；
- 剑诀里合格候选 **0 处**，所以这一轴要去有这类读数的文件上找，不能按文件批量推。

**本轮工具改进**（都已入库）：

- `tools/交叉对局对照.py` 增 `--差异名单 <file>`：落盘完整差异，并顺带列出「差异卡」去重集，
  大批次一眼核「差异 ⊆ 授权集」；
- 新增 `tools/强度对照.py`：给一批卡各对三名固定对手各打 N 局，报胜/负/平与平均行动数，
  带 `--基准` 报增量。`交叉对局对照` 判**相等**（一个哈希），它回答「变了没有」；这个工具回答
  「变强还是变弱」。每批改写都过一遍它——本轮的 −24pt 就是它量出来的。


### 第三条轴落到「读上限」这个真实集中点上，首批 50 处（第 26 轮）

第 25 轮的教训是「不能按文件无差别换来源」。这一轮先把**全库 `读取数值` 的分布**量出来，
才发现集中点根本不在「自身/目标」，而在**读什么**：

| 来源 | 次数 | 占比 | 卡数 | 被 `最高值` 夹住 |
| --- | --- | --- | --- | --- |
| 构筑计量 | 3757 | 63.2% | 1185 | 3757 |
| 自身属性 | 1810 | 30.5% | 933 | 0 |
| 本次数值 | 134 | 2.3% | 115 | 0 |
| 状态层数 | 62 | 1.0% | 53 | 0 |
| 事件事实 | 55 | 0.9% | 47 | 0 |
| 战斗记录 | 31 | 0.5% | 30 | 0 |
| 自身当前血气 | 25 | 0.4% | 21 | 0 |
| 目标当前血气 | 22 | 0.4% | 16 | 0 |
| 自身已损失血气 | 12 | 0.2% | 12 | 0 |
| 其余（保存结果 / 当前·已损失精神 / 目标属性 / 目标已损失血气） | 45 | 0.8% | — | 0 |

**两个决定性读数：**

1. `自身属性` 1810 次里，**读 `上限` 的有 1441 次（79.6%）**——`精神上限` 799、`血气上限` 541、
   `护盾上限` 101，读 `攻击` 只有 369 次。也就是说「自身属性」这个来源看着像多样化，
   实际上是**第二种缩放惯用法：拿自己的资源上限当系数**。
2. `行动条` / `技能冷却` / `效果来源属性` **三个引擎来源全库 0 次使用**——引擎支持、词表空着。

**机械模板长什么样**（`真意-献祭` / `真意-绝境` 里成片重复）：

```
恢复资源 血气 = 读取数值(自身属性: 血气上限) × 24%      ← 连号卡全是同一个式子
```

**首批改法（50 处 / 49 张，`真意-绝境` `真意-献祭` `真意-返照`）**：按**恢复对象**决定语义，
百分比不动：

- 恢复给**自身** → 读 `自身已损失{血气|精神}`：越残回得越多（起死回生），满血时回 0；
- 恢复给**己方（按血气比例排序）** → 读 `目标已损失{血气|精神}`：谁缺得多补谁（救急）。

同一百分比下 `已损失 ≤ 上限`，所以是**前期略弱、后期略强**的形状变化，不是单纯加号。

| 检查 | 结果 |

### 判据覆盖面：气机 703 张此前不在任何战斗判据里（第 29 轮）

准备开「限额·真上限」这条新轴时，先核了一遍判据覆盖面，撞见一个更大的问题：

| 通道 | 改前的覆盖 |
| --- | --- |
| 语料对照 | 1264 场 = 功法 600 + 真意 600 + 器律 64 |
| 战报对照 | 同上 1264 份 |
| 交叉对局对照 | 3792 = 1264 × 3 |
| 渲染正文 / 查看页 / 装配规划 / 机械化盘点 / audit | **含气机** ✔ |
| **战斗类判据** | **气机 703 张一张都没有** |

**先确认这不是类型限制**：拿 `气机-命闪.json` 的第一张卡当构筑卡跑一场——**打得动**
（7 次行动、99 条事件、有胜负）。所以气机卡是可战斗的，只是三条战斗通道的 `SURFACES`
从建立时就没写它。

**为什么它一直被忽略**：`检查构筑形状.py` 里写着气机是四个方向之一 ——
「气机 42 → **只有固定属性加成，不引用事件、不监听、不生成技能**」。也就是说气机是**纯属性块**，
所以建通道时按「谁有事件监听」挑卡，就把它整类漏掉了。但纯属性块**照样影响战斗结果**：
它加的攻击/防御/速度会进结算，改错了战斗层必须能看出来。

**改法**：给 `语料对照` / `战报对照` / `交叉对局对照` 三条通道的 `SURFACES` 补上气机，
重取基准。验收口径是「**旧条目一字不变，新条目单列**」：

| 通道 | 结果 |
| --- | --- |
| 语料对照 | **一致 1264 · 差异 0 · 新增 703** |
| 战报对照 | **一致 1264 · 差异 0 · 新增 703** |
| 交叉对局对照 | **差异 0 · 新增 2109**（703 × 3 名对手） |

旧条目全部 bit 级一致，说明这次只是**加覆盖**、没有碰行为；新增的 703 / 2109 条就是气机的
战斗判据。三条通道的耗时从 25 秒 / 115 秒 / 60 秒涨到约 40 秒 / 180 秒 / 95 秒，可以接受。

**这条值得单独记的原因**：改内容之前，先问「我要改的这些东西，**有没有判据看得见**」。
此前有过同类教训（战报没判据、查看页没判据，都是后来补的），这是第三次——
**漏掉的不是某张卡，是一整个类别（36% 的语料）**。判断覆盖面的办法很简单：
把四类构筑卡的数量与各通道的条目数对一下，对不上就是漏了。


### 限额轴的第一步：把「哪个事件一次行动会发生几次」从手工业改成实测（第 29 轮）

限额这一轴的关键事实是「上限在哪类事件上真的会碰到」。此前这条是**手工分类**的：
第 6 轮判 `行动结束` 一次行动只发生一次（所以上限是装饰性的），第 7 轮判 `受到伤害后` 会多次
（所以上限是活的）。这次改成实测：`BattleEvent.turn` 就是上下文行动序号，按
`(场次, 行动序号, 事件名)` 数一遍 1967 场镜像战，就得到每种事件的真实频次。

`tools/事件频次.py` 的结论表（节选，按行动内最大次数排）：

| 事件 | 行动内最大 | 平均 | ≥2 的行动占比 |
| --- | --- | --- | --- |
| 移除状态后 | 96 | 1.22 | **14.0%** |
| 添加状态前 / 后 | 90 | 1.46 | **24.5%** |
| 命中判定前 / 命中后 / 造成伤害前 / 后 / 受到伤害后 | 54 | 1.23 | **13.4%** |
| 战场规则变化后 | 32 | 1.36 | 13.6% |
| **技能冷却变化后** | 29 | 2.20 | **76.9%** |
| 资源变化后 | 28 | 1.60 | 30.2% |
| 获得护盾前 / 后 | 28 | ~2.05 | ~22.7% |
| 资源恢复前 / 后 | 23 | 1.84 | ~23.0% |
| 行动条变化后 | 14 | 1.22 | 16.6% |

**能一次行动发生多次的事件 39 种，至多一次的 13 种。** 三条结论：

1. **第 6 轮的手工判断被实测证实**：`行动开始`/`行动结束`/`行动决策前`/`后` 的行动内最大
   次数**恰好是 1**、0.0% 的行动超过一次 —— 写在这些事件上的 `每次行动最多触发=1`
   是**装饰性的**，全库这一块是噪音。
2. **第 12 轮那次「行动结束 → 行动开始」的副作用也被解释了**：两者频次完全一样（都是 1），
   所以当时的漂移（战斗拖长 37%）不是频次造成的，是**时点早晚**造成的——效果提前上线。
3. **但「活的」面比手工分类窄得多**：`技能施放后` 只有 **1.4%** 的行动会发生多次，
   `状态层数变化后` 1.2%、`暴击后` 0.2%。真正高频的是
   `技能冷却变化后` 76.9%、`资源变化后` 30.2%、`添加状态前/后` 24.5%、
   `资源恢复前/后` ~23%、`获得护盾前/后` ~22.7%、`行动条变化后` 16.6%、
   `移除状态后` 14.0%、`受到伤害后`/`命中后`/`造成伤害后` 13.4%。
   **限额轴要动就动这几类**，动 `技能施放后` 那种近似装饰的，等于白改。

**方法论教训（工具自己的 bug）**：第一版把 `(行动序号, 事件)` 的计数**跨战斗累加**了，
于是打出「一次行动内最大 1792 次」这种荒唐数。**一眼假就该停下来查，而不是照着它去改数据**。
改成「每场各数、再取最大」才对。这类错误只有自己看数字能否成立才能拦住。

### 负责人口径（第 30 轮追加，后续所有批次按这个判）

1. **机制要平均**：每个机制维度的分布往「平均」推，**最大项占比要降**——不只是「不升」。
   棘轮原有的「不许更集中」是底线，现在的目标是主动摊平。
2. **差异化与特色要体现**：同族卡不许共用一个模子；每张卡的行为签名要能看出来。
3. **没有的机制优先用上**：先在空位里找，而不是在已有的少数几种里换花样。
4. **强度不设限**：卡牌式组合玩法，1+1>2 与强力单卡都正常。**强度只量、只报**，
   不再作为补偿性调整（地板/找补）的理由。

**为了让第 1、3 条每轮可见，`机械化盘点.py` 的读数里加了「空位」段**（只报事实，不自动判好坏）：

```
  空位：未启用的读取来源 4 种（固定值 效果来源属性 行动条 技能冷却）
  读取数值 字段用量：百分比 2944 · 最低值 9 · 最高值 3757 · 固定值 0
  技能标签（主动技能）：1 种 · 群体 120
  其它标签（战斗关联/事件标签/条件…）：363 个 · 151 种
```

**这一加立刻纠正了一个我先前的错判**：之前记过「技能标签只有 `群体` 一种，等于没在用」——
但把**所有**带 `标签` 列表的节点混在一起数，会得到「113 种、很丰富」的相反结论。
分开数才看得清：

- `主动技能` 的标签（真正的**技能标签词表**）：**120 个、只有 1 种**（`群体`）——这个空位是真的；
- `修改战斗关联`（38 种）· `修改事件标签`（12 种）· `造成伤害`（10 种）· `标签条件`（5 种）·
  `选择状态`（3 种）：另有一套、用得不薄。

**教训**：同一个字段名挂在不同节点上就是不同的机制，**混在一起统计等于把两个问题平均成一个假象**。
量表必须按「挂载节点 + 值」的组合来数。

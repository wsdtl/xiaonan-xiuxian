# 战场环境 JSON

> 本说明只写现行规则与边界；历史变更见 git 历史，待补事项与缺功能见 [待补内容.md](../待补内容.md)。

本目录严格使用“一地势一文件”：`溪谷.json` 只能定义溪谷，`雷谷.json` 只能定义雷谷。不再把多个地势合并进“林野”、“水泽”、“山岳”等大类文件。每个环境以 `61` 前缀六位编号作为稳定身份。

```text
世界/内容/**/地点.json.地形
  -> 战场环境.名称
  -> 战斗/规则/环境.json
  -> 世界与玩法服务形成战场环境规格
  -> 战斗核心执行阶段
```

## 单项结构

- `编号`：存档、请求和战报使用的稳定引用。
- `名称`：必须与地点 `地形` 完全一致；无相境除外。
- `阶段`：按 `起始承伤比例` 严格递增。第一阶必须从 `0` 开始。
- `入阶能力`：跨入该阶时按顺序执行一次。
- `常驻能力`：只能使用 `监听事件`，阶段变化后替换旧阶监听。
- 每个地势在生成器中显式登记三段收束路线，不从地理大类继承通用压力模板。

## 设计约束

- 环境是中立来源，不存在 `自身`、`己方`、`敌方`、`主人` 等阵营目标。
- 环境不读取自身属性，只能读取事件事实或实际目标属性。
- 中后阶用禁疗、抑盾、判定改写、冷却失衡、行动条与暴露状态收束战斗。
- 伤害必须是地理事件的后果，例如破盾回流、暴击震岩、闪避扰林、施法引火或落雷；不写通用全场增伤。
- `无相境.json` 只有一阶，且两类能力都必须为空。

当前 55 份战场环境 JSON 直接维护，`tools/` 下已经不存在生成器脚本（历史生成器已随工具清理移除）。调整阶段名、阈值或能力时直接修改本目录 JSON，并同步 `data/战斗/定义` 与 `data/战斗/规则/环境.json`；新增环境必须匹配 `data/战斗/组件.json` 中 `战场环境` 的读取规则。

# 战斗机制 JSON 关系说明

本目录保存可复用的无名执行节点。机制位于原子能力和构筑之间：它只组合程序动作，不拥有玩家词条、能力名称或说明文本。

## 实体结构

每个文件是机制池数组，每个机制只有两个根字段：

```json
{
  "编号": "600001",
  "节点": {
    "能力": "造成伤害"
  }
}
```

| 字段 | 作用 |
| --- | --- |
| `编号` | `60` 前缀稳定身份，供功法、真意和规则引用 |
| `节点` | 符合原子能力 Schema 的可执行能力树 |

当前共有 82 个文件、1681 个机制。文件名只用于维护分类，编号是具体机制身份。

## 上游定义

机制节点只能使用：

- `战斗/定义/原子能力.json` 登记的能力名和字段；
- `战斗/定义/属性.json` 登记的属性名；
- `战斗/定义/资源.json` 登记的资源名；
- `战斗/定义/事件.json` 登记的事件名；
- 其他真实存在的机制编号。

机制可以通过 `引用战斗机制` 或 `引用被动机制` 嵌套复用，但必须受能力链深度和循环引用校验约束。

## 下游消费者

```text
功法.能力[].效果[].机制 ----------> 机制编号
真意.能力[].效果[].机制 ----------> 机制编号
战斗/规则/构筑/相冲.json[].机制 ------> 机制编号
BattleEngine ----------------------> 展开节点并执行
战报 ------------------------------> 使用构筑能力名或构筑专属词条名解释来源
```

功法、真意、气机和器律都可组合执行节点。装配时，战斗核心把槽位绑定到当前构筑实例的词条表；机制编号不会进入玩家战报。

## 文件分类的意义

文件分类用于维护和以后配置候选池，不改变节点语义。同一个编号无论被哪个构筑引用，节点都完全相同。能力名和词条名必须定义在构筑中，不能复制节点只为换名。

## 修改检查

1. 新机制编号必须唯一且符合 `60` 前缀。
2. `节点` 必须通过原子能力递归 Schema 校验。
3. 引用其他机制时检查引用存在、没有环并且深度可控。
4. 修改已有节点会影响所有引用它的功法、真意和构筑相冲关系。
5. 删除机制前必须全库搜索六位编号；公共机制没有可供搜索的名称。

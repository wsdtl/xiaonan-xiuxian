# 战斗文本规范

`说明` 是玩家读到的**唯一**规则正文：查看页把构筑的 `说明` 逐行原样展示，不做二次渲染。
所以文本必须像游戏王 OCG 的「效果文字框架」（Problem-Solving Card Text）一样，
用**固定的句式与标点**把时机、因果、次数、代价编码进去——玩家不需要查引擎，读文本就能推出结算。

规范只描述引擎**已经能表达**的东西。凡是引擎没有的语义，一律不许写进文本。

## 一、一条处理只回答三个问题

| 段 | 回答 | 引擎来源 | 游戏王对应 |
| --- | --- | --- | --- |
| 条件 | 什么时候能用、能用几次 | `监听事件.事件 / 观察角色 / 阵营关系 / 条件 / 每次行动最多触发 / 每场战斗最多触发` | 绿字（发动条件） |
| 发动 | 发动当刻付出什么、取哪些目标 | `主动技能.精神消耗 / 冷却行动 / 额外代价 / 使用次数 / 共享冷却` | 红字（代价与取对象） |
| 处理 | 结算时依次发生什么 | `主动技能.效果`、`监听事件.效果` | 蓝字（效果处理） |

**标点承载语义**：

- `：` 分隔条件段与处理段。没有 `：` 就是无条件段。
- `；` 分隔发动段与处理段，也分隔同一段里的前后步骤。
- `。` 结束一条处理。
- `[]` 引用代码里的名字：`[九转接燃]` 是技能，`[九转裂锋]` 是计量，`[不灭灵兆]` 是状态。
- `（）` 放数值与限定，不承载时序。
- `、` 只并列同类项，不表示先后。

三段式骨架：

```text
①[技能名]　主动 · 耗神12 · 冷却5行动
条件：……
发动：支付精神12；选择当前目标。
处理：……；然后……
```

条件或发动为空时整段省略，不留空标题。

## 二、连接词就是因果

游戏王用 `然后 / 此外 / 若能则 / 并且` 区分时机与因果。本引擎有对应的原语，必须一一对上：

| 连接词 | 引擎原语 | 时机 | 因果 |
| --- | --- | --- | --- |
| `然后` | 效果数组的下一项、`顺序执行` | 先后 | 前项做不到就停在这里；后项做不到不影响前项 |
| `若能则` | `尝试执行`（`成功效果` / `失败效果`） | 同时 | 前项成功才做后项；前项失败走失败分支 |
| `若…则` | `条件执行`（`成立效果` / `不成立效果`） | 同时 | 条件不成立走不成立分支 |
| `一并` | `事务执行` | 同时 | 全部成立才生效，否则整段回滚 |
| `随机` | `随机执行`（`抽取数量` / `是否放回`） | 同时 | 各项等价，抽中才生效 |
| `至多` | `重复执行.失败时停止` | 先后 | 失败即停，不补做 |
| `无效` | `取消事件` | — | 本次事件不再结算 |
| `此外` | 同一处理段里互不依赖的两件事 | 同时 | 一件做不到，另一件照做 |

反例：把 `顺序执行` 写成 `此外` 会让玩家以为两件事同时发生；把 `事务执行` 写成 `然后`
会让玩家以为可以只做前半段——引擎会整体回滚。

## 三、时机必须写全观察者

`监听事件` 有两个必填的视角字段，缺一个文本就不成立：

- `观察角色`：`来源 / 承受者 / 行动者`——盯的是事件里的哪一方。
- `阵营关系`：`自身 / 其他己方 / 任意己方 / 任意敌方 / 任意`——那一方和自己什么关系。

所以**禁止**只写「受到伤害后」。要写成「任意敌方造成伤害后」「其他己方施放技能后」。

- `XX前` → `当……前`
- `XX后` → `每当……后`
- `条件` 非空 → 条件段里补 `若……`

引擎按事件队列结算，没有游戏王「时 / 的场合」那套「是否最后发生」的时序差，
所以**不要**区分「时」与「的场合」；统一用「每当……后」。

## 四、代价、目标与失败

- 代价写进发动段：`支付精神12`、`冷却5行动`，或 `额外代价` 的原文。
- 目标是**结算时**按节点取值（本引擎没有连锁，也没有发动时取对象），统一用 `选择`，
  不采用游戏王的「选择 / 选」二分。
- `不足时是否失败=true` 写 `（不足则本次不结算）`；`false` 写 `（不足则按实际值结算）`。
- `主动技能.失败时回滚=true` 写 `（任一环节不成立则整段回滚）`。
- `重复执行.失败时停止=true` 写 `至多重复N次`。

## 五、正文写玩家要用的，明细写引擎才关心的

游戏王的卡面**没有分段标签**，全靠标点和固定句式承载结构。本作故意多一行 `条件：/发动：/处理：/明细：`——
功法一张卡最多六门技能，光靠标点读不出层次。标签是刻意偏离游戏王的地方，其余照抄。

**正文（`条件：` `发动：` `处理：`）只写影响决策的东西**：

| 写进正文 | 例 |
| --- | --- |
| 代价 | `耗神12 · 冷却5行动`、`支付血气上限×45%点血气` |
| 目标与范围 | `对敌方全体`、`一名己方（血气比例最低）` |
| 数值与倍率 | `自身攻击×58%`、`[九转裂锋]×30%` |
| 持续与层数 | `（持续2次行动、最多6层）` |
| 判定限制 | `（可暴击、可格挡）`、`（不可闪避）` |
| 免代价 | `（不消耗精神、无视冷却）` |
| 失败行为 | `（不足则本次不结算）`、`至多重复3次` |

**明细行只写引擎级、不影响当场决策的东西**，顺序固定：次数限制 → 结构细节 → 计量上限 → 优先级。

| 写进明细 | 例 |
| --- | --- |
| 次数限制 | `每行动只能使用1次`、`每场战斗只能使用1次` |
| 结构细节 | `标签：群体`、`共享冷却`、`任一环节不成立则整段回滚`、`来源退场时移除` |
| 计量上限 | `[九转归元]上限100` |
| 优先级 | `优先级60` |

次数限制照抄游戏王的句式：`每行动只能使用1次`，不写「最多触发1次」——「只能」才是限制，「最多」读起来像余量。
计量上限只在**结算段**出现一次，不在每一次 `[计量]+N` 后面重复；上限是引擎夹取，玩家不需要每次都被提醒。

### 渲染器只转写，不美化

`条件执行` 套一层同条件的判定是**真冗余**，已经清掉了（`tools/一次性迁移/清理冗余判定.py`）。
现在只剩一类看着像缺陷、其实不是的写法：

| 形态 | 例 | 为什么不能改 |
| --- | --- | --- |
| 成败分支同内容 | `……；然后无论成败，[太白回元]清零` | 引擎执行效果数组是**短路返回**，把清零并进同一个效果数组，尝试失败时清零就会被跳过，计量留着下回合再触发一次。`尝试执行` 的两条分支是引擎里唯一能表达「无论成败都做某事」的写法 |

渲染器把这种写法收成一句「然后无论成败，…」，不让玩家读到两个一模一样的句子。改这个属于改引擎语义，不属于改文本。

## 六、四类方向各有各的语气

四条设计方向不是同一套词换个前缀，文本也一样：

| 方向 | 标题 | 计量段叫法 | 语气 |
| --- | --- | --- | --- |
| 功法 | 法门 | 裁定 | 法门运转、周天搬运 |
| 真意 | 真意 | 印证 | 只有一条被动，直述 |
| 气机 | 契合 | —— | 只写固定属性加成，不谈过程 |
| 器律 | 器纹 | 器纹裁定 | 器物承载、锋芒所向 |

`说明` 里只保存**卡头一行**（风味简介 + 五行），规则正文由
战斗文本渲染器从能力树现算，`查看` 现拼现显示。卡头那行允许自由
发挥；从 `主动` 开始的正文必须能由 JSON 逐字推出，因此**不许写回数据**——
`tools/audit_combat_descriptions.py` 会在 `说明` 里发现 `主动：` 之类的小节标题时报错。

正文的固定结构是：**规则 → 主动 → 被动 → 裁定**（气机没有前三段，只有 `常驻`；没有规则文本的卡不出现「规则：」段）。

## 七、本引擎不采用游戏王的部分

- **没有连锁**：不写「发动无效」「效果无效」的连锁区分，`取消事件` 统一写「无效本次事件」。
- **没有连锁时点**：不区分「时」与「的场合」。
- **没有攻守表示**：`能否闪避` / `能否暴击` / `能否格挡` 直接写在伤害句尾。
- **没有主阶段**：行动条与冷却直接写数值，不写「回合」。

**采用「效果外文本」**：效果之外的常驻规则单独成段，写在正文最前（`规则文本`）。
它不是效果——引擎在结算之前读它做合法性判定，所以「效果无效」这一类改写碰不到它。
规则句由 `战斗/定义/规则层.json` 的 `卡面` 文案渲染，卡面**不许手写规则句**；
行级的规则（例如主动技能上的 `不可禁用`）并进该行的句子，同样取自登记表。

## 八、原子能力措辞表

每个原子能力在文本里的标准说法。这张表同时是渲染器的措辞来源。

### 装配

| 原子能力 | 标准说法 |
| --- | --- |
| `规则文本` | 段首 `规则：`，逐条 `•` 印登记表里的卡面文案（参数填进占位符） |
| `主动技能` | 标题行：`①[名称]　主动 · 耗神N · 冷却N行动`；行上带锁定规则时并进标题句 |
| `被动技能` | 标题行：`①[名称]　被动` |
| `固定属性加成` | `永久获得：攻击+9、防御+6` |

### 组合

| 原子能力 | 标准说法 |
| --- | --- |
| `顺序执行` | 用 `；然后` 连接子项 |
| `条件执行` | `若〈条件〉，则……`；有不成立分支时补 `否则……` |
| `随机执行` | `随机执行N项：` 后接并列子项 |
| `遍历目标` | `对〈目标〉逐个执行：` |
| `重复执行` | `重复N次：`；失败时停止写 `至多重复N次：` |
| `尝试执行` | `……；若能则……`；有失败分支时补 `若不能则……` |
| `事务执行` | `一并：……`；有失败分支时补 `若不成立则……` |
| `监听事件` | 条件段 `每当〈观察角色〉〈事件〉后`，处理段接 `效果` |

### 条件

| 原子能力 | 标准说法 |
| --- | --- |
| `概率条件` | `有N%概率` |
| `数值条件` | `〈左值〉〈比较〉〈右值〉` |
| `状态条件` | `〈目标〉的[状态]层数〈比较〉N` |
| `类型条件` | `〈来源/目标〉是〈值〉` |
| `组合条件` | `全部成立 / 任一成立 / 全部不成立` 后接子条件 |
| `标签条件` | `〈对象〉的标签包含任一/包含全部/全部不含/为空/至少N个：……` |

### 数值

| 原子能力 | 标准说法 |
| --- | --- |
| `读取数值` | `〈目标〉的〈属性/事实/状态/计量〉`；带百分比写 `相当于……的N%`；带上限写 `（最高N）` |
| `计算数值` | `〈左值〉〈方式〉〈右值〉`，如 `自身攻击×58%` |
| `随机数值` | `N至M之间的随机值` |
| `聚合数值` | `〈目标〉的〈数量/总和/最小/最大/平均/不同值数量〉` |

### 目标

| 原子能力 | 标准说法 |
| --- | --- |
| `选择目标` | `〈范围〉`，限定依次追加：`（存活/死亡）`、`（不含自身）`、`（参战者/召唤物/构造物）`、`（拥有[状态]）`、`（关联：X）`、`（排序：血气比例最低）`、`（最多N名）` |
| `选择技能` | `〈全部技能/可用技能/冷却中的技能/当前技能/指定技能〉`，如 `释放顺序最前的一门可用技能` |
| `选择状态` | `〈目标〉的[状态]`，限定同 `选择目标` |

### 效果

| 原子能力 | 标准说法 |
| --- | --- |
| `造成伤害` | `对〈目标〉造成〈数值〉的‹真实/属性›伤害`，句尾按 `能否闪避/暴击/格挡` 补 `（可暴击、可格挡）` |
| `恢复资源` | `〈目标〉恢复〈数值〉点〈资源〉` |
| `消耗资源` | `〈目标〉消耗〈数值〉点〈资源〉`；`不足时是否失败` 按第四节补注 |
| `支付代价` | 按 `代价类型` 分：`支付N点〈资源〉` / `消耗〈状态〉N层` / `行动延后N点` / `〈技能〉冷却增加N次行动` / `移除战斗对象〈对象ID〉` |
| `设置资源` | `将〈目标〉的〈资源〉设为〈数值〉` |
| `转移资源` | `将〈来源目标〉的〈来源资源〉〈数值〉转移给〈接收目标〉` |
| `添加状态` | `〈目标〉获得[状态]（持续N次行动，最多N层）` |
| `移除状态` | `移除〈目标〉的[状态]` |
| `增加状态层数` | `〈目标〉的[状态]+N层` |
| `消耗状态层数` | `消耗〈目标〉[状态]N层`；N 不小于该状态层数上限时写 `消耗〈目标〉[状态]全部层数` |
| `延长状态` | `〈目标〉的[状态]延长N次行动` |
| `缩短状态` | `〈目标〉的[状态]缩短N次行动` |
| `复制状态` | `将〈目标〉的[状态]复制给〈接收目标〉` |
| `转移状态` | `将〈目标〉的[状态]转移给〈接收目标〉` |
| `修改行动条` | `〈目标〉行动提前/延后N点`，设置时写 `行动条设为N` |
| `修改技能冷却` | `〈目标〉的〈技能〉冷却增加/减少/清空/设为N` |
| `修改构筑计量` | `[计量]+N` / `-N` / `设为N` / `清零`，带上限写 `（上限N）` |
| `追加攻击` | `对〈目标〉追加一次N倍威力攻击` |
| `分摊伤害` | `将〈目标〉的N%伤害分摊给……` |
| `转移伤害` | `将〈目标〉的N点伤害转移给……` |
| `抵挡致命伤害` | `抵挡一次致命伤害，并至少保留N点血气` |
| `复活` | `复活〈目标〉（血气N%、精神N%）` |
| `修改事件数值` | `本次事件的〈数值〉增加/减少/设为/乘算N` |
| `修改事件目标` | `将本次事件的目标改为〈目标〉` |
| `修改事件标签` | `为本次事件添加/移除/设置标签：……` |
| `取消事件` | `无效本次事件` |
| `触发技能` | `令〈目标〉施展〈技能〉`；`忽略代价`/`忽略冷却` 补 `（不消耗精神、无视冷却）` |
| `记录战斗事实` | `记录〈归属〉的‹名称›为〈值〉（保留N条）` |
| `修改战斗关联` | `在〈一方〉与〈另一方〉之间建立/解除关联‹名称›` |
| `修改技能` | `将〈目标〉〈技能〉的‹字段›设置/增加/减少/追加为〈值〉` |
| `复制技能` | `将〈来源目标〉的〈技能〉复制给〈接收目标〉` |
| `修改行动意图` | `取消该次行动`／`将该次行动的目标改为〈目标〉`／`将该次行动的技能改为〈技能〉`／`将该次行动改为〈值〉`。主体固定是「该次行动」，指**行动者那次行动**；`目标` 字段是意图被改成的**新目标**，不是意图的归属者（写成「〈目标〉的行动意图…」会把 `取消` 读成自己取消，方向正好相反） |
| `转化事件` | `将本次事件转化为〈事件〉` |
| `修改判定` | `本次〈判定〉必定成功/必定失败/反转/重掷取优`，多次写 `（N次）` |
| `修改战场规则` | `添加/移除战场规则〈名称〉：……`；位移时补 `（来源退场时移除）` |
| `保存结果` | `记为‹名称›`，来源为指定值时写 `记为〈值〉` |
| `切换形态` | `〈目标〉进入〈形态〉（攻击+9、防御+6）` |
| `创建战斗对象` | `召出〈类型〉[名称]（耐久N，阵营：己方/敌方）` |
| `移除战斗对象` | `移除战斗对象〈对象ID〉` |
| `修改归属` | `将〈目标〉的‹阵营/主人/控制者›改为……` |
| `回放效果` | `重复上一项效果（N倍率）` |
| `修改战术` | `〈目标〉的战术替换/追加/清空为〈战术〉` |

## 九、改写示例

现有文本（`九转金丹大道篇`，节选）：

```text
主动：
①[九转接燃]：耗神12，冷却5行动。
•先处理[传导]结算；
•令自身进入[余威相]（攻击+9、防御+6）；
•使[过杀]增加15。

裁定：
①[传导]：释放[九转接燃]时检查；达到4时，对当前目标造成传导×30%的真实伤害，随后清零；
```

按本规范改写：

```text
主动：
```

# 战斗文本规范

卡面正文由渲染器从能力树现算，`说明` 只保留卡头一行（风味 + 五行）。文本要让玩家不查引擎也能推出时机、因果、次数与代价；只写引擎已经能表达的语义。

## 一条处理的三个问题

| 段 | 回答 | 对应字段 |
| --- | --- | --- |
| 条件 | 什么时候能用、能用几次 | 监听事件、观察角色、阵营关系、条件、次数上限 |
| 发动 | 发动时付出什么、取哪些目标 | 精神消耗、冷却、额外代价、使用次数 |
| 处理 | 结算时依次发生什么 | 主动技能/监听事件的效果数组 |

标点承载语义：

- `：` 分条件与处理；没有 `：` 就是无条件段。
- `；` 分发动与处理，也分同一段的前后步骤。
- `。` 结束一条处理。
- `[]` 引用名字：技能、计量、状态。
- `（）` 只放数值与限定，不承载时序。
- `、` 只并列同类项，不表示先后。

条件或发动为空时整段省略，不留空标题。

## 连接词就是因果

| 连接词 | 引擎原语 | 含义 |
| --- | --- | --- |
| `然后` | 顺序执行 | 前项做不到就停；后项不影响前项 |
| `若能则` | 尝试执行 | 前项成功才做后项，失败走失败分支 |
| `若…则` | 条件执行 | 条件不成立走不成立分支 |
| `一并` | 事务执行 | 全部成立才生效，否则整段回滚 |
| `随机` | 随机执行 | 各项等价，抽中才生效 |
| `至多` | 重复执行.失败停止 | 失败即停，不补做 |
| `无效` | 取消事件 | 本次事件不再结算 |
| `此外` | 互不依赖的两件事 | 一件做不到，另一件照做 |

不要把 `顺序执行` 写成 `此外`，也不要把 `事务执行` 写成 `然后`。

## 时机要写全观察者

监听事件必须写清 `观察角色`（来源/承受者/行动者）与 `阵营关系`（自身/其他己方/任意己方/任意敌方/任意）。禁止只写「受到伤害后」，要写「任意敌方造成伤害后」。

- `XX前` → `当……前`
- `XX后` → `每当……后`
- `条件` 非空 → 条件段补 `若……`

本引擎没有「时 / 的场合」的时序差，统一用「每当……后」。

## 代价、目标与失败

- 代价写进发动段：`支付精神12`、`冷却5行动`，或额外代价原文。
- 目标是结算时取值，统一用 `选择`，不采用游戏王的「选择 / 选」二分。
- `不足时是否失败` 为真写 `（不足则本次不结算）`，为假写 `（不足则按实际值结算）`。
- 主动技能失败回滚写 `（任一环节不成立则整段回滚）`。
- `重复执行.失败时停止` 写 `至多重复N次`。

## 正文与明细

- 正文只写影响决策的：代价、目标与范围、数值与倍率、持续与层数、判定限制、免代价、失败行为。
- 明细只写引擎级信息，顺序固定：次数限制 → 结构细节 → 计量上限 → 优先级。
- 次数限制用「每行动只能使用1次」，不用「最多触发1次」。
- 计量上限只在结算段出现一次，不在每次 `[计量]+N` 后重复。

渲染器只转写，不美化；「无论成败」这类写法是引擎语义，不能当冗余删掉。

## 四类方向的语气

| 方向 | 标题 | 计量段 | 语气 |
| --- | --- | --- | --- |
| 功法 | 法门 | 裁定 | 法门运转、周天搬运 |
| 真意 | 真意 | 印证 | 只有一条被动，直述 |
| 气机 | 契合 | — | 只写固定属性加成 |
| 器律 | 器纹 | 器纹裁定 | 器物承载、锋芒所向 |

正文固定结构：规则 → 主动 → 被动 → 裁定；气机只有 `常驻`。卡头可自由发挥，正文必须能由 JSON 逐字推出，不能写回数据。

## 不采用游戏王的部分

- 没有连锁：不写「发动无效 / 效果无效」，统一写「无效本次事件」。
- 没有发动时取对象；目标在结算时选择。

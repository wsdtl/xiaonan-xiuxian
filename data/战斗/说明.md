# 战斗数据包

## 功能

### 一、启动期

1. 战斗核心晚于阵法核心；启动时一次性装载「战斗定义」与「战斗规则」，逐项校验属性、资源、事件、原子能力、行动、时序、伤害、五行与环境规则。
2. 属性只允许固定八键，`默认值` 必须落在最低/最高之间；`加成` 口径默认 100，`减免`/`比率` 默认 0。
3. 事件只允许 `携带事实` 与 `可修改`；`可修改` 只能是当前数值、目标、标签、取消、类型；只有恢复前、获得护盾前、资源恢复前允许带类型。
4. 每个已声明的执行器都必须有原子能力；`转移伤害` 只能挂在造成伤害前或受到致命伤害。
5. 行动规则：追加攻击 3、事件链 256、能力链 384、触发嵌套 8、每方召唤物 6、战斗构造物 12；链到顶不是报错，是「不再往下」，并留事实。
6. 时序来源层级固定：战场环境、阵法、功法、器律、真意、战丹、状态、战斗对象、战场规则；同一事件只建一次监听快照，新监听延迟 1 个事件生效。
7. 战报展示必须逐项覆盖事件全集；少项、多项或旧事件名都拒绝启动。

### 二、构筑与行动

8. 68 套构筑各 6 功法 + 6 真意 + 6 气机，三类各 408 套；功法 = 主动 + 常驻，气机 = 固定属性，真意 = 配合功法放大优势。器律是另一方向。卡片自带完整能力树，装载期不展开模板。
9. 行动条按速度线性累积：行动效率 = 有效速度 ÷ 标准速度，速度上限 300；就绪者按到达时刻、速度、阵营、序号、参战位序出队。
10. 一次行动固定次序：行动开始 → 恢复资源 → 减冷却 → 服丹 → 决定意图 → 行动决策前/后 → 技能或普攻 → 生命周期 → 行动结束 → 阵法轮转。
11. 技能从游标起找第一个可用且精神足够的；找不到就普攻；施放失败也补普攻。
12. 监听在事件创建后、事实提交前执行；排序：响应等级 → 来源层级 → 监听优先级 → 结算顺序 → 参战位序 → 装配位序 → 物品编号 → 能力序号。
13. 触发名额按「修士 + 词条 + 监听声明」算，同一修士两张同名词条共用一份；按行动清空，效果失败也算用掉。

### 三、伤害与五行

14. 伤害固定七段：输出倍率、命中、暴击、防御、增减伤、格挡、边界与落地；只有对敌伤害吃输出倍率，自伤不吃。
15. 命中 = 来源命中 − 目标闪避，夹在 20%–100%；暴击 = 暴击率 − 抗暴，倍率取暴击伤害 − 减免，最低 1、最高 400%；格挡最高 80%，格挡减伤最高 90%。
16. 防御段：有效防御 = 防御 ×(1−比例穿透) − 固定穿透；非负时倍率 = 常数 ÷ (常数+防御)，为负时翻成加伤。
17. 落地先托底到 1（原值大于 0 时），再扣护盾、扣血气；超出部分记过量伤害。
18. 五行关系倍率：同属性 1.00、相生 1.03、相克 1.15、被克 0.85、无关 1.00；全无相直接取 0.92；团队相生再乘 1.08。

### 四、环境、阵法与规则层

19. 战场环境按地形匹配；承载基准只按正式参战者血气上限求和，环境伤害只由具体事件触发，不用全场统一倍率。
20. 单次大伤害可跨多个阶段，按顺序触发入阶能力；阶段用替换制，旧阶监听失效。
21. 阵法不进行动条，在行动结束后轮转；轮转间隔 = ceil(基准周期 × 阶段倍率 ÷ 传导)；先冲敌方阵基，没有阵法才直达参战者。
22. 规则层是「拦截点 + 条件 + 处置」：拦截点决定载体，条件用标签匹配；参数留空表示不设限；优先级升序询问，成立结论只有被列进 `可改写` 才能改。
23. 锁定技不是效果：不产生事件、没有触发点、不进连锁，由规则读它做合法性判定；卡面最前逐条渲染，一条一个 `•`。
24. 越界的事件改写「拒绝 + 留痕」：不在白名单的改写不生效，事实里留 `改写非法`；转化目标已在结算栈上则放弃，留 `转化跳过`。

### 五、战报与意境

25. `战斗/展示/战报.json` 是名称、分类、颜色、文案与默认选项的唯一来源；后端生成完整展示对象，页面只渲染。
26. 伤害、恢复、消耗与状态变化只按 `标准化.结算事件` 统计；时间线只重放事件前后数值，末帧必须与战斗结果一致。
27. 阵法冲击以阵法编号为来源，在战报中有独立的承载、余承、冲击、节点、轮转与崩解事实。
28. 意境是战斗内强化：六条路各管一个子系统，九阶；买到的阶常驻，战斗中另有一层从零爬升的动态档，上限是买到的阶。
29. 血脉的 DNA、族谱与传位属于玩法；血脉能力与觉醒档属于战斗。两份数据按血脉编号对齐，不互相复制。

## 数据集

| 数据集 | 路径 |
| --- | --- |
| 战斗定义 | `定义/*.json` |
| 战斗规则 | `规则/*.json` |
| 构筑 | `内容/构筑/*.json` |
| 功法 | `内容/功法/` |
| 真意 | `内容/真意/` |
| 气机 | `内容/气机/` |
| 意境 | `内容/意境/` |
| 血脉规则 | `规则/血脉.json` |
| 血脉内容 | `内容/血脉/*/*.json` |
| 战场环境 | `内容/战场环境/*.json` |
| 战报展示 | `展示/战报.json` |

构筑模板另带 `建议种族`（种族编号），只作内容索引；实体仍按自己的 `构筑` 取模板。

血脉内容是 `编号实体`：文件名 `编号-名称`，根值单个对象；`说明` 是按条件/判定生成的摘要，不另写风物文案。

## 边界

- 战斗核心不创建角色资产、不决定构筑获取、不发玩法奖励、不做评分与平衡。
- 阵法正文、固定消耗与圣品材料倍率由阵法核心解释；战斗核心只执行不可变快照。
- 构筑之间只能通过真实战斗事件联动，不能读写另一个构筑的状态或裁定。

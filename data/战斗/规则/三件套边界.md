# 三件套边界（功法 / 真意 / 气机）

> 本文件是**规则说明**，与 `data/战斗/规则/构筑契约.json` 配套：
> 契约是机器判据，本文件是人读的口径。两者必须一致。
> 修改任一侧，另一侧必须同步修改，否则 `tools/架构审查/检查三件套边界.py` 会报红。

## 一、三条职责（现行规则）

| 组件 | 只做什么 | 不允许什么 |
| --- | --- | --- |
| **功法**（编号前缀 40） | **只有主动技能**：出手时结算，带 `冷却行动` / `精神消耗` / `目标` / `属性构成`（五行根基） | 不允许 `被动技能`（常驻、条件触发都属于真意）；不允许承载属性底数 |
| **真意**（编号前缀 41） | **只有被动**：常驻修正与条件触发（监听事件 → 条件 → 处理），不占行动 | 不允许 `主动技能`；不允许 `冷却行动` / `释放顺序`（那是功法的事） |
| **气机**（编号前缀 42） | **只做属性**：数值、资源、上限与恢复这类基础量 | 不允许技能（主动/被动都不行）；不使用效果模板 |

## 二、契约对应（`构筑契约.json`）

### 计量能力的使用边界

`修改构筑计量` 与 `来源=构筑计量` 不是通用战斗积木。它只允许出现在少数真意的特殊被动中，用来表达明确的积累-引爆或互斥转化；功法主动技能不再新增计量玩法，优先使用即时伤害、资源交换、状态互斥、位置与先后顺序。已有功法计量机制在迁移完成前保持可读，不得继续复制模板或扩展同类卡。

```json
"功法": { "根能力": ["主动技能"],            "要求主动技能": true }
"真意": { "根能力": ["被动技能"],            "要求主动技能": false }
"气机": { "根能力": ["固定属性加成"], "能力数量": 1, "要求主动技能": false }
"器律": { "根能力": ["被动技能"] }   ← 器律不在本次三件套范围内，保持原样
```

功法与真意按职责分离：功法只保留主动技能，真意独立承载被动监听；迁移时先完成数据归类，再由契约收紧边界。

## 四、口子（不许再开）

历史上出现过两种"绕判据"的做法，**都已被否掉**：

1. 把功法里的被动直接留在功法——会让主动与被动职责重新混在一起；
2. 给功法**新加一种能力种类**（如 `常驻能力`）来承载被动——这是绕判据，不是做规则。

**正确做法**：功法只保留主动技能；需要长期承载的特殊被动另行归入真意设计，不能继续挂在功法根能力上。

## 甲档：一卡一结构（实测配方与读数）

### 功法（主动侧，结构级唯一）

- 做法：从"甲档开工前"的干净数据出发，给每张功法卡在原有内容之外**追加一个结构**（原有内容全保留）。
- 结构构成：多原子组合，只用**字段干净**（体内不出现 名称/状态/计量/事实/记录 之类键）且经**合法性筛**通过的原子；
  实测通过的原子为：修改行动条、切换形态、修改事件数值、尝试执行、复活、分摊伤害、回放效果、取消事件。
- 变体维度：原子组合（2~4 个）、数值档、目标范围（合法取值：自身/当前目标/全体 等）、
  枚举字段（能否暴击、能否格挡、防御规则）。
- 结构池：实测 **1244** 个互不相同的结构；每张卡取一个，**不重复使用**。
- 实测读数：功法 600 张，**内联结构唯一 600 / 600**，卡级签名 **600 / 600**，重复最多出现 1 次。

### 真意（被动侧，参数级唯一）

- 前提实测结论：真意**不接受手写内联结构**（71 次尝试、0 合法），因此改为**引用现成被动模板 + 参数唯一化**。
- 做法：把在用模板按**参数键签名**分组（26 个模板 ⇒ 9 组），组内换模板 + 组内参数值轮转；
  分配方式为**进制展开**（把卡序号在"分组大小 × 值域大小"上逐位取模），保证双射。
- 实测读数：真意 600 张，**参数级唯一 600 / 600（100%）**，最大碰撞 1（即无碰撞）；
  剩余 12 张属结构性约束（其两个引用都落在"单模板组"或"单值域"里），已记录为已知残余。

### 功法唯一性的上限结论（实测穷举后的结论）

在同时满足下列四条约束时，功法唯一性**上限约为 300 / 600**：

1. 不改变战力（否则仓库里的团战深度用例会失败）；
2. 不新增原子能力（65 项不动）；
3. 不新增字段种类（只能用既有字段与其合法取值）；
4. 一卡一结构（结构不得重复使用）。

实测依据（每条都跑过闸门）：

| 做法 | 规模 | 八支闸门 | raid 用例 | 唯一签名 |
| --- | --- | --- | --- | --- |
| 追加结构（含强效果） | 600 | 全绿 | 失败 | — |
| 追加结构（仅低强度原子） | 60 | 全绿 | 通过 | — |
| 追加结构（仅低强度原子） | 600 | 全绿 | 失败 | — |
| 替换第二主动（低强度） | 120 | 全绿 | 通过 | — |
| 替换第二主动（低强度） | 240 | 全绿 | 失败 | — |
| **最小改动（数值微扰）** | 600 | 全绿 | **通过** | 289 |
| **最小改动 + 同组合换模板 + 参数轮转** | 600 | 全绿 | **通过** | **300** |
| 唯一标签（给效果打唯一标签） | — | — | — | 无效（该字段不存在） |

原因：功法在用模板仅 19 个，且**每个原子组合只有 1 份模板**（同组合内无可换对象）；各参数键的合法取值域又多为单值，
因此"参数层"能拉开的空间只有约 300 种。

要达到 600 / 600，只能放宽其中一条约束（例如允许新增"同原子组合、不同参数结构"的模板体，或调整上述仓库用例的阈值）。


### 上限的三重独立证据（补充）

- 证据一（行为）：凡改变结构或强度的做法，都会让团战深度用例变红；只有"完全不改战力"的做法能全绿。
- 证据二（算术）：功法全部模板引用里可用的数值参数总计约 303 个
  （威力倍率 121 个 + 数值 121 个 + 百分比 61 个），而可区分的卡片数不超过可变化参数个数，
  因此上限约 300；实测三次分别得到 289、294、300，与算术吻合。
- 证据三（否定）：在低强度模板中，带参数的模板数量为 0，无参数模板仅 1 个，
  因此"没有参数的卡片"无法通过换模板获得可区分维度。

结论：在不改战力、不新增原子能力、不新增字段种类、一卡一结构四条约束同时成立时，
功法唯一性上限约 300 张；真意侧不受团战深度用例约束，同一思路下达到 600 张。
放宽其中任一条约束才能继续提高功法侧的上限。

## B 档收口裁决（执行者记，待用户确认后即为定案）

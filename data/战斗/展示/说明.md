# 战斗展示

> 本说明只写现行规则与边界；历史变更与试玩过程见 [待补内容.md](../内容/待补内容.md)。

`战报.json`是战斗事实到玩家战报的唯一展示契约。

```text
战斗引擎的结构化结果
+ 战斗/定义/{属性,资源,事件}.json
+ 技能、状态与构筑的展示名称
+ 战斗/展示/战报.json
-> 标准化战报
-> 后端战报展示协议
-> static/battle-report
```

| 根部分 | 作用 |
| --- | --- |
| `协议` | 战报 Schema、展示协议、展示版本，以及**展示载荷里事件与事实只许带的字段**（`事件字段` / `事实字段`） |
| `游戏名称` | 战报对外显示的游戏名 |
| `视觉` | 前景色、系统色、参战者颜色和资源颜色 |
| `标准化` | 原始事件到分类、名称和明细格式的映射 |
| `展示` | 界面文案、顺序、状态和结果表现 |

`协议.事件字段` / `协议.事实字段`是展示载荷的**形状白名单**：一条公开事件只许有这八个字段（事件类型、标签、色调、分类、正文、来源、目标、事实），一条事实只许有标签与显示串两个字段。判据（工具目录里的战报展示审查）逐条核，多一个少一个都红。这份名单不含**页面上一个都不读**的字段：每条事件各抄一遍的时间、各抄一遍的能力名、序列号、事件序号，以及事实里的「事实键」（与标签同值）与「原值」。**要往载荷里加字段，先加进这份名单**——加了就是协议变了。

事件的来源与目标**是角色键（字符串），不是小字典**：角色颜色与来源/目标名字收成载荷级的两张表——演员表（键 → 名字）与调色板（键 → 序号 / 颜色 / 前景色），页面查表。两份表在战报头与明细包里各有一份（各自的载荷自成一体），里面必须有「系统」那一项（系统事件的来源就是它）。时间线条上的每条行动带的是「行动者键」。协议版本因此从 4 升到 5：拿到 4 的旧页面会直接拒绝渲染，而不是安静地画成空白。判据除形状外还核「键能不能查到」与「两张表跟战报的参战者是否一致」。

**快照里的参战者只带会变的那一半**：行动前后状态每条行动各存两份快照，其中不变的东西（功法 / 招式 / 能力 / 属性列表）收进花名册。现在载荷多一份**花名册**（键 → 名字 / 阵营 / 队名 / 颜色 / 分组标题 / 功法能力分组），快照记录只剩「键 + 血气精神护盾 + 当前状态」三项（`协议.参战者字段`），页面加载后用花名册合成完整记录（前端加载每个载荷时合成一次，查不到档案当场抛错）。协议版本 5 → 6。判据「快照与花名册」核三件事：快照记录字段就是那三项、花名册覆盖战报的每一个参战者且名字一致、每条记录的键都能在花名册里查到。

`标准化.结算事件`只选择哪些已有事件代表最终伤害、战场伤害、资源恢复、资源消耗和状态增减，不能新增结算。事件是否触发、属性数值、目标和胜负都由战斗核心决定。

`标准化.紧凑事实`声明简要模式（页面的「战斗记录」）每一行带出哪些事实：按事件类型列出要取的明细标签，按序取第一个有值的；写两个标签表示「前 → 后」。事件自己有正文时用正文（引擎只把类型名抄一遍的那些不算正文），否则用这一行拼成「类型名 · 事实」。声明的类型必须真实存在，也不能声明已经被 `标准化.紧凑隐藏类型` 藏起来的类型——两种写错都只会安静地不生效。

`标准化.内部明细`是**不进战报**的明细标签：引擎的记账字段（`事件` / `来源` / `原始数值` / `当前数值`）与内部编号（`行动者` / `目标ID` / `对象ID`，引擎那边写作字母加序号）。战报是对外文档，里面只许出现名字。

`标准化.记录事实`是**日志的闸门**，两份名单：`保留`（进日志的事实键）与 `丢弃`（明确想过、决定不记的键——引擎的记账字段、掷点过程、伤害链的中间值）。引擎在**记录那一刻**就按 `保留` 筛，所以不在名单上的键既不进事件、也不进战报与落库记录（不是「记下来再藏起来」）。规矩：`保留` 与 `丢弃` 不许重叠；`标准化.内部明细`（屏上不许出现的账）必须也在 `丢弃` 里；`展示.伤害事实`、`标准化.百分比明细`、`标准化.倍率明细`、`标准化.紧凑事实` 里提到的事实键必须都在 `保留` 里（否则渲染出来是空的）——这几条在战斗核心启动时校验，写错直接起不来。

判据是 `tools/战报记录对照.py`：同一批仗跑两遍（全记 / 按名单筛），要求**事件骨架、简要行与参战者快照逐场一致**，记下来的键全在 `保留` 里，且语料里出现的每个键都被决定过（在 `保留` 或 `丢弃` 里）——冒出新键就红，逼作者做决定。

`展示.伤害事实`在伤害类事件里当白名单用：一条伤害事件的明细有三十多个字段，只有这里列出的才进战报。**它列的都是「结果」**（原始伤害、命中、暴击、格挡、护盾/血气/过量/实际伤害、前后血气与护盾、伤害形式与名称）；判定概率与掷点（`命中率` / `命中判定值` / `暴击率` / `暴击判定值` / `格挡率` / `格挡判定值`）、伤害链的中间值（`暴击后伤害` / `防御后伤害` / `增减伤后伤害` / `格挡后伤害` / `边界后伤害`）以及防御内部（`原始防御` / `有效防御` / `防御倍率` / `伤害倍率` / `防御规则`）都在 `记录事实.丢弃` 里，根本不进日志。

参战者的阵营由战报写死（每个参战者的 `阵营`）：展示层只许照抄，不许按顺序猜。多单位编组（宗门战、讨伐）的阵营一律照抄战报，不许按顺序猜。

**首屏只给片段头部信息，片段内容按需取**：`/data` 里的片段表只有概览字段（片段号、标题、胜负、时间、统计、阵法），时间线与参战者快照由服务端按片段给（`/segments/<序>` 等五条，见 `static/说明.md`）。展示包本身也**不进存档**——宗门战只存战报，页面要的时候从战报现算。

修改事件、资源或界面字段时，必须同步初始化战斗核心并重新生成战报；静态页面只能读取后端展示协议，不能自定义游戏文案或分类。

# 角色规则关系说明

> 本说明只写现行规则与边界；历史变更与试玩过程见 [待补内容.md](../../战斗/内容/待补内容.md)。

本目录按完整角色主体或角色档次组织 JSON。文件名表达具体分类，一个文件中的每个字典保存该分类的一套完整规则；同一主体的属性、成长、修行槽位等相关字段不再机械拆成多个文件。

## 当前结构

```text
角色/
├─ 主体/
│  ├─ 人物.json
│  ├─ 道侣.json
│  ├─ 敌方修士.json
│  └─ 灵兽.json
├─ 成长/
│  └─ 修士修炼.json
└─ 修行/
   └─ 修行所得.json
```

境界实体不属于角色规则目录，保存于 `角色/内容/境界.json`；角色规则只负责解释等级成长，突破的裁定（必成功、永久属性只增不减、每个目标境界一条记录）写在角色服务里，没有单独的突破规则文件。

## 人物初始化关系

```text
主体/人物.json.成长规则 --------> 成长/修士修炼.json
人物、道侣与敌方修士 ----> 物品/炼器/规则/本命武器.json（由炼器服务提供独立武器状态）

玩家实例把当前等级、突破记录和本命武器状态交给角色服务。角色服务先执行修士成长，再按突破记录中的丹药编号读取当前 JSON，汇总永久属性，并按战斗属性定义的最低值与最高值收束；超出属性最高值的部分不进入战斗快照。每个目标境界只保存一条突破记录，不重复保存可由丹药定义计算出的永久属性结果。

`主体/人物.json`、`主体/道侣.json` 和 `主体/敌方修士.json` 分别通过 `本命武器.器律池` 显式引用四个器阶池，这是对应主体的公共候选规则。世界道侣实体必须保存自己的本命武器名称、等级、经验和已占器律孔，不重复保存公共池名；角色与炼器服务不得根据人物等级或名称临时补造武器状态。敌方修士是按等级范围临时生成的战斗角色，其武器等级直接用生成出来的实际等级；敌方修士实体中的本命武器 `攻击` 是一级基础攻击，后续攻击成长统一读取 `物品/炼器/规则/本命武器.json`。灵兽没有本命武器，因此不定义器律池。

战斗/定义/属性.json 默认值
+ 人物.json.属性覆盖
-> 最终初始属性
-> 人物.json.资源 初始化当前资源
```

`人物.json.物品` 直接使用编号、品级与数量字典列表。人物运行中的三类状态由 `角色/规则/状态/初始状态.json` 组合，数据库只保存为 `player_state/main`，由玩家状态核心按行为、队伍、控制三份状态定义读取和变更。文件名已经表达“人物”，JSON 内不再增加同名外层键或版本字段。

## 修士性别

修士性别的唯一取值来源是 `角色/定义/性别.json`。人物主体使用 `创建选择`，玩家创建完成后必须持久化具体性别；道侣主体使用 `实体`，每名世界道侣直接保存固定性别；敌方修士主体使用 `随机`，每次生成敌人实例时从性别定义中等概率取得，地点敌人定义不得提前写死。

首次邀约道侣要求双方性别不同；成功邀约过后，玩家转性不会解除关系，再次邀约也不重新检查性别。世界道侣不允许转变性别，两仪易形丹只作用于玩家自身。性别不参与基础属性、成长、修行槽位或本命武器计算；战斗快照只携带性别稳定值，供明确声明两仪分支的少数功法读取。灵兽、召唤物和构造物不使用修士性别规则，也不会误命中任一分支。

## 共享修炼成长

人物、道侣和敌方修士共用 `修士修炼.json` 中的等级、属性成长和经验公式，突破条件与结算写在角色服务里。灵兽不走这条曲线：每个灵兽物种按等级命中唯一 `阶梯`，直接保存自己完整的 `每级成长`，不再用公共成长与差值拼装。

经验先按 `幂次基数 × 等级^等级幂次 + 等级基数 × 等级` 取整；40 级后再叠加后段的中段、高段和终段倍率。**数值不在这里写死**：全部系数以 `成长/修士修炼.json` 的 `经验` 一节为唯一出处，累计值由角色成长服务按这份曲线现算。按当前曲线，修士从 1 级升至 100 级累计需要 `49062369` 经验（即 1 级到 99 级每级所需经验之和；每级需求各自至少 1）。角色成长服务是唯一对外计算入口，其他业务不能自行复写公式。

道侣在修士成长结果上应用 `道侣.json.资质成长修正`。灵兽实体的 `每级成长` 必须直接给出血气上限、精神上限、攻击和防御四项最终值；角色业务不再读取隐藏的公共成长，也不执行差值加算。

```text
灵兽实际每级成长 = 敌人实体.每级成长
```

修士本体每级攻击为 `0.5`，本命武器每级攻击为 `1`；一级人物本体攻击 `5`、武器攻击 `10`，到一百级分别为 `54.5` 和 `109`，武器保持攻击主来源，本体成长也具有实际分量。

灵兽没有本命武器，肉身必须同时承担修士本体与武器两条成长线。当前 122 个灵兽物种直接保存以下完整每级成长：

- 血气上限 `14–22`，平均约 `18.46`；
- 精神上限固定为 `3`；
- 攻击 `1.2–2.1`，平均约 `1.54`，对应修士本体与武器合计的每级攻击 `1.5`；
- 防御 `1–1.9`，平均约 `1.38`。

灵兽用更强的血气、攻击和防御表达肉身路线，用较弱精神成长和较少修行槽位保持差异。不得再把灵兽解释成缺少武器的弱化修士，也不得为灵兽补本命武器、器律池或隐藏武器倍率。

## 修行槽位关系

修行槽位属于角色自身配置，不是战斗核心规则：人物读取 `人物.json.修行槽位`，道侣读取 `道侣.json.修行槽位`，敌方修士和灵兽都按实际等级读取对应阶梯中的 `修行槽位`。修行槽位保存功法、真意和气机；人物另有一个独立的先天灵宝槽，槽位数量由 `玩法/先天灵宝/规则/先天灵宝.json` 统一声明，当前执掌状态由先天灵宝核心单独保存。器律孔属于本命武器，并由本命武器等级命中 `物品/炼器/规则/器则.json.器阶` 后派生。敌方修士从 `2/2/2` 增长至 `12/12/12`，灵兽从 `1/1/1` 增长至 `6/6/6`。**首领档就该比玩家满编**：人物与道侣是 `6/6/6`，敌方修士的圆融档与人物同级、镇域 `9/9/9` 与天灾 `12/12/12` 比玩家更厚——**敌人不超过玩家，那还叫什么首领**。构筑形状判据只盯一条：**同一个主体内部，档次越高修行槽位不得变少**，且功法 / 真意 / 气机三项齐全；超不超过玩家不是缺陷。

功法、真意和气机候选池位于 `内容/功法`、`内容/真意` 和 `内容/气机` 的 `池` 子目录；角色规则或角色实体只保存池文件名引用，不复制候选内容。构筑相冲和随机生成终止边界位于 `战斗/规则/构筑/`，不属于角色规则。

取得后的功法按 `修行/修行所得.json` 永久进入道藏，同编号只保留当前最高品级；真意和气机进入修行资粮，按 `编号 + 品级` 分别累计数量。装配功法不消耗道藏所有权，被替换功法仍留在道藏；装配真意或气机消耗对应品级一份资粮，被替换内容直接消失。取得后的器律进入器藏，由自身器阶决定强度，只保存编号与待覆炼数量；覆炼消耗一份器律，原孔内容被覆盖后消失，其他器律孔保持不变。

## 突破记录

突破记录按目标境界唯一，保存本次使用的突破丹编号。纯突破节点服用九霄补天丹后，再保存玩家所选的同目标境界单属性突破丹编号作为 `补正来源丹药`；角色服务据此读取该丹当前永久属性。九霄补天丹本身不直接写死数值，也不复制永久属性结果。

## 敌方修士档次

当前 `主体/敌方修士.json` 保存六档完整规则，每档通过 `功法池`、`真意池`、`气机池` 引用同阶段候选池。后续按敌人档次拆分时，应采用 `精英敌人.json`、`天灾敌人.json` 这类具体分类文件；每个文件仍保存该档敌人的完整字典或字典列表，不把等级、速度、抗控和修行槽位继续拆开。

群体攻击、阶段转换、受击反制、资源续航和绝境翻盘必须来自实际装配内容，不能写进角色成长 JSON。

## 灵兽档次

`主体/灵兽.json` 与 `主体/敌方修士.json` 使用相同的顶层和阶梯协议：`角色类型`、`成长规则`、`阶梯`，以及每阶的等级范围、修行槽位、三类候选池、每级速度、固定控制抵抗率和固定韧性。灵兽数值整体较低，但不是没有修炼与高阶成长。

敌人实体通过 `角色规则: 灵兽` 接入，生成实际等级后再命中对应阶梯；不得因敌人自身等级范围跨阶而提前写死候选池。灵兽没有本命武器，其肉身直接承担完整战斗成长，物种差异由属性覆盖、完整每级成长以及实际装配内容表达。

## 种族

种族是**天生**那一层：不挂卡、不占修行槽位，只给一组**天生锁定技**（战斗侧叫「参战者固有规则」，见 `战斗/说明.md` 第 66 条）。`规则/种族/种族.json` 是登记表，共 **180 条、18 个族系**；实体只引用 `种族` 名，不复制内容。

**七条口径**：

- **有负面就必须配至少一条强正面**：挡同伴（`来源关系:己方`）与挡自己（`来源关系:自身`）算负面，挡敌方或不设限算正面。只给负面是纯惩罚，只给正面是白送。
- **每个种族一副形状**：两个种族的天生规则组合（含参数）完全一样就报红——不比数值、不换皮。
- **人族是基准族，不许有任何天生规则**：它的强度全在道途、构筑与经营上，所有种族都以它为参照，而且它**六档全出现**（谁都得能跟人族比）。
- **卡与种族不共用同一条闸门**：卡带 `不吃负面状态` / `不受控制`，种族就不许再带这两条——敌人的构筑里随时可能抽到那三张卡，同一张脸上写两条同名规则是启动期错误。两条渠道各走各的名额。
- **名额有两本账**：`名额` 是**卡**的发行量，`种族名额` 是**种族**的发行量（只有单位级规则该有它），判据把两笔都打出来，超一个就红。
- **每个种族都要在敌方档次里出得来**（`出现档次`）：抽不到的种族就是躺着的死数据，直接报红；**每档至少三个族**。
- **种族没有卡面**：查看页看到的是种族名与它的天生规则，而不是一张卡（固有规则不参与卡面渲染）。

**另外三样（非锁定技）**：`成长修正`（属性→倍率，只乘等级带来的增量；敌人与人物成长都按它走）、`寿元系数`（乘在境界寿元上，只算寿元上限，衰老与寿终还没做）、`卡池来源`（从哪一套阶梯池抽卡，默认敌方修士、可选灵兽——兽性族系走灵兽池）。

## 修改检查

- 先判断新数据属于哪个角色主体或敌人档次，再放入具体命名的 JSON。
- 同一主体内共同组成一条完整规则的字段保存在一起，不按字段名机械拆文件。
- 新角色规则必须使用敌方修士与灵兽共享的阶梯字段协议，不为新角色族另造初始化形状。
- 每个灵兽实体直接保存完整 `每级成长`；不得重新引入公共值加个体修正的二次拼装。

# 字段位次规范

本规范只管字段先后，不改字段值、不改数组顺序。所有正式 JSON 按对象类型套用同一套位次；不再保留旧的字段排列。

## 一、对象类型

1. **编号记录**：含 `编号` 的对象。开头固定为 `编号`、`名称`、`说明`，随后是分类、引用、规则、数值、展示。
2. **能力节点**：含 `能力` 且不含 `编号` 的对象。`能力` 第一，随后是 `名称`、`说明`、`范围`、`目标`、状态/资源/属性、条件/事件/效果、数值。
3. **schema 对象**：含 `字段` 或 `约束` 的对象。顺序为 `说明`、`字段`、`约束`。
4. **前缀登记**：含 `前缀` 的对象。顺序为 `前缀`、`主体`、`类别`。
5. **纯映射**：对象里没有任何已登记的结构字段，键是名字表或属性表。纯映射保留原键顺序，只递归整理它的值；不把名字表按字典序打乱。

## 二、字段分组

从前往后：

1. 身份：`编号`、`名称`、`说明`。
2. 分类：`类别`、`来源类别`、`类型`、`分类`、`定位`、`品级`、`器阶`、`阶`、`阶序`、`阶段`、`境界`、`书脉`、`流派`、`种族`、`性别`、`身份`、`角色类型`、`关系`、`立场`、`归属`、`码`、`权柄`、`地形`、`事件标签`、`存入位置`。
3. 引用与位次：匹配状态、匹配优先级、触发优先级、优先级、结算/释放/获得顺序、等级上下限、寿元、下一境界、目标境界、最低品级、上下限、数量、次数、权重、参考价、倍率、系数、比例、概率、百分比、数值、消耗、冷却、持续、触发上限。
4. 规则与结构：`能力`、`范围`、`目标`、`选择全部`、`状态`、`资源`、`属性`、`属性构成`、`属性覆盖`、`效果`、`条件`、`事件`、`观察角色`、`阵营关系`、来源/接收目标、方式、左右值、执行器、监听、触发、匹配、战斗状态、叠加、治疗、层数、材料、掉落、阵核、检测、节点、坐标、功能配置。
5. 展示：标题、页面、样式、显示、格式、按钮、文本、错误、提示、分页、顺序表、页码、旁白。
6. 组件与 schema：组件、读取规则、数据集、路径、结构、实体类别、编号类别、目录池、编号定义、文件名唯一、资源池字段、归属规则、扫描目录、字段、约束、类型规格键。

## 三、未登记字段

已登记字段按上面的语义组排列。未登记字段统一排在已登记字段之后，按 Unicode 码位排序；不再沿用各文件原来的随机位置。

纯映射是唯一例外：它的键是内容顺序，不是属性位次，所以不改键顺序。

## 四、硬规则

- `编号` 必须是编号记录的第一个字段。
- `名称`、`说明` 在编号记录里紧随其后。
- `能力` 必须是能力节点的第一个字段。
- `说明`、`字段`、`约束` 是 schema 的前三个字段。
- 数组顺序不变；数组元素里的对象分别按本规范重排。
- 不保留旧字段排列，不写兼容分支。

## 五、执行

所有正式 JSON 用同一套排序器重排；重排后必须能通过 JSON 语义等值检查、数据驱动、字段契约和全量测试。后续新增字段先归入上面的组；确实无法归组的，才落到未登记字段的码位序。

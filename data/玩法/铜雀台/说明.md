# 铜雀台数据包

> 本说明只写现行规则与边界；历史变更与试玩过程见 [待补内容.md](../../战斗/内容/待补内容.md)。

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、启动期把规则读死

1. **依赖必须先就绪**：初始化时依次检查修为转移核心、角色核心、道侣核心、资产核心、人物状态核心、位置核心、世界核心、数据库核心、先天灵宝核心九个，任一未就绪就抛「必须先于铜雀台玩法启动」。
2. **展示契约硬校验**：铜雀台展示的「文本」必须是对象，且必须含「预览 / 结算 / 错误」三个对象分区；「按钮」必须是数组，每个按钮必须恰好含 编号 / 名称 / 命令 / 条件 / 行为 / 样式 六字段，条件只能是「始终 / 有护契丹」，行为只能是 callback / send / fill / link，样式只能是 primary / secondary。
3. **规则来自世界地点**：夺元参数不在本包，而在世界地点 `功能配置` 的 `夺元` 一节里，按「`可用功能` 含夺元的地点必须且只有一个」取回（`data/世界/内容/云京州/铜雀台/铜雀台.json`、`data/世界/定义/地点功能.json`）。
4. **目标契约硬校验**：`目标` 的 `角色类型` 必须是「道侣」、`目标` 的 `必须同行` 必须是 true、`目标` 的 `每次数量` 必须是 1，`最低等级` 必须为正整数（配置值 2）；不满足直接拒绝启动（`data/世界/内容/云京州/铜雀台/铜雀台.json`）。
5. **转化率硬校验**：护契丹的 `使用效果` 里 `类型` 必须是「护持道契」，`服丹` 的 `转化率` 必须正好 100、`未服丹` 的 `转化率` 必须正好 70，否则拒绝启动（`data/世界/内容/云京州/铜雀台/铜雀台.json`）。
6. **重置与保留字段硬校验**：`重置` 的 `修为字段` 必须等于「境界→等级对应境界、等级→1、经验→0、属性→初始属性、突破记录→空」，`清除来源` 必须依次是「等级成长、突破永久属性」，`资源处理` 必须是「保留当前值并受初始属性上限约束」，`保留字段` 必须依次是 资质 / 属性倍率 / 功法 / 真意 / 气机 / 本命武器 / 器律 / 自动用药 / 待战战丹（`data/世界/内容/云京州/铜雀台/铜雀台.json`）。

### 二、预览怎么算

7. **守卫与地点**：先按规则里的 `状态守卫`（自主空闲或休息）校验人物状态，未通过直接拒绝；再按玩家坐标定位世界地点，要求「夺元」在该地点的 `可用功能` 里，否则抛「只有身在铜雀台才能夺元」。
8. **可夺修为**：用同行道侣实例的等级与经验算可夺总量 = 当前经验 + 从 1 级升到（等级 - 1 级）所需的经验之和；低于 `最低等级` 2 级直接抛「至少达到2级才能夺元」，经验为负也拒绝。
9. **两档转化**：护契所得 = 总量 × 100 ÷ 100 后向下取整，离契所得 = 总量 × 70 ÷ 100 后向下取整；若先天灵宝在「铜雀台夺元」节点给出「提高转化效率」，离契转化率换成「效率 × 100」取整后的值，护契仍是 100。
10. **承接受境界上限所阻**：预览对两种模式各算一次人物吸收修为的计划，承接量与溢散量由角色一侧的境界上限决定，`等级上限约束` true 且 `溢出处理` 为「丢弃」——溢出部分不入账（`data/世界/内容/云京州/铜雀台/铜雀台.json`）。
11. **丹药取自纳戒**：读纳戒中 `服丹` 的 `丹药`（160003）的全部品级栈，取品级顺序最小的一栈作为将消耗的丹；没有栈即视为没有护契丹（`data/世界/内容/云京州/铜雀台/铜雀台.json`）。
12. **动作条件**：条件为「始终」的按钮恒出，条件为「有护契丹」的按钮只在纳戒里确实有守真定契丹时出现。

### 三、结算的事务与幂等

13. **模式入参校验**：模式只能是「护契」或「离契」，其余一律抛「夺元方式只能是护契或离契」。
14. **请求编号幂等**：先按用户与请求编号查已提交的事务；已有提交且业务类型是「铜雀台夺元」、`模式` 与本次相同就回放上次结果，业务类型不符或模式不符均按冲突拒绝。
15. **吸收与重置先规划**：确认后先规划人物吸收修为（承接 / 溢散按境界上限截断）与道侣修为重置（回到初境一级、经验 0、初始属性，并清掉 `等级成长` 与 `突破永久属性`），保留 资质 / 功法 / 真意 / 气机 / 本命武器 / 器律 等字段。
16. **护契分支**：纳戒无守真定契丹时抛「纳戒中没有守真定契丹」；有丹则按数量 1 扣丹、额外并入道侣的护契守卫状态，好感与同行关系保持不动。
17. **离契分支**：并入道侣的离契状态变更——好感归零、解除同行、关系转为离契、回到 `原始地点`，并把变更前好感记进事务回执。
18. **同事务交割**：扣丹（护契时）、人物吸收、道侣重置、关系变更放进同一笔「铜雀台夺元」提交，任一步版本冲突即整体失败并抛「人物、道侣关系或纳戒已经变化，请重新预览」。
19. **回执载荷**：提交载荷记录 地点 / 人物名称 / 道侣编号 / 道侣名称 / 道侣故地 / 模式 / 应得修为 / 承接修为 / 溢散修为 / 原好感 / 丹药编号 / 丹药名称 / 丹药品级 / 先天灵宝 这些内容，回放时直接由该载荷还原结果。
20. **丹药名解析**：丹药名称取自 `丹药` 实体 160003 的 `名称`，护契回执里带上该名称与本次消耗品级的名称。

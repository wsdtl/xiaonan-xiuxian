# 特殊地点

特殊地点不是另一套地点系统，而是 `可用功能` 里挂了**地点专属功能**的普通地点。地点实体在 `世界/内容/地点/特殊地点/<地点>/<地点>.json`，玩法包在本目录下；两者同名但不是同一个所有者。

## 一、分层

| 层 | 权威 | 决定什么 |
| --- | --- | --- |
| 地点实体 | `世界/内容/地点/特殊地点/<地点>/<地点>.json` | 坐标、说明、`可用功能`、`功能配置` |
| 功能定义 | `世界/定义/地点功能.json` | 功能是否`地点配置`、同目录内容、地点字段要求 |
| 世界按钮 | `世界/展示/按钮/地点功能.json` | 功能对应的按钮名称、命令与样式 |
| 玩法包 | 本目录 `<地点>/` | 该功能的展示文案与复杂规则 |
| 命令/业务 | 命令层与对应领域服务 | 解析、渲染、结算 |

## 二、六条规律

1. **地点是壳，功能是槽**：`可用功能` 列出这个地点有哪些槽；地点不解释槽里做什么。
2. **`地点配置: true` 是特殊功能的唯一标记**：这类功能必须且只能有一个地点，地点实体必须在 `功能配置` 里给它一节。普通功能（闭关、修士、探险、交易、锻造、炼丹、炼阵）可以出现在多个地点，不需要 `功能配置`。
3. **按钮只登记一次**：一个功能在世界按钮表里一行；地点只决定这行按钮出不出。到达地点后的面板按 `可用功能` ∩ 按钮表生成，不在玩法包里另列一套按钮。
4. **丹药是门槛，不是地点属性**：强制丹写 `功能配置.<功能>.丹药`；可选或分支丹写在功能自己的子结构里（如夺元的 `服丹`）；宗门、山门没有丹。不要为了统一硬造 `丹药` 键。
5. **玩法包只写槽里的内容**：规则能放进 `功能配置` 的，就不在本目录重复；流程超出地点配置的（生育、宗门园区）才建 `规则/`。命令包只解析与渲染，业务可以在别的领域服务里。
6. **特殊地点可以套地点**：宗门园区本身也是特殊地点，只是它的“大槽”是内层地点（宗门洞天），不是一组并列功能。外层到达只显示宗门、山门；进入内层后，内层地点再按同一套 `可用功能` / `功能配置` / 按钮规律显示自己的功能。两层都按同一规律，不要把内层功能塞进外层。

## 四、新增或整改时

1. 先在世界地点实体里写 `可用功能` 与 `功能配置`；新功能先登记 `地点功能.json`，`地点配置: true`。
2. 在世界按钮表加一行；没有按钮的功能不会出现在到达面板，启动时会直接报错。
3. 玩法包只建 `展示/`；流程确实超出 `功能配置` 才加 `规则/`。
4. 命令包只放命令注册、解析与渲染；业务按领域落到对应服务。
5. 特殊丹放 `物品/内容/丹药/特殊丹/16xxxx`，门槛只在一个地方声明（世界 `功能配置`），代码读它，不硬编码编号。
6. 如果特殊地点是“地点套地点”，外层只放进入内层的入口功能；内层地点按同一份清单单独登记、单独校验。
7. 补测试：到达面板出按钮、缺丹拒绝、扣丹成功、离开地点拒绝。

## 五、检查

- `地点功能.json` 的每个名称都必须有一行世界按钮；按钮表也不能有未登记的功能。
- 每个地点的每个 `可用功能` 都必须能在 `地点功能.json` 找到；`地点配置: true` 的功能必须且只能出现在一个地点，并在该地点的 `功能配置` 里有一节。
- `功能配置` 的键必须是 `可用功能` 的子集。
- 地点套地点时，外层与内层各自按 `可用功能` 与按钮表校验，不能拿外层按钮表去覆盖内层。

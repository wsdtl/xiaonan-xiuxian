# 血脉数据包

## 功能

### 一、启动期把展示契约读死

1. **依赖必须先就绪**：初始化时依次检查角色核心、数据库核心两个，任一未就绪就抛「必须先于血脉玩法启动」。
2. **展示契约硬校验**：血脉展示数据必须恰好含 文本 / 图标 / 血脉 三键；文本的页面只能是「族谱」与「传位」，出现别的页面即拒绝启动；图标与按钮同批读入。
3. **按钮契约硬校验**：按钮页面只能是「族谱」或「传位」，行为与样式走共享骨架的白名单校验，编号在同一页面内不得重复。

### 二、族谱（只增不改）

4. **读出族谱**：按玩家编号读「血脉族谱」这一份状态；没有这份状态时返回空族谱，不报错。
5. **记录当时的事实**：族谱节点同时记「族谱名」（出生时的名字）与「玩家名」（继承后的名字），两者都不随后续改名而改写。
6. **同代不漏记**：一代之内该记的候选与实记条数必须一致，缺记即判非法。
7. **可作取名参考**：族谱只提供查阅与取名参考，不参与任何数值计算，也不做近亲判定。

### 三、传位（结束这一代，开始下一代）

8. **列出可传位的新生儿**：只列族谱里尚未传位、且仍活着的新生儿，按代次与登记顺序排。
9. **选定一个新生儿**：按编号或名字精确选定；找不到就抛「没有这个新生儿」，多于一个同名时要求报编号。
10. **旧壳进族谱**：传位时把当前这一壳在族谱里标为「已传位」，保留它当时的名字、性别、DNA 与代次快照。
11. **换壳不换人**：境界、等级、属性、构筑、图鉴、熟练与纳戒全部不变，只有血脉、性别、族群与年龄寿元四项随新生儿重算。
12. **代次加一，胎次清零**：传承前后为一代，传位成功即代次加一，同时把这一代的胎次计数清零。
13. **按新 DNA 重算血脉**：新生儿成为当前这一壳之后，按它的 DNA 重新跑一遍血脉匹配，写回新的命中血脉。

### 四、命令入口

14. **两条命令**：族谱与传位都注册在专属血脉二级组件里，主命令都是「血脉」，族谱走族谱分支、传位走传位分支。

15. **血脉规则表**：规则文件给两组定义。普通血脉每条读 编号 / 名称 / 条件 / 强度 / 能力；条件里的每一条读 组 / 下限 / 上限，至少要有一条，全部命中才算生效。天外每条读 编号 / 名称 / 形态 / 判定 / 负面 / 能力。
16. **能力用战斗的原子能力写法**：血脉自己不解释能力，只把 能力 数组原样交出去，由战斗引擎装配与结算。基础加成写成一条 固定属性加成（属性是一张 属性名 到 数字 的表）；能觉醒的血脉再跟若干条 条件执行，条件是一条 数值条件（比较 自身当前血气 与 自身属性 里的 血气上限 的百分比），成立效果是另一条 固定属性加成。血脉不自己造加成字段，也不自己算倍率。
17. **觉醒档**：规则文件另给一组觉醒档，每档读 下限 / 上限 / 倍率；这一张表是给人看的口径说明，真正落到每条血脉能力里的，是按 基础值 x (倍率 - 1) 折算出的固定属性加成。
18. **基础加法表的属性名**：每条血脉的 能力[0].属性 是一张属性名到数字的表，实际用到的是 攻击 / 速度 / 韧性 / 精神上限 这几个属性名（与战斗属性登记表同名，不新造名字）。
19. **能觉醒**：每条血脉另有一个 能觉醒 布尔字段；为真表示它吃觉醒档（当前 17 条：天外的 10 件与普通里命中人数不超过 8 人的 7 条）。
20. **形态与判定分开住**：天外的 形态 只是给人看的名字（怎么写都不影响判定）；真正的条件是 判定，一个 DNA 表达式串。
21. **表达式的记号**：G1 到 G6 是那一组的整组值；G11 G12 是第 1 组的第 1 个 / 第 2 个数字（即十位 / 个位），其余组同理（G32 是第 3 组的个位）；最多重复数 是六组里重复出现最多的次数。可用的运算符：加减乘与整除、取余，比较 = != > < >= <=（可链式写成 G1<G2<G3），以及 且 / 或 / 非。写法例：G1+G6=99 ／ G1<G2<G3<G4<G5<G6 ／ G12=G32 且 G32=G52 ／ 最多重复数>=3。判定写错就拒绝启动。
22. **代码只做解释器**：判定 的表达式由代码解释执行；形态叫什么名字、条件怎么写，都住在本规则文件里，改数据不需要改代码。
23. **读到的键就必须写在这里**：本节列的键与规则文件一一对应，加键要同时改说明。

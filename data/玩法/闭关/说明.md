# 闭关数据包

> 本说明只写现行规则与边界；历史变更见 git 历史，待补事项与缺功能见 [待补内容.md](../../战斗/内容/待补内容.md)。

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、启动期把规则读死

1. **依赖必须先就绪**：闭关玩法初始化时依次要求闭关核心、行动编排核心已经初始化，否则抛「闭关核心必须先于闭关玩法启动」或「行动编排核心必须先于闭关玩法启动」；闭关核心自身还要求异步玩法生命周期核心、长期伤势核心、先天灵宝核心先就绪。
2. **按钮契约硬校验**：按钮页面只能是「开始 / 进度 / 总结」，按钮编号不得重复，越界即拒绝启动。
3. **总时长必须自洽**：`每轮秒数` 300 × `最多轮数` 6 必须等于 `持续秒数` 1800，不等就抛「闭关持续秒数必须等于每轮秒数乘最多轮数」（`规则/闭关.json`）。
4. **行为状态硬校验**：`行为状态` 520004 必须指向人物状态表里类型为「行为」的状态，`允许提前出关` 必须 true、`提前出关轮数` 必须是「向下取整」，否则拒绝启动（`规则/闭关.json`）。
5. **经验与结算硬校验**：`每轮经验` 的 `等级取值` 必须是「开始时」；`成长结算` 必须整块等于「人物经验 true / 本命武器经验 false / 正式参与者分别结算 true」（`规则/闭关.json`）。
6. **恢复与感悟硬校验**：`每轮恢复` 的 `最多恢复至上限` 必须 true，血气与精神的上限比例必须各自落在 0 至 1（配置各 0.2）；`功法感悟` 的 判定对象 / 每轮独立判定 / 候选来源 / 抽取模式 / 品级来源 / 取得规则 必须与玩家全池契约逐项相等，`概率` 也必须在 0 至 1，否则拒绝启动（`规则/闭关.json`）。

### 二、开始与预计算

7. **参与者解析**：开始时要求发起者排在首位、成员不重复、人数不超过 `参与用户上限` 15，越界抛「一次闭关最多15名用户」；行动编排报出「成员不能发起」时转成「只有领队可以发起闭关」。
8. **开始幂等**：先读玩家名下最近一次闭关的指针，若其中的闭关编号对应的开始请求与本次请求编号相同，直接回放上次开始结果。
9. **种子与场次编号**：未显式传种子时，随机种子由发起者与请求编号共同决定；场次编号同样由这两者推出，保证同一请求必得同一编号。
10. **同处与地点校验**：逐名参与者取当前位置，要求（空间类型、空间编号、坐标）三元组全同，否则抛「同行修士必须位于同一空间和坐标」；空间类型不是「地表」则抛「宗门洞天内不能进行闭关」；定位后的地点必须把「闭关」列在 `可用功能` 里，否则抛「当前位置不能闭关」。
11. **状态守卫与切状态**：逐名参与者要求处于「空闲或托管」，否则带着用户标识抛出拒绝原因；通过后规划切到 `行为状态` 520004，上下文写入 闭关编号 / 发起者 / 参与人数。
12. **每轮经验预锁**：开始时读每名参与者的人物等级，按 `基础` 150 + `每级` 22 × 开始时的等级锁进会话，后续每轮都用这个固定值乘完成轮数，等级中途变化不影响本场（`规则/闭关.json`）。
13. **同道侣一起算正式角色**：同行道侣按 `同行道侣` 的 `方式`「并肩」算作正式角色，存在但缺实例时抛「同行道侣缺少实例」；有实例则按道侣自身等级同样预锁每轮经验，正式参与者再加一人。
14. **灵宝改写预计算**：先天灵宝效果节点为「闭关开始」或「闭关疗伤」时，能力「增加每轮感悟判定」按 `次数` 增加每轮判定次数、「提高每轮经验」按 `比例` 抬高每轮经验（取「原值 + 1」与「原值 × (1 + 比例) 后向上取整」两者中较大的一个）、「增加每轮疗养进度」按 `进度` 累加疗养进度倍率。
15. **功法感悟预抽**：对 `最多轮数` 6 轮每轮按 `概率` 0.1 独立判定，命中就从 `玩家虚拟全池` 抽 1 本功法（`允许重复`）、品级按「随机奖励」抽，记下轮次 / 编号 / 品级；整场最多 6 次基础判定（`规则/闭关.json`）。

### 三、进度与结算

16. **完成轮数**：已完成轮数 = 已过秒数除以 `每轮秒数` 后向下取整，上限截到 `最多轮数` 6，提前出关同样按整轮向下取整（`规则/闭关.json`）。
17. **进度只读**：查看进度时只放行轮次不超过已完成轮数的感悟；未结算时剩余秒数 = 最晚出关时间减现在后向上取整，且不小于 0，已结算则剩余为 0 并回显结算里的完成轮数。
18. **只有领队能出关**：出关时先查结算记录，已存在就直接回放；否则要求当前用户就是发起者，不是则抛「本次闭关由领队统一带领出关」。
19. **每轮恢复取上限**：`每轮恢复` 按 `血气上限比例` 0.2 与 `精神上限比例` 0.2 分别给出气血与精神的恢复比例，两者都取 1 与「完成轮数 × 0.2」之中较小的一个，都不超过各自上限，满轮时正好回满（`规则/闭关.json`）。
20. **人物经验与疗伤**：人物本场经验 = 预锁每轮经验 × 完成轮数，随人物结算计划一并写入；同时按 完成轮数 × 疗养进度倍率 推进长期伤势疗养，没有变化时不产生状态写入。
21. **道侣经验**：同行道侣按自己的预锁每轮经验 × 完成轮数结算，同时按完成轮数推进道侣一侧的疗养；`成长结算` 的 `本命武器经验` 为 false，所以本命武器经验不结算（`规则/闭关.json`）。
22. **功法感悟取得**：解封的感悟走 `取得规则` 指向的「修行所得.功法取得」落成资产获取计划，结果只会是「新得 / 升品 / 复悟」三种，未知结果即判状态非法；其中「升品」还要同步人物一侧的功法品级（`规则/闭关.json`）。
23. **同事务交割**：人物成长、道侣成长、双方疗伤、功法奖励与品级同步、逐人结束行为状态、结算记录全部并入同一笔「闭关出关」提交，任一步版本冲突即整体失败并抛冲突错误。

### 四、幂等与页数边界

24. **开始同事务**：「闭关开始」提交同时放下会话状态、全部参与者的行为状态迁移与每人最近一次闭关的指针。
25. **回执状态落点**：会话状态、最近一次闭关的指针、结算记录三类状态都由闭关核心声明，外部只能经核心读写。
26. **页数边界**：出关命令按 1 + 参与人数 算总页数，页码不在 1 到总页数 内即拒绝；总结页的上一页 / 下一页按钮按页码是否存在生成。

### 五、命令入口

27. **三条命令，各带别名**：`开始闭关`（别名 `闭关`，命令注册于专属闭关组件第 13 行）、`闭关进度`（别名 `查看闭关进度`、`闭况`，命令注册于专属闭关组件第 39 行）、`闭关结束`（别名 `结束闭关`、`出关`，命令注册于专属闭关组件第 69 行）。三条都走「空闲或托管且可行动」守卫。

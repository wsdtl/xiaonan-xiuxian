# 道侣数据包

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、启动期把展示契约读死
1. **依赖必须先就绪**：初始化时依次检查道侣核心、物品查询核心、资产核心、角色核心、位置核心、世界核心、数据库核心、先天灵宝核心八个，任一未就绪就抛「必须先于道侣结交玩法启动」。（`game/features/daolv_jiejiao/service.py`）
2. **展示契约硬校验**：`道侣展示` 数据集必须恰好含「文本 / 图标 / 道侣」三键，文本必须恰好含「查看 / 交谈 / 赠礼 / 邀约 / 暂别 / 命令 / 错误」七分区，图标必须恰好含 身份 / 性情 / 喜好 / 关系 / 交谈 / 赠礼 / 邀约 / 暂别 / 错误 九键，多一键少一键都拒绝启动。（`game/features/daolv_jiejiao/presentation.py`）
3. **按钮契约硬校验**：按钮页面只能是「查看 / 交谈 / 赠礼 / 邀约 / 暂别」，条件只能是 空 / 可邀约 / 同行中，行为只能是 `callback` / `send` / `fill` / `link`，样式只能是 `primary` / `secondary`；名称不许带占位符，命令除「暂别」页外必须恰好含 `{道侣}` 一个占位符，且同一页面按钮编号不得重复。（`game/features/daolv_jiejiao/presentation.py`）

### 二、道侣对象与可达性
4. **编号或名称解析**：`_resolve_companion` 先按道侣编号精确匹配，再按去空白后的名称匹配，找不到就抛「未找到道侣」。（`game/core/companion/service.py`）
5. **定义装载校验**：道侣核心按 `道侣` 实体逐条过世界字段契约，等级必须唯一落进某个境界区间，喜爱灵植池非空且成员类别必须是「灵植」，喜爱池必须都能在炼药归脉里查到本脉，否则拒绝启动。（`data/角色/规则/主体/道侣.json`、`game/core/companion/service.py`）
6. **规则硬校验**：道侣核心要求 `同行上限` 必须是 1、`圆满回礼.每名道侣终身次数` 必须是 1、`赠礼喜好.拒绝倍率` 必须是 0、`赠礼喜好.合意推导` 必须是「炼药规则.归脉 / 与偏爱灵植池本脉相同」，资质成长最高倍率不得低于最低倍率；不满足直接拒绝启动。（`data/角色/规则/主体/道侣.json`、`game/core/companion/service.py`）
7. **可达性校验**：`_ensure_accessible` 先看目标是否正是当前同行道侣，是则放行；否则要求玩家所在地点名等于道侣定义的地点，不等就抛「如今不在此处」。（`game/features/daolv_jiejiao/service.py`）

### 三、赠礼的好感与事务
8. **喜好三档判定**：物品按 `ItemCatalogService.inspect` 解析；类别不是「灵植」一律记「拒绝」，是灵植则查道侣的偏爱集合与合意集合，命中偏爱返回「偏爱」、命中合意返回「合意」，都不命中返回「拒绝」。（`game/core/item_catalog/service.py`、`game/features/daolv_jiejiao/service.py`）
9. **拒绝分支先返回**：判定为「拒绝」时直接返回零好感结果，`消耗` 为 false，不进任何事务，物品不扣除。（`game/features/daolv_jiejiao/service.py`）
10. **好感算式**：实际好感 = `赠礼每件好感 × 喜好倍率（偏爱或合意）× 品级.能力倍率 × 数量`，按 `0.1` 量化、`ROUND_HALF_UP` 进位；偏爱时再尝 `先天灵宝` 的「道侣赠礼」节点，能力为「提高偏爱好感」就按 `比例` 放大后二次量化。（`data/角色/规则/主体/道侣.json`、`game/core/companion/service.py`）
11. **品级解析**：未显式给品级时读纳戒中该物品的全部品级栈，无栈抛「纳戒中没有这株灵植」，多于一个栈要求玩家指定品级并列出候选。（`game/features/daolv_jiejiao/service.py`）
12. **数量校验**：数量必须是大于等于 1 的整数，布尔值也拒；道侣核心侧同样再校验一次「赠礼数量必须是正整数」。（`game/core/companion/service.py`）
13. **好感状态累加**：`plan_gift` 把 `当前好感 + 实际好感` 量化后写回，同时按 `物品编号:品级编号` 累加 `赠礼累计`；此键必须是 6 位编号加 2 位品级，否则状态即判非法。（`game/core/companion/service.py`）
14. **首次圆满与回礼**：只有当 `首次圆满时间` 为空且累加后好感达到 `圆满回礼.触发好感` 时才置为首次圆满，此时同一事务里额外加入回礼物品的纳戒增量。（`game/core/companion/service.py`）
15. **同事务交割与幂等**：纳戒扣除与关系写入放进同一笔 `道侣赠礼` 提交；提交读到已存在的同 `request_id` 事务时走回放，返回「已处理」结果并标记 `回放`，不二次扣物。（`game/core/database/storage.py`、`game/features/daolv_jiejiao/service.py`）
16. **异常映射**：纳戒不足或状态版本冲突分别转成查询错误与「关系状态刚刚发生变化」的冲突错误。（`game/features/daolv_jiejiao/service.py`）

### 四、邀约与暂别
17. **邀约先看好感**：好感低于 `邀约.好感要求` 直接拒绝；随后看同行位，已有道侣同行且不是目标就抛「正在与你同行，请先暂别」，已是目标则原样返回并标 `已经同行`。（`data/角色/规则/主体/道侣.json`、`game/core/companion/service.py`）
18. **首次邀约性别约束**：首次邀约（或 `再次邀约检查性别` 为 true 时的每次邀约）在 `首次邀约性别关系` 为「不同」时，若玩家性别与道侣性别相同即拒绝。（`data/角色/规则/主体/道侣.json`）
19. **实例与同行位落点**：首次邀约同一事务写入道侣轻实例（固定资质与属性倍率）、关系里的 `首次邀约时间` 和唯一同行位；曾邀约过但缺实例则报状态错误，不补建。（`game/core/companion/service.py`）
20. **暂别只清同行位**：`plan_farewell` 要求目标正是当前同行道侣，只把同行位状态置空，好感、赠礼累计与个人实例全部保留，同一事务提交。（`game/core/companion/service.py`）
21. **动作条件过滤**：动作按页面取按钮，条件「可邀约」要求 `can_invite` 为 true，「同行中」要求该道侣正在同行；`can_invite` = 定义可交互 且 好感达 `邀约.好感要求` 且 当前同行位为空 且（已首次邀约过 或 玩家性别与道侣不同）。（`game/features/daolv_jiejiao/service.py`）

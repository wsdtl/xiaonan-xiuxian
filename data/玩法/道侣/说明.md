# 道侣数据包

## 功能

### 一、启动期把展示契约读死

1. **依赖必须先就绪**：初始化时依次检查道侣核心、物品查询核心、资产核心、角色核心、位置核心、世界核心、数据库核心、先天灵宝核心八个，任一未就绪就抛「必须先于道侣结交玩法启动」。
2. **展示契约硬校验**：道侣展示数据必须恰好含 文本 / 图标 / 道侣 三键，文本必须恰好含 查看 / 交谈 / 赠礼 / 邀约 / 暂别 / 命令 / 错误 七分区，图标必须恰好含 身份 / 性情 / 喜好 / 关系 / 交谈 / 赠礼 / 邀约 / 暂别 / 错误 九键，多一键少一键都拒绝启动。
3. **按钮契约硬校验**：按钮页面只能是「查看 / 交谈 / 赠礼 / 邀约 / 暂别」，条件只能是 空 / 可邀约 / 同行中，行为只能是 callback / send / fill / link，样式只能是 primary / secondary；名称不许带占位符，命令除「暂别」页外必须恰好含 `{道侣}` 一个占位符，且同一页面按钮编号不得重复。

### 二、道侣对象与可达性

4. **编号或名称解析**：先按道侣编号精确匹配，再按去掉空白后的名称匹配，找不到就抛「未找到道侣」。
5. **定义装载校验**：道侣核心按道侣实体逐条过世界字段契约，等级必须唯一落进某个境界区间，喜爱的 `灵植池` 非空且成员类别必须是「灵植」，喜爱池里的每一项都必须能在炼药的归脉里查到 `本脉`，否则拒绝启动（`data/角色/规则/主体/道侣.json`）。
6. **规则硬校验**：道侣核心要求 `同行上限` 必须是 1、`圆满回礼` 的 `每名道侣终身次数` 必须是 1、`赠礼喜好` 的 `拒绝倍率` 必须是 0、`赠礼喜好` 的 `合意推导` 必须整块等于「炼药规则.归脉 / 与偏爱灵植池本脉相同」，`资质成长修正` 的 `最高倍率` 不得低于 `最低倍率`；不满足直接拒绝启动（`data/角色/规则/主体/道侣.json`）。
7. **可达性校验**：先看目标是否正是当前同行道侣，是则放行；否则要求玩家所在地点名等于道侣定义的地点，不等就抛「如今不在此处」。

### 三、赠礼的好感与事务

8. **喜好三档判定**：物品按编号解析；类别不是「灵植」一律记「拒绝」，是灵植则查道侣的偏爱集合与合意集合，命中偏爱返回「偏爱」、命中合意返回「合意」，都不命中返回「拒绝」。
9. **拒绝分支先返回**：判定为「拒绝」时直接返回零好感结果，`消耗` 为 false，不进任何事务，物品不扣除。
10. **好感算式**：实际好感 = `赠礼每件好感` × 喜好倍率（偏爱或合意）× `品级` 的 `能力倍率` × 数量，按 0.1 量化、四舍五入进位；偏爱时再尝试先天灵宝的「道侣赠礼」节点，能力为「提高偏爱好感」就按 `比例` 放大后二次量化（`data/角色/规则/主体/道侣.json`）。
11. **品级解析**：未显式给品级时读纳戒中该物品的全部品级栈，没有栈抛「纳戒中没有这株灵植」，多于一个栈要求玩家指定品级并列出候选。
12. **数量校验**：数量必须是大于等于 1 的整数，布尔值也拒绝；道侣核心一侧同样再校验一次「赠礼数量必须是正整数」。
13. **好感状态累加**：把 `当前好感` 加上实际好感后量化写回，同时按「物品编号:品级编号」累加赠礼累计；这个累加键必须是 6 位编号加 2 位品级，否则状态即判非法。
14. **首次圆满与回礼**：只有当首次圆满时间为空、且累加后的好感达到 `圆满回礼` 的 `触发好感` 时，才把它记为首次圆满，此时在同一事务里额外加入回礼物品的纳戒增量。
15. **同事务交割与幂等**：纳戒扣除与关系写入放进同一笔「道侣赠礼」提交；提交读到已存在的同一请求编号事务时走回放，返回「已处理」结果并标记为回放，不二次扣物。
16. **异常映射**：纳戒不足或状态版本冲突分别转成查询错误与「关系状态刚刚发生变化」的冲突错误。

### 四、邀约与暂别

17. **邀约先看好感**：好感低于 `邀约` 的 `好感要求` 直接拒绝；随后看同行位，已有道侣同行且不是目标就抛「正在与你同行，请先暂别」，已是目标则原样返回并标 `已经同行`（`data/角色/规则/主体/道侣.json`）。
18. **首次邀约性别约束**：首次邀约（或 `再次邀约检查性别` 为 true 时的每次邀约）在 `首次邀约性别关系` 为「不同」时，若玩家性别与道侣性别相同即拒绝（`data/角色/规则/主体/道侣.json`）。
19. **实例与同行位落点**：首次邀约在同一事务里写入道侣轻实例（固定资质与属性倍率）、关系里的首次邀约时间和唯一同行位；曾经邀约过但缺实例则报状态错误，不补建。
20. **暂别只清同行位**：要求目标正是当前同行道侣，只把同行位状态置空，好感、赠礼累计与个人实例全部保留，同一事务提交。
21. **动作条件过滤**：动作按页面取按钮，条件「可邀约」要求允许邀约，「同行中」要求该道侣正在同行；允许邀约 = 定义可交互 且 好感达到 `邀约` 的 `好感要求` 且 当前同行位为空 且（已首次邀约过 或 玩家性别与道侣不同）。

### 五、命令入口

22. **五条命令**：`查看道侣`（别名 `道侣查看`，命令注册于专属道侣结交组件第 19 行）、`交谈`（别名 `道侣交谈`，命令注册于专属道侣结交组件第 49 行）、`赠予 道侣 灵植 [品级] [数量]`（命令注册于专属道侣结交组件第 79 行，走的就是本节第三条那套好感与回礼裁定，业务类型「道侣赠礼」）、`邀约`（别名 `邀约道侣`，命令注册于专属道侣结交组件第 116 行）、`暂别`（别名 `暂别道侣`，命令注册于专属道侣结交组件第 150 行）。命令层守卫是 `自主空闲或休息`，页面与按钮由展示层渲染。

# 位置数据包

> 本说明只写现行规则与边界；历史变更与试玩过程见 [待补内容.md](../../战斗/内容/待补内容.md)。

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、位置核心的启动期

1. **依赖必须先就绪**：玩家位置核心启动时依次检查 JSON 数据服务、核心数据库、世界核心三个依赖，任一未就绪就拒绝启动，并指出该依赖必须先于玩家位置服务启动（「JSON 数据服务必须先于玩家位置服务启动」「核心数据库必须先于玩家位置服务启动」「世界核心必须先于玩家位置服务启动」）；重复启动直接抛「玩家位置核心微服务已经初始化」。
2. **四条上限硬校验**：`附近` 规则里的 `修士` 分区必须存在，`范围米数` 15000、`每页数量` 20、`最多可见数量` 100、`最多候选数量` 500 四个值都必须是正整数，并且 `每页数量` 不得超过 `最多可见数量`、`最多可见数量` 不得超过 `最多候选数量`，越界即拒绝启动。（`规则/附近.json`）
3. **格子尺寸取自世界**：格子尺寸不是本组件的数据，而是从世界核心的地图快照里读每格米数，位置核心不复制地势。

### 二、附近修士怎么筛

4. **水平预筛在数据库**：附近修士查询以自身坐标为原点，把 `范围米数` 折成格半径，按格心平方距离不超过半径平方枚举候选格；查询时排除自己，并要求候选的空间类型与空间编号都与原点一致。
5. **候选上限探测**：向数据库索取 `最多候选数量` 加 1 条记录；取回条数大于 `最多候选数量` 时记下候选已经触顶，随后只保留前 `最多候选数量` 条。（`规则/附近.json`）
6. **三维距离复算**：逐条按世界核心查该点海拔，用水平距离平方加上海拔差的平方得到三维距离平方，超过半径平方的候选被丢弃。
7. **排序**：结果按三维距离平方、坐标、玩家编号三级升序；核心只负责候选与排序，公开状态过滤和截断留给位置玩法。
8. **内部读接口**：按玩家读当前位置时直接读数据库里的位置事实，记录为空就报错「人物缺少地表位置」；出生位置写入先把出生坐标过一次世界校验，再落成 0 版本的位置记录。

### 三、位置写入与事务落点

9. **单人行路**：单人行路先把预期起点与终点各过一次地点查询，非地表空间拒绝（「非地表空间不能执行世界行路」）；已经在终点就返回未变化的成功结果；实际位置不等于预期起点时抛位置冲突（「人物位置已经改变：预期 …，当前 …」）。
10. **集体行路**：集体行路要求参与者名单非空、不重复且首位是发起者，再逐人读当前位置；任一人不在地表就拒绝（「非地表空间不能执行世界行路」），有人不在同一个预期起点就整队拒绝（「同行修士已经不在同一出发位置」）。
11. **一次事务落全部**：集体行路把每个参与者的位置写入连同各自版本号放进同一条事务，业务类型按人数取「集体行路」或「人物行路」；任一版本失效就转成位置冲突（「同行位置在行路结算前已经改变」），请求编号命中已提交事务时返回重放标记。
12. **空间变更**：空间变更同样校验参与者顺序与唯一性（「空间变更参与者顺序无效」）；地表不许带空间编号（「地表空间不能包含空间编号」），非地表必须带（「非地表空间必须包含空间编号」）；全部已在目标空间时返回未变化结果，只有一部分在目标空间则抛「同行空间状态不一致」，彼此不在同一空间抛「同行修士不在同一空间」；提交时业务类型按方向取「进入宗门洞天」或「离开宗门洞天」，版本失效转成位置冲突（「空间变更前位置已经改变」）。
13. **状态上报**：状态上报只在已初始化时读数据库里的位置记录条数，同时回传半径、每页数量与可见上限，供上层装配玩法。

### 四、行路与同行的落点

14. **同行状态由三个核心各自持有**：「独行 / 随队 / 随宗」不落在位置核心的数据结构里，也不读本组件的规则文件；人物状态、队伍、宗门三个核心各自持有自己那一面，位置玩法按它们的公开快照判冲突——队伍公开快照说已编组、宗门公开快照说正在跟随，两者同时为真就是「同行状态冲突」。坐标锚点由位置核心按玩家单独保存，跟随由一条集体行路事务完成。
15. **一名玩家一条状态**：同行状态不落在位置核心的数据结构里，而是由人物状态、队伍、宗门三个核心各自持有；队伍公开快照的已编组与宗门公开快照的跟随中同时为真时，位置玩法直接给出「同行状态冲突」这一状态项，不判优先级。
16. **领路与脱离**：集体行路只允许参与者与发起者同处一个预期起点，所以领路人一移动，整队就在同一条事务里跟随；行路玩法在发起前向行动编排核心取参与者，成员被判定为跟随身份时抛「当前正在跟随领队，只有领队可以发起行路」；脱离后的坐标由位置核心保留，同行归属由队伍与宗门核心清除。
17. **道侣随行**：道侣不进入位置核心；位置玩法按当前地点的道侣池查本地道侣，并把自己当前出战的那名从列表里排除；道侣坐标始终跟随所属玩家的最终位置。

### 五、位置玩法的入口与参数

18. **玩法启动依赖**：位置玩法启动依次要求世界核心、玩家位置核心、角色核心、人物状态核心、世界道侣核心、宗门核心六个已就绪，任一未就绪就拒绝启动，原因是该依赖「…必须先于位置查看玩法启动」。
19. **附近地点参数**：从 `附近` 规则里的 `地点` 分区读 `范围米数` 50000 与 `最多数量` 8，两者都必须是正整数；距离用世界快照的每格米数与海拔复算成三维平方距离。（`规则/附近.json`）
20. **附近修士过滤与截断**：先并发取候选、出战道侣、人物公开摘要、公开状态、队伍与宗门同行摘要；缺人物摘要、缺公开状态、或公开状态标记为不出现在附近的候选一并剔除，再按最多可见数量截断；候选触顶或可见条数超过上限时记下已截断。
21. **分页与拒绝**：页码不是正整数时按「页码必须是正整数」拒绝；页码大于 1 且起始下标已经越过可见条数时按「附近修士没有这一页」拒绝；切片起点 =（页码 - 1）× 每页数量，是否还有下一页按停止下标小于可见条数判定。（`规则/附近.json`）
22. **附近地点边界**：非地表空间直接返回空结果；按三维距离平方、坐标、名称升序后只取前 `最多数量` 条；每个地点的功能只保留展示按钮中开放的那些。
23. **方向与距离算法**：方向取横纵坐标差各自的正负号去查方向表，偏移为零时返回空串；距离平方为 0 时返回 `同处措辞`，否则开方、除以 `每里米数` 折成里，再四舍五入到 `约数步长` 的整数倍且下限为一步。（`展示/规则/距离与方向.json`）
24. **非地表清场**：读当前位置时，非地表空间把 `可用功能` 与三类池全部清空，并用宗门核心的宗门归属与宗门信息解析出空间名称。

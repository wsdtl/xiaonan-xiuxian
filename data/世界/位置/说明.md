# 位置数据包

本包按组件维护数据，文件归属由 [组件.json](组件.json) 声明。数据集名是公共读取契约；编号、池文件名不随目录变化。

## 功能

### 一、位置核心的启动期
1. **依赖必须先就绪**：`initialize` 依次检查 JSON 数据、数据库、世界三个核心，任一未就绪就抛「…必须先于玩家位置服务启动」；重复初始化抛「玩家位置核心微服务已经初始化」。（`game/core/location/service.py`）
2. **四条上限硬校验**：`附近.修士` 必须存在，`范围米数` 15000、`每页数量` 20、`最多可见数量` 100、`最多候选数量` 500 四个值都必须是正整数，且 `每页数量` ≤ `最多可见数量` ≤ `最多候选数量`，越界即拒绝启动。（`规则/附近.json`、`game/core/location/service.py`）
3. **格子尺寸取自世界**：`_cell_size_meters` 不是本组件的数据，而是从 `WorldService.map_view().cell_size_meters` 读取，位置核心不复制地势。（`game/core/location/service.py`）

### 二、附近修士怎么筛
4. **水平预筛在数据库**：`nearby_players` 以自身坐标为原点，把 `范围米数` 折成格半径，按格心平方距离 ≤ 半径平方枚举候选格，查询时排除自己并要求 `space_type`/`space_id` 与原点一致。（`game/core/location/service.py`、`game/core/database/storage.py`）
5. **候选上限探测**：向数据库要 `最多候选数量 + 1` 条，取回条数大于 `最多候选数量` 时置 `candidate_limit_reached`，随后只保留前 `最多候选数量` 条。（`规则/附近.json`、`game/core/location/service.py`）
6. **三维距离复算**：逐条用 `WorldService.locate` 取该点海拔，`distance_squared = 水平距离平方 + (海拔差)²`，超过半径平方的候选被丢弃。（`game/core/location/service.py`）
7. **排序**：结果按 `distance_squared_meters`、`xy`、`user_id` 三级升序，核心只做候选与排序，公开状态过滤和截断留给位置玩法。（`game/core/location/service.py`）
8. **内部读接口**：`current(user_id)` 直接读数据库位置事实，记录为空时抛 `LocationMissingError`；`initial_mutation` 把出生坐标过一次世界校验再落成 0 版本的位置写入。（`game/core/location/service.py`）

### 三、位置写入与事务落点
9. **单人行路**：`move` 先把预期起点与终点各过一次 `locate`，非地表空间拒绝（「非地表空间不能执行世界行路」），已在终点则返回未变化的成功结果，实际位置不等于预期起点时抛 `LocationConflictError`。（`game/core/location/service.py`）
10. **集体行路**：`move_many` 要求参与者列表非空、不重复且首位是发起者，逐人读当前位置，任一人非地表或不在同一预期起点就整队拒绝。（`game/core/location/service.py`）
11. **一次事务落全部**：`move_many` 把每个参与者的 `LocationMutation` 连同各自版本号放进同一条 `TransactionCommand`，业务类型按人数取「集体行路」或「人物行路」；任一版本失效抛 `StateConflictError`，转成 `LocationConflictError`，`request_id` 命中已提交事务时返回 `replayed`。（`game/core/location/service.py`）
12. **空间变更**：`change_space` 同样校验参与者顺序与唯一性，`地表` 不许带空间编号、非地表必须带；全部已在目标空间时返回未变化结果，只有部分在目标空间则抛「同行空间状态不一致」，彼此不在同一空间抛「同行修士不在同一空间」；提交时业务类型按方向取「进入宗门洞天」或「离开宗门洞天」。（`game/core/location/service.py`）
13. **状态上报**：`status()` 只在已初始化时读数据库的 `location_count`，同时回传半径、每页数量与可见上限供上层装配玩法。（`game/core/location/service.py`）

### 四、行路与同行的落点
14. **同行定义的位置事实**：`规则/同行.json` 把「独行 / 随队 / 随宗」三态的 `坐标来源` 都定为「自身」，随队随宗都 `可独立行路` false 并 `结束后` 回到「独行」，道侣 `坐标来源` 为「所属玩家」且 `保存独立坐标` false；本快照没有读取该文件的独立 Python 模块，位置层面的执行落在下面的核心与玩法分支上。（`规则/同行.json`）
15. **一名玩家一条状态**：同行状态不落在位置核心的数据结构里，而是由人物状态、队伍、宗门三个核心各自持有，`team.public_many` 的 `grouped` 与 `sect.public_follow_many` 的 `following` 同时为真时，位置玩法直接给出「同行状态冲突」这一状态项，不判优先级。（`game/features/weizhi/service.py`）
16. **领路与脱离**：`move_many` 只允许参与者与发起者同处一个预期起点，因此领路人移动即整队在一条事务里跟随；行路玩法在发起前向行动编排核心取参与者，成员被判定为跟随身份时抛「当前正在跟随领队，只有领队可以发起行路」，脱离后的坐标由位置核心保留、同行归属由队伍与宗门核心清除。（`game/core/location/service.py`、`game/features/xinglu/service.py`、`game/core/action_group/service.py`）
17. **道侣随行**：道侣不进入位置核心，位置玩法按当前地点的 `companion_pool` 调 `CompanionService.local_cultivators` 取本地道侣，并把自己当前出战的那名从列表排除；道侣坐标始终跟随所属玩家的最终位置。（`game/features/weizhi/service.py`）

### 五、位置玩法的入口与参数
18. **玩法启动依赖**：`PositionFeature.initialize` 依次要求世界核心、玩家位置核心、角色核心、人物状态核心、世界道侣核心、宗门核心六个已初始化，任一未就绪抛「…必须先于位置查看玩法启动」。（`game/features/weizhi/service.py`）
19. **附近地点参数**：从 `附近.地点` 读 `范围米数` 50000 与 `最多数量` 8，两者都必须正整数；距离用世界快照的 `cell_size_meters` 与海拔复算三维平方距离。（`规则/附近.json`、`game/features/weizhi/service.py`）
20. **附近修士过滤与截断**：先并发取候选、出战道侣、人物公开摘要、公开状态、队伍与宗门同行摘要，缺摘要或 `appears_nearby` 为假者剔除，再按 `visible_limit` 截断；`candidate_limit_reached` 或可见条数超限时置 `truncated`。（`game/features/weizhi/service.py`）
21. **分页与拒绝**：页码不是正整数抛 `NearbyPageError`（`invalid_page`），`page > 1` 且起始下标已越过可见条数抛 `NearbyPageError`（`missing_page`）；切片写成 `start = (page - 1) * page_size`、`has_next = stop < len(visible)`。（`规则/附近.json`、`game/features/weizhi/service.py`）
22. **附近地点边界**：非地表空间直接返回空结果；按 `distance_squared`、`xy`、`name` 升序后只取前 `最多数量` 条；地点功能只保留 `_visible_functions` 认可的项目。（`game/features/weizhi/service.py`）
23. **方向与距离算法**：方向取 `(sign(dx), sign(dy))` 查方向表，偏移 `(0, 0)` 返回空串；距离平方为 0 返回同处措辞，否则开方、除以 `每里米数` 折成里，再四舍五入到 `约数步长` 的整数倍且下限为一步。（`game/features/weizhi/presentation.py`、`game/features/weizhi/service.py`）
24. **非地表清场**：`current` 在非地表空间把 `available_functions` 与三类池全部清空，并用宗门核心的 `membership`、`sect` 解析出 `space_name`。（`game/features/weizhi/service.py`）

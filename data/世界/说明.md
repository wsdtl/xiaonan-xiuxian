# 世界数据包

## 功能

### 一、启动期把规则读死

1. **依赖与初始化**：世界地点服务启动时先要求 JSON 数据服务已经就绪，否则抛「JSON 数据服务必须先于世界地点服务启动」；再按地势、区域、地形分区、地点功能、地点、世界六类的顺序逐类建立索引，六类全部通过才记为已初始化并交出一份世界状态，重复启动直接抛「世界地点服务已经初始化」。
2. **世界唯一**：`世界` 实体必须且只能有一份，多一份或少一份都报错；`出生地` 去掉首尾空白后必须是已登记的地点名。（`内容/晓楠修仙界.json`）
3. **地势硬校验**：`地表高度` 必须是非空二维整数数组，行数等于 `坐标边界` 里 `y轴` 的长度、每行列数等于 `x轴` 的长度；`海拔范围` 必须恰好等于高度表的真实最小值与最大值（-33333 与 28710）；`水平每格米数` 必须是正整数（10000）。（`规则/地势.json`）
4. **区域域**：每个区域只许出现 `类别`、`坐标带`、`说明` 三个字段，`类别` 与 `说明` 必须非空；`坐标带` 按 `y` 分层，每层只许 `y` 与 `x轴`，`y` 不得越界或重复，`x轴` 区间必须有序、彼此不重叠且落在边界内；整个区域必须四向连通、完整覆盖 `x轴` [0, 99] 与 `y轴` [0, 99] 的 10000 格且互不重叠，缺格或多格都报错。（`内容/<区域>/<区域>.json`）
5. **地形域**：`地形分区` 必须是字典列表，每片只许 `名称`、`地形`、`坐标带`，`名称` 与 `地形` 必须非空且 `名称` 唯一；连通性、完整覆盖与互不重叠的要求与区域相同；每片使用的地形必须另有同名 `战场环境` 实体，否则报「地形缺少同名战场环境」。（`规则/地形分区.json`）
6. **地点字段闭合**：地点主体只许出现 `坐标`、`说明`、`可用功能`、`功能配置`，以及 `地点功能` 为已启用功能声明的可选字段（当前是修士/灵兽的阶级与数量区间）；多一个就报「存在未声明字段」。`坐标` 必须是两个整数，`说明` 必须非空。（`内容/<区域>/<地点>/<地点>.json`）
7. **坐标与区域对齐**：地点坐标不得重复；地点所属目录指名的区域必须与按坐标反查出来的区域一致，地形必须落在某片地形分区内，两处对不上都在启动期报错。
8. **派生池就绪**：每个地点按自己的地形要求 `灵植-<地形>` 与 `灵矿-<地形>` 两个池都已登记在基础物品中，缺一个就报「派生资源池无效」。（`规则/地形分区.json`）

### 二、地点功能与同目录内容

9. **功能定义校验**：`地点功能` 必须是字典列表，每项只许 `名称`、`同目录内容`、`要求`、`地点配置`，`名称` 必须非空且不重复，`地点配置` 必须是布尔值。（`定义/地点功能.json`）
10. **同目录内容白名单**：`同目录内容` 只接受「道侣 / 敌人 / 商店 / 炼器工匠 / 炼丹师 / 阵师」，出现别的取值即拒绝。（`定义/地点功能.json`）
11. **要求字段**：`要求` 只许 `非空字段` 与 `正数范围字段` 两个键，两者不得交叉；字段名必须属于地点的已声明字段；`正数范围字段` 的值必须是两个顺序正整数（`修士数量区间`、`灵兽数量区间` 走这条）。（`定义/地点功能.json`）
12. **按功能汇总要求**：地点声明的每个功能把自己的 `非空字段` 与 `正数范围字段` 合并成一份必填集合，再逐字段校验非空或正整数范围；地点里出现不属于任何已声明功能的可选字段就报「字段没有对应功能要求」。
13. **专属配置缺失检查**：`功能配置` 的键必须是 `可用功能` 的子集且每个值都是对象；标记 `地点配置` 为 true 的功能必须在该地点的 `功能配置` 中恰好出现一次，缺失就报「缺少专属功能配置」。（`定义/地点功能.json`）
14. **实体与池落地**：`商店` 要求同目录存在 `<地点>商店`，且该文件的归属地点就是本地点；`炼器工匠`、`炼丹师`、`阵师` 要求实体来自同目录文件，并且不得重复保存 `地点` 字段；其余内容走 `<地点><内容>` 池，池成员必须都落在该地点目录内。（`定义/地点功能.json`）
15. **专属功能读取**：按功能名读专属配置时，先反查声明该功能的地点，数量不等于 1 就报「地点专属功能必须且只能有一个地点」；再要求该地点的 `功能配置` 里这个功能名对应的是一个对象。
16. **实体字段契约**：字段契约数据为「道侣 / 炼器工匠 / 炼丹师 / 阵师」四类各自声明一份 `必填字段`；世界道侣、炼器工匠、炼丹师、阵师各自的领域核心在启动时按这份契约逐实体校验。（`定义/字段契约.json`）

### 三、地点查询与派生视图

17. **查询入口**：地点查询必须在地点名与坐标之间恰好给一个，两个都给或都不给都抛「地点查询必须只提供地点名或 xy」；按名查要求该地点已登记，按坐标查先过边界校验，越界抛「xy 超出世界边界」。
18. **野外回退**：按坐标查不到登记地点时，地点名与地点键都为空串，区域改由按坐标反查得出，地形、海拔与战场环境编号仍照常返回。
19. **派生池字段**：地点视图默认带灵植池（`灵植-<地形>`）与灵矿池（`灵矿-<地形>`）——但只要该地点的任一 `功能配置` 写了 `可采集: false`（门面地点如宗门园区就是这么写的），两个池都清空、不摆上采集面板（池文件本身照旧登记）；内容集合里含「道侣」且地点非空时才给道侣池（`<地点>道侣`），敌人池只在旧的 `刷新区间` 存在时派生；新的探险按阶级直接取 `<阶级>修士` / `<阶级>灵兽` 池，敌情由修士/灵兽阶级区间与数量区间决定。
20. **行路编排入口**：行路编排先确认规划器已经构建，再把起点坐标与目的地各过一次地点查询，最后交给行路规划器；未初始化时抛「世界地点服务尚未初始化」。

### 四、地图快照

21. **快照协议**：地图快照在初始化时一次构建，协议标识固定为世界地图展示契约、版本号为 2，内含世界名称与说明、出生地、坐标边界、每格米数、海拔范围、100×100 地表高度场、区域、地形分区、地点与道路。
22. **每块坐标域派生**：区域与地形分区都附带外接边界、标签坐标（取最接近格重心的格子，距离相同时按 `y`、`x轴` 取小）、格数与坐标带；区域另带与之相交的地形分区名单；坐标带把同一 `y` 上的 `x轴` 合并成连续区间。
23. **排序与消费方**：区域按纵向下界、横向下界与 `名称` 排序，地形分区按 `名称` 排序，地点按纵坐标、横坐标与 `名称` 排序；公开地图玩法、位置玩法的附近地点，以及交易与锻造、炼丹、炼阵的地点对齐，都只读这份快照。

### 五、道路

道路按七类保存，当前 121 条；道路保存连续水平坐标，运行时海拔从地势读取，世界只负责查询与行程规划。

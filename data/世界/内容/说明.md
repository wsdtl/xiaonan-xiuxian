# 世界 JSON 关系说明

世界内容采用“世界 -> 区域 -> 地点 -> 同目录内容”的层级。目录和文件名就是地点身份与玩家名称；JSON 主体只保存地点业务数据。当前共 81 个正式地点。

## 层级关系

```text
晓楠修仙界.json
  ├─ 出生地 ------------------------------> 某个地点文件名
  ├─ 道路 --------------------------------> 道路/*.json
  └─ 行程规则 ----------------------------> 世界/行路/规则/行程.json

地势.json
  └─ 坐标边界 + 水平尺度 + 海拔范围 + 地表高度

地形分区.json
  └─ 85 片地形的名称 + 地形 + 坐标带

<区域>/<区域>.json
  ├─ 类别 + 坐标带 + 说明
  └─ <区域>/<地点>/<地点>.json
          ├─ 坐标 -> 地形分区.json -> 灵植/灵矿池
          ├─ 修士功能 -> 同目录 <地点>道侣.json
          ├─ 探险功能 -> 同目录 <地点>敌人.json
          ├─ 讨伐功能 -> 同目录讨伐定义与独立首领、辅助、属从、奖励来源
          └─ 单次遭遇敌人倍率 ------------> 玩法/探险/规则/探险.json
```

当前世界只有一个界，不设置位面层或跨界坐标。`x`、`y` 像经纬度一样唯一定位全境 `0..99` 的100×100个地表位置；每格尺度和海拔都由 `地势.json` 定义。11 个区域的坐标带共同完整覆盖全境且互不重叠，每个区域必须四向连通；地点坐标必须落入目录所属区域、保持全局唯一，出生地必须指向真实地点。

## 世界与区域文件

`晓楠修仙界.json` 只定义世界说明、出生地、道路和行程规则。唯一的 `地势.json` 自行定义坐标边界、水平尺度和海拔范围，不需要世界再次引用。区域文件只定义区域类别、不规则坐标带和说明；区域海拔范围与所含地形都由世界服务按真实坐标域计算。世界与区域不保存地点列表，地点所属区域仍由 `世界/内容/<区域>/<地点>/` 的目录路径确定。

区域名称来自文件名；地点目录和地点主体文件名必须相同，二者共同构成地点身份。重命名地点必须同步移动目录、改主体文件名、改同目录池文件名，并更新道路和出生地引用。

## 地点文件

地点文件负责：

- 二维 `坐标`；区域由目录路径确定，海拔从地势取得；
- 地点说明；地形由坐标所在的全境地形分区确定；
- `可用功能`；
- 由坐标和可用功能派生的灵植、灵矿、道侣和敌人资源池；
- 普通探险每场敌人数倍率范围。

地点的行政层级由目录结构表达：州目录本身是州级行政目录，州下地点是州辖三级地点；防线、荒野和特殊地点位于各自区域目录下，不虚构行政层级。地点不再写 `地点类别`、`行政层级`、`形制` 或 `显示名称`，也不在代码中用同名字段补造一套平行分类。

`交易`、`锻造`、`炼丹` 和 `炼阵` 是地点功能声明，不是世界服务要执行的业务。地点主体声明功能后，必须在同目录放置对应主持实体：`<地点>商店.json`、`<地点>炼器工匠.json`、`<地点>炼丹师.json` 或 `<地点>阵师.json`。主持实体的目录就是唯一地点归属，不再保存重复的 `地点` 字段，也不允许在全局领域目录维护一份地点名单。

功能与同目录内容必须保持一致：提供修士交互的地点必须存在 `<地点>道侣.json`，提供探险的地点必须存在 `<地点>敌人.json` 和 `单次遭遇敌人倍率`。地形材料池固定由坐标所在的地形派生为 `灵植-<地形>` 与 `灵矿-<地形>`，由采药和采矿玩法使用。倍率范围由每个敌方编组独立使用，形成该编组人数，不再与全场正式单位数相乘。世界微服务负责校验并返回这些派生关系；具体命令与玩法状态由探险业务服务实现。

地点只保存二维坐标。地点海拔始终由 `地势.json.地表高度[y][x]` 推导，不能在地点中重复保存第三个坐标或单独调整高度。

`地形分区.json` 是全境唯一的地形事实源。85 片地形以独立坐标带完整覆盖10000格，每一片都必须四向连通，彼此不允许重叠、缺口或默认兜底。区域与地形是两套独立分区，运行时通过 `(x,y)` 相交；登记地点与未登记坐标使用完全相同的解析方式。

## 地势文件

`地势.json` 覆盖 `x=0..99`、`y=0..99` 的全部整数坐标，共100行、每行100项。东、西、南边缘以外海收束地界，东南离岸角落下切为万丈天渊，北缘则由烬脊与天裂原有高地连成封界群山；这些边界不改变内陆各区域原有的高度特色。高度函数直接查表：

```text
H(x, y) = 地表高度[y][x]
```

分辨率为1，水平每格10000米，所有高度都是整数米。海平面为 `z=0`，当前地表从东南天渊的-33333米延伸到无光崖的28710米；负高度既包含湖泽、河口和湿地，也包含正式外海与天渊底部，不表示地下层。南方湖泽与河口保持低地，镇岳防线整体抬升，烬脊群山和天裂禁地形成万米级高地。详细契约见 [地势说明.md](地势说明.md)。

## 道路文件

`道路` 目录按官道、乡道、山道、堤道、军道、荒径和栈道拆成七个文件，共118条道路，覆盖全部81个地点并保持全境连通。每条道路只保存起点、终点和连续的二维坐标；高度、坡度、爬升与距离全部从地势和地图尺度计算，不复制进道路。道路由统一山河规划按地形与坡度寻路，不能为了视觉连线穿过无关城镇。

```text
道路起点/终点地点名
+ 道路逐格坐标
+ 地势高度表
+ 水平每格10000米
-> 有方向的道路剖面
-> 比较所有候选路线
-> 取得最优行程并生成叙事
```

道路默认双向，但上山和下山必须分别计算。所有已登记地点始终可达；海拔和坡度只参与路线权重与行程描述，不构成人物准入条件。未来境界可以改变赶路方式、速度和措辞，但不能封锁目的地。详细契约见 [道路/说明.md](道路/说明.md)。

## 道侣文件

道侣文件根节点是数组，每名道侣使用 `50` 前缀六位编号。道侣通过以下数据组合：

```text
+ 角色/规则/主体/道侣.json.角色类型与成长规则
+ 战斗/定义/属性.json 默认值
+ 道侣实体.属性覆盖与实力波动
+ 角色/规则/成长/修士修炼.json
+ 角色/规则/主体/道侣.json 的好感和资质修正
-> 道侣关系与培养实例
```

道侣 `结交.灵植池` 引用灵植文件名，`圆满回礼` 使用六位物品编号、两位品级编号和数量。结交业务只需按这些稳定引用取得定义，不能依赖展示名称。

每名道侣通过 `功法池`、`真意池` 和 `气机池` 显式引用 `战斗/内容/功法/池/道侣`、`战斗/内容/真意/池/道侣` 和 `战斗/内容/气机/池/道侣` 下自己的候选池文件。个人池从全池逐角色建立，不使用公共道侣池兜底。

道侣共同使用 `角色/规则/主体/道侣.json.本命武器.器律池` 中的四阶公共候选池，但每名世界道侣必须保存自己的本命武器名称、等级、经验和器律列表。世界实体不重复公共池名；未来某名道侣确有专属器律候选规则时，再为该实体设计明确的覆盖协议。

每名道侣还必须显式保存来自 `角色/定义/性别.json` 的固定性别。当前 264 名道侣严格保持男 132 名、女 132 名；每个地点内部的男女数量最多相差一人。性别属于道侣身份，不得由生成器随机，也不得被丹药或其他物品改变。

## 敌人文件

敌人文件根节点是“敌人名称 -> 定义”的对象，没有六位敌人编号。一次敌人实例由以下数据组合：

```text
敌人定义
-> 按权重从展开后的敌人池抽取
-> 按我方玩家编组数量生成敌方编组
-> 每个编组独立使用地点.单次遭遇敌人倍率范围决定人数
-> 每个编组独立抽取成员、等级和属性
-> 在等级范围内确定等级
-> 通过角色规则按实际等级命中六阶规则
-> 取得对应功法池、真意池和气机池
-> 属性默认值 + 成长规则初始属性 + 实体属性覆盖
-> 修士读取共享成长，灵兽读取实体完整每级成长
-> 对实力波动列出的属性独立波动
-> 形成参战者快照
```

所有敌人都显式保存 `角色规则`。修士敌人指向 `角色/规则/主体/敌方修士.json`，灵兽指向 `角色/规则/主体/灵兽.json`；两类规则使用同一套六阶字段协议，并按实际生成等级选择修行槽位、候选池、速度成长、控制抵抗率和韧性。

敌方修士的性别由主体规则在生成实例时从修士性别定义中等概率随机，地点敌人文件不保存固定性别。灵兽不使用修士性别定义。

敌方修士共同使用的四阶器律池由 `角色/规则/主体/敌方修士.json.本命武器.器律池` 定义，武器等级直接用生成出来的实际等级；世界敌方修士实体的 `本命武器` 只保存该武器独有的名称和一级基础攻击。灵兽天生以肉身为战斗器体，不设本命武器、不写空器律池，也不为满足字段整齐而伪造器律；对应的攻击、血气和防御全部由灵兽实体自身更强的完整 `每级成长` 承担。

敌人的等级范围可以跨越阶梯边界，因此池不能直接写死在敌人定义中。敌方修士通过角色规则引用 `角色/规则/成长/修士修炼.json`；灵兽不套公共经验曲线，按等级命中 `角色/规则/主体/灵兽.json` 里唯一一个 `阶梯`，由物种实体的 `每级成长` 直接给出完整肉身成长值。灵兽每级血气为 `14–22`、攻击为 `1.2–2.1`、防御为 `1–1.9`，不再套用弱化修士尺度。所有属性名都必须来自 `战斗/定义/属性.json`。

普通探险的地域角色边界固定如下：南方六州只使用灵兽，北方朔风荒原、寒渊林海、烬脊群山和天裂禁地只使用敌对修士，镇岳防线同时存在敌对修士与灵兽。该边界描述的是同目录敌人文件的组成，不要求防线每一场战斗都固定生成两类角色。

敌对修士可以在名称中带所在地，表达其驻守、潜伏或活动身份。灵兽名称必须是可以脱离地点独立成立的物种名，不添加地点前缀；出没地点由敌人文件所在目录表达，不能把归属重复塞进物种名称。

敌人不重复保存所在地材料池。普通探险不掉落地形灵植或灵矿；灵兽按完整名称派生 `兽宝-<灵兽名>`。只有无法由身份推导的特殊掉落才写入 `掉落.额外物品池`，当前敌方修士的恢复丹属于此类。`交锋所得.本命武器经验` 关联 `物品/炼器/规则/本命武器.json.经验`。掉落结算属于探险业务，不属于战斗核心。

## 池展开规则

地点的基础池由关系派生。运行时应先取得全部候选池并展开合并，再按对象权重抽取，不能先抽文件再抽对象，否则文件拆分方式会改变概率。

```text
地点坐标与功能
-> 取得同目录敌人池
-> 合并敌人额外物品池与灵兽独有兽宝池
-> 展开每个文件的对象
-> 合并候选
-> 按编号或名称决定是否去重
-> 按我方编组数量生成敌方编组
-> 每个编组在地点倍率范围内独立确定人数
-> 同场优先抽取不同敌人
-> 候选不足时才允许重复抽取
```

## 修改检查

- 新地点必须位于地势边界及其目录所属区域坐标带内，并使用唯一坐标；地点不得重复保存地形。
- 新增或调整区域时必须保持11个区域完整覆盖全境、互不重叠且各自四向连通。
- 新增或调整地形分区时必须保持全境完整覆盖、互不重叠且每片四向连通，所用地形必须存在对应战场环境。
- 新地点只保存唯一 `(x, y)`；修改地势后只需同步区域高度范围并重新校验地点海拔。
- 新地点必须接入道路网络；修改道路时检查坐标连续、端点一致和出生地可达性。
- 改地点名称时必须同时移动地点目录、重命名地点主体及其全部同目录内容文件，并同步出生地、道路和全部地点池引用。
- 提供探险的地点必须配置两个整数构成的 `单次遭遇敌人倍率`，且均大于零。
- 地点专属功能的参数必须写在地点主体的 `功能配置.<功能名>` 中；业务服务只能通过世界核心按地点功能读取，不能从全局玩法规则按地点名读取。
- 商店主体统一保存 `品级`、`真意目录` 和 `气机目录`，不得再通过区域货源组间接展开。
- 修改敌人等级时必须核对其实际等级命中的六阶构筑池；南方聚居地、防线、北境和禁地不能继续共用同一低阶范围。
- 检查地域角色边界：南方六州不得出现修士敌人，北方四域不得出现灵兽，镇岳防线的总池必须同时包含两类。
- 灵兽名称必须全局唯一且不带所在地点前缀；移动出没池时不应被迫改物种名。
- 每种地形必须存在同名灵植池和灵矿池；每种灵兽必须存在以自身完整名称命名的兽宝池，池内至少包含三项 `21` 前缀兽宝。
- 改道侣编号时会破坏持久化身份，禁止修改已有编号。
- 新增或移动道侣时必须保持世界男女总数相等、单个地点相差不超过一人；不得为世界敌方修士写死性别。
- 人物、道侣和敌方修士主体必须显式引用四阶器律池；世界道侣必须保存个人本命武器状态但不得机械复制主体公共池，灵兽不得出现本命武器或器律池。
- 改池文件名时检查地形命名、道侣喜好、敌人额外掉落和炼药炼器规则。
- 世界数据能加载不代表业务已实现；不要在世界 JSON 中塞入流程状态。

讨伐属于地点同目录内容：地点主体声明 `讨伐` 后，必须同时拥有同目录的讨伐定义、首领池、辅助池和属从池。普通敌人池不会回退到讨伐，具体地点的首领与属从来源彼此隔离。

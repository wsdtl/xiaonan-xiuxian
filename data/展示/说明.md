# 展示 JSON 总览

`展示`只决定已经发生的游戏事实怎样命名、着色和组织，不参与战斗、行路、资产或位置裁定。每个一级目录对应一个消费领域，根目录不再平铺业务 JSON。

展示目录只保存模板、按钮、图标、分页和排序，不保存地点商店目录、主持者、价格、开放阵法或任何可执行业务事实；这些事实由世界和领域核心从内容 JSON 返回后再套用展示模板。

| 目录 | JSON 职责 | 消费服务 |
| --- | --- | --- |
| `战斗` | 战报标准化、视觉与界面协议 | 战斗核心、静态战报页 |
| `行路` | 路线事实的行程措辞与境界叙事 | 世界核心、行路玩法 |
| `纳戒` | 玩家资产的大类、小类、排序与分页 | 玩家资产核心、纳戒玩法 |
| `位置` | 距离方向、回复文本、图标与按钮 | 位置查看玩法 |
| `道侣` | 结交回复、图标与按钮 | 道侣结交玩法 |
| `探险` | 探险开始、进度、分页总结与强联动按钮 | 普通探险玩法 |
| `闭关` | 闭关开始、整轮进度、分页总结与强联动按钮 | 闭关玩法 |
| `采药` | 采药开始、整轮进度、分页总结与强联动按钮 | 采药玩法 |
| `采矿` | 采矿开始、整轮进度、分页总结与强联动按钮 | 采矿玩法 |
| `宗门战` | 战书状态、错误文案、历史分页与强联动按钮 | 宗门战玩法 |
| `宗门生产` | 灵脉、灵田状态文本与收取按钮 | 宗门资源生产玩法 |

读取规则按领域目录交付数据集：

```text
展示/战斗/*.json       -> 战斗展示（对象）
展示/行路/*.json       -> 行路展示（对象）
展示/纳戒/*.json       -> 纳戒展示（对象）
展示/位置/规则/*.json  -> 位置展示（对象）
展示/位置/按钮/*.json  -> 位置展示（字典列表）
展示/道侣/规则/*.json  -> 道侣展示（对象）
展示/道侣/按钮/*.json  -> 道侣展示（字典列表）
展示/探险/文本.json     -> 探险展示（对象）
展示/探险/按钮.json     -> 探险按钮（字典列表）
展示/闭关/文本.json     -> 闭关展示（对象）
展示/闭关/按钮.json     -> 闭关按钮（字典列表）
展示/采药/文本.json     -> 采药展示（对象）
展示/采药/按钮.json     -> 采药按钮（字典列表）
展示/采矿/文本.json     -> 采矿展示（对象）
展示/采矿/按钮.json     -> 采矿按钮（字典列表）
```

文件名就是数据集内的稳定数据名。移动或改名后，消费服务必须直接使用新数据名；不保留旧路径或旧数据名兼容。

## 公共边界

- 展示 JSON 只能格式化已经产生的结构化事实，不能创造事件、改变查询范围或修改结算结果。
- 玩家可见文案、图标、颜色、按钮名称和命令来自 JSON，前端与命令层不维护第二份展示定义。
- 按钮只声明动作编号、名称、完整命令、行为和样式；触发后仍须重新经过状态守卫和业务校验。
- 修改 JSON 后先运行 Prettier、JSON 数据服务初始化和对应消费服务测试。

# 公共回复消息协议

`message/` 是业务层与通信驱动器之间的协议中间层。业务只描述要展示的内容，驱动器负责把同一份消息转换为 QQ Markdown、本地 Markdown 或纯文本。

业务代码不得直接拼接 Markdown 引用符号、粗体、斜体、QQ 键盘或平台原生请求字段。

## 标准回复结构

```python
from message import Action, M

reply = (
    M.document()
    .header("人物创建完成")
    .inline_section("创建结果", "成功", icon="system")
    .section("人物", icon="player")
    .row(("姓名", "林远"), ("性别", "男"))
    .row(("境界", "灵动"), ("等级", 1))
    .section("出生地", icon="map")
    .field("地点", "溪隐台")
    .row(("坐标", "8, 8"), ("海拔", "2360 米"))
    .section("初始资源", icon="recovery")
    .row(("血气", "100 / 100"), ("精神", "100 / 100"))
    .field("灵石", 10000)
    .section("初始物资", icon="inventory")
    .item(1, "小还丹 × 3")
    .item(2, "养神丹 × 2")
    .note("数据已保存")
    .action(
        Action(
            action_id="view-character",
            label="查看",
            data="查看人物",
            behavior="callback",
        )
    )
    .build()
)
```

## 内容构造

| 构造方法 | 用途 | 回复表现 |
| --- | --- | --- |
| `header(...)` | 消息主标题 | 由 Markdown 渲染器统一加粗；只能是单行普通文本 |
| `inline_section(..., icon=...)` | 通知、结果等短信息 | 图标、标题和内容位于同一行 |
| `section(..., icon=...)` | 开始一个正文栏目 | 生成带图标的栏目标题和归属范围 |
| `line(...)` | 栏目内普通正文 | 生成栏目正文行 |
| `field(label, value)` | 单个字段 | 普通文本 `标签: 值` |
| `row((label, value), ...)` | 同行字段组 | 使用统一字段分隔符 |
| `item(index, ...)` | 有序列表项 | 只能使用正整数编号 |
| `blank()` | 栏目内空行 | 保持正文归属 |
| `note(...)` | 正文后的附加说明 | 与正文分隔显示 |
| `image(...)` | 图片消息中的正文图片 | 由驱动器决定平台图片格式 |
| `action(...)` | 结构化交互 | 不进入正文，由驱动器生成按钮或动作 |

正文联动与底部按钮不是同一层：

- `M.command(...)` 用于正文中自然出现的可操作名称，例如商品名、功法名、物品名和地图入口；`submit=False` 表示只填入命令，适合需要数量、槽位等后续参数的操作。
- `Action` 用于底部按钮，只承载当前位置面板、地点专属面板复现和当前业务的强联动动作。
- 同一条完整命令不能同时出现在正文联动和底部按钮中。正文已经提供入口时，底部只保留其它规则允许的动作，避免重复显示。
- 正文中的普通事实、状态、地点功能和分页信息不自动按钮化；只有具有明确命令语义且不与底部动作重复的文本才建立联动。

`line`、`field`、`row`、`item`、`blank` 必须先调用 `section`。消息内部使用稳定的列表序号，不能把用户 ID、请求 ID 或数据库键直接展示出来。

## 图标位置

图标只属于栏目标题，使用位置固定为：

```python
.inline_section("创建结果", "成功", icon="system")
.section("人物", icon="player")
.section("出生地", icon="map")
.section("初始资源", icon="recovery")
.section("初始物资", icon="inventory")
```

`field`、`row`、`item`、`line` 和 `note` 不接收图标。业务传递稳定的英文分类键，消息层负责转换为实际图标；业务文本中不手写图标字符。

常用中立分类：

| 分类键 | 用途 |
| --- | --- |
| `system` | 操作结果、系统通知 |
| `notice` | 警告、待处理事项 |
| `player` | 人物、玩家资料 |
| `map` | 地点、区域、坐标 |
| `recovery` | 血气、精神、恢复资源 |
| `inventory` | 背包、初始物资 |
| `item` | 单个物品详情 |
| `combat` | 战斗信息 |
| `weapon` | 本命武器 |

未知分类键会直接报错，避免不同业务自行创造不统一的图标含义。具体游戏需要新增分类时，使用 `register_icons(source, mapping)` 一次性注册。

## 样式边界

当前协议只保留两种展示层级：

- `header` 的标题强调由渲染器统一生成；
- 正文、字段、列表和说明全部是普通文本。

协议没有斜体语义，也没有 `M.em()`、`Strong` 或 `M.strong()`。业务不应手写 `_文本_`、`*文本*`、`**文本**`，渲染器也不得为字段或列表值追加这些标记。

业务文本如果以 `>` 开头或单独等于 `---` 会被拒绝；引用层级、空行和转义由渲染器统一处理。

## 交互动作

```python
Action(
    action_id="confirm-operation",
    label="确认",
    data="确认操作",
    behavior="callback",
)
```

`action_id` 是一条消息内稳定且唯一的动作编号；它与 QQ 回调事件的 `interaction_id` 不是同一概念。`callback` 必须携带完整命令，`fill` 用于还需要玩家补充参数的输入，`link` 只负责打开链接。按钮的权限提示不能代替业务服务的归属校验。

游戏回复只允许三种按钮来源：当前位置与行路抵达的地点主面板、地点专属业务结束后的地点面板复现、当前业务内部具有直接下一步关系的强联动动作。除此之外不得为了导航便利或装饰统一附加按钮。按钮归属由游戏命令规则决定，公共消息协议和通信驱动器不读取地点、人物或玩法状态，也不自动补充动作。

## 驱动器降级

支持 Markdown 的驱动器使用统一 Markdown 渲染器；不支持 Markdown 的驱动器使用纯文本渲染器。两者读取同一份 `DocumentMessage`，业务层不得根据驱动器分支拼接回复。

公共 `manager` 只接受 `message.Message` 或包含它的 `SendRequest`，QQ 原生 payload 只能在 QQ 适配器内部生成。

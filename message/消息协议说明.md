# 公共回复消息协议

`message/` 是业务与通信驱动器之间的唯一消息协议。业务先构造 Markdown 的标题、栏目、层级与正文，再标记需要美化的片段；驱动器只负责渲染和发送。

业务不得手写 Markdown 引用、粗斜体、公式、QQ keyboard 或平台原生请求字段；颜色、字号、背景与进度条形态也不进游戏 JSON。

## 标准回复

```python
from message import Action, M

reply = (
    M.document()
    .inline_section("创建结果", M.status("成功", tone="positive"), icon="system")
    .section("人物", icon="player")
    .row(("姓名", M.text("林远", tone="emphasis")), ("性别", "男"))
    .section("当前资源", icon="recovery")
    .field("气血", M.progress(100, 100, tone="health", display="value"))
    .action(Action("view-character", "查看", "人物"))
    .build()
)
```

## 文档结构

| 构造方法 | 用途 |
| --- | --- |
| `header` | 消息顶部的人物头；单行引用行，不单独加粗。游戏层由 composer 前置，业务不写 |
| `command_title` | 触发本次回复的命令原文；一层引用，可做成行内按钮。游戏层由 composer 前置，业务不写 |
| `inline_section` | 一行通知或结果 |
| `section` | 正文栏目标题 |
| `line` / `small` | 栏目普通正文 / 整行小字 |
| `field` / `row` | 单字段 / 同字段组 |
| `item` | 稳定有序列表 |
| `blank` / `note` | 空引用行 / 正文后说明 |
| `image` | 公网正文图片 |
| `action` / `actions` | 底部结构化交互（单个 / 批量） |

`line`、`small`、`field`、`row`、`item` 必须先属于一个 `section`。字段用 `标签: 值`，同行字段由渲染器分隔；列表用 `[1]`。相邻栏目之间由渲染器留空行，业务不手写引用符号。

## 游戏回复与系统推送

正式游戏里业务只造正文。玩家命令的回包由 `game/cmd/reply_composer.py` 的 `send_game_reply` 在发送前前置 `header` 与 `command_title`；系统推送走 `send_system_message(message, target)`，不读当前上下文、不加人物头与命令标题，目标必须显式。两条路都最终调用公共 `manager.send`。

## 语义构造

- `M.text("林远", tone="emphasis")`：`tone` 只能用主题登记的语义名，不能传色值。
- `M.status("休息中", tone="positive")`：短状态，不承载句子。
- `M.progress(812, 1000, tone="health", display="value")`：固定宽度、自动夹在 0–100%；实际数值不夹。`display` 取 `none/percent/value/both`。

主题在 `message/theme.py`：栏目标题一层引用、正文二层引用；状态、进度、可点击强调与显式小字都是普通正文。**消息里没有公式**，客户端不渲染公式。

## 正文与按钮

可点击名称统一用引导色，`M.command` 的 `submit` 默认 `False`（只填入、不发送）；玩家侧不许 `submit=True`。要一点即发的只有底部 `Action`。

同一份内容有多条命令时合并成一个分支控件：`查看|藏经阁 借阅 400001`，或每条分支自带完整命令。本地纯文本出口没有可点按钮，命令原文要跟标签一起印出来。

`Action` 只用于底部按钮，遵守三类来源：地点面板、地点专属业务结束后的面板复现、当前业务的直接下一步。

## 安全与驱动器

玩家名、道侣名、物品名与动态数值进 Markdown 前统一转义 `\ { } $ % _ # & ^ ~`；未知语义色、无效进度上限、重复动作编号、未知图标、手写 Markdown 都会立即报错。

- QQ：同一份 `DocumentMessage` 渲染为 Markdown 外框、正文与原生 keyboard；正文纯文本，无公式。
- Local：读同一语义对象，可输出 Markdown 或无公式纯文本，用于调试与断言。
- 天道 Web：读同一份正文与交互，不定义另一套主题或游戏数据。

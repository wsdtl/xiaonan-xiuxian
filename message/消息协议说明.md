# 公共回复消息协议

`message/` 是业务层与通信驱动器之间的唯一消息协议。业务先用构造函数组织 Markdown 的标题、栏目、层级和正文，再用语义构造函数标记需要美化的片段；驱动器只负责渲染和发送。

业务代码不得手写 Markdown 引用、斜体、粗体、LaTeX、QQ keyboard 或平台原生请求字段。颜色、字号、背景和进度条形态不得进入游戏 JSON，也不得在已经生成的 Markdown 字符串上二次查找替换。

## 标准回复

```python
from message import Action, M

reply = (
    M.document()
    .header("人物创建完成")
    .inline_section("创建结果", M.status("成功", tone="positive"), icon="system")
    .section("人物", icon="player")
    .row(
        ("姓名", M.text("林远", tone="emphasis")),
        ("性别", "男"),
    )
    .row(("境界", "灵动"), ("等级", 1))
    .section("当前资源", icon="recovery")
    .field("气血", M.progress(100, 100, tone="health", display="value"))
    .field("精神", M.progress(100, 100, tone="spirit", display="value"))
    .section("初始物资", icon="inventory")
    .item(1, M.command("小还丹 × 3", "查看 小还丹"))
    .small("物资已经存入纳戒")
    .action(Action("view-character", "查看", "人物"))
    .build()
)
```

## 文档结构

| 构造方法 | 用途 | 字号 |
| --- | --- | --- |
| `header(...)` | 唯一消息主标题 | Markdown 加粗 |
| `inline_section(...)` | 一行通知或结果 | 正文 |
| `section(...)` | 正文栏目标题 | 正文 |
| `line(...)` | 栏目普通正文 | 正文 |
| `small(...)` | 栏目内整行说明 | 统一小字 |
| `field(label, value)` | 单个字段 | 正文 |
| `row((label, value), ...)` | 同行字段组 | 正文 |
| `item(index, ...)` | 稳定有序列表 | 正文 |
| `blank()` | 栏目内显式空引用行 | 正文 |
| `note(...)` | 正文后的附加说明 | 正文 |
| `image(...)` | 公网正文图片 | 平台决定 |
| `action(...)` | 底部结构化交互 | 普通短文本 |

`line`、`small`、`field`、`row` 和 `item` 必须先属于一个 `section`。列表编号只能是当前消息中的正整数序号，不能展示数据库键、用户 ID 或请求 ID。

字段使用 `标签: 值`，同行字段使用 `&nbsp;|&nbsp;` 分隔，列表使用 `[1]` 形式。相邻栏目之间由渲染器统一保留一行空引用；栏目内部确有分段需要时使用 `blank()`，业务仍不得手写 Markdown 引用符号。

排版优先利用横向空间：三个以内且值较短的字段使用 `row` 同行展示；长名称、说明、技能效果和战报正文保持独立行。不能为了少一行而制造拥挤、缩小正文，或把不同信息层级强行拼接。

## 语义构造

### 语义文本

```python
M.text("林远", tone="emphasis")
M.text("顾听澜", tone="companion")
M.text("无相", tone="formless")
```

`tone` 只能使用主题中已经登记的语义名，不能传 `#RRGGBB`。普通正文不需要调用 `M.text`。

### 短状态

```python
M.status("休息中", tone="positive")
M.status("等待结算", tone="warning")
M.status("重伤", tone="danger")
```

状态使用紧凑语义色文字，只适合短词，不承载句子或说明。

### 进度

```python
M.progress(812, 1000, tone="health", display="value")
M.progress(72, 100, tone="spirit", display="both")
M.progress(4, 15, tone="positive", display="percent")
```

进度条固定宽度并自动限制在 0%-100%。实际数值不会被限制，超出上限时仍按原值展示。`display` 支持 `none`、`percent`、`value` 和 `both`。

## 唯一主题

主题定义位于 `message/theme.py`。Markdown 结构固定为：

- 主标题使用 Markdown 结构性加粗；
- 普通字段、列表、栏目和 `note` 沿用 Markdown 默认字号；
- 状态、进度、可点击强调和显式 `small` **一律是普通正文**：它们不进公式（2026-10 起）。
  之前它们统一包成公式 `small` 是为了抵消客户端公式基线偏大，但实测客户端根本不渲染公式，
  玩家看到的是源码，所以这条约定已作废。

普通文字始终沿用 Markdown 正文。状态、进度、可点击强调和显式 `small` 也**只是普通正文**——分层靠图标、一级/二级引用与字段分隔，不靠公式；长说明与 `note` 保持原生正文，保证窄屏自然换行。

栏目标题使用一层 Markdown 引用，栏目正文使用二层引用，保留标题与内容的阅读层级。颜色只表达成功、警告、危险和关键进度；普通状态、标题、标签和说明保持客户端默认正文色，不使用大面积背景色块。进度使用五格分段条，避免客户端不稳定的 `rule` 横条。

主题提供以下稳定语义名。它们按用途收敛到少量颜色：

```text
title section label muted emphasis
positive warning danger info mystic companion
health spirit cultivation
metal wood water fire earth formless
```

公式只负责局部可视化：进度条、必要的短状态以及可点击名称。主标题、栏目标题、字段、列表和句子保持 Markdown 原生文字；`M.text` 的语义色不会自动把整行变成公式。可点击名称统一使用引导色，避免按类别铺开彩色。

## 正文与按钮

 再包进 `[...]`，而 **QQ 不解析公式内的链接**——按钮当场失效。天道 Web 走 `webcmd://`，
不受这条限制，但标签同样规范化，两个出口保持一致。公式不是独立消息层，而是这些 Markdown
构造函数中的局部语义片段；**可点名称不进公式**。

`submit` 的规则定死：**命令已经完整（玩家不用再补参数）→ `submit=True`，点了直接发**；
**还差参数 → `submit=False`，只填入输入框**。还差参数却直接发，只会得到一条格式报错。

**同一份内容有多条命令时合并成一个分支控件**：把分支词用 `|` 连在前面、后面跟共享的参数尾巴
（`查看|借阅功法 400001`），点一次回一个选择菜单，每条分支按上面那条 `submit` 规则决定直接发还是只填入。
两种写法都行：**分支词 + 共享尾巴**（`查看|借阅功法 400001`，只写命令词的段继承共享尾巴），
或**每条分支自带完整命令**（`查看 400001 | 人物装配 功法 400001 03`）。

本地纯文本出口（`render_local_message(markdown=False)`）没有可点按钮，**命令原文要跟着标签一起印出来**，
否则那份文本既点不了、也抄不出一条能执行的命令。

`Action` 只用于底部按钮，继续遵守三类来源：当前位置或行路抵达的地点面板、地点专属业务结束后的面板复现、当前业务内部的直接下一步。正文命令与底部按钮不能提交同一条完整命令。

## 安全与转义

玩家名、道侣名、物品名和动态数值进入公式前会统一转义：

```text
\ { } $ % _ # & ^ ~
```

动态文本不能作为原始公式传入。未知语义色、无效进度上限、重复动作编号、未知图标和手写 Markdown 结构都会立即报错。

## 驱动器展示

- QQ 将同一份 `DocumentMessage` 渲染为 Markdown 外框、公式正文和原生 keyboard。
- 本地驱动读取相同语义对象，可按调用场景输出正式 Markdown 或无公式纯文本；纯文本用于明确的调试与断言，不是 QQ 的兼容回退。
- 天道 Web 继续只读取后端消息内容和交互，由 KaTeX 呈现后端公式，不定义游戏数据或另一套主题。

`tools/公式预览/` 是已归档的独立兼容性回归组件，不属于正式消息协议，也不能被游戏业务导入。它默认不装载；需要复验时登记进 `.env` 的 `ROUTER_FOLDERS`。

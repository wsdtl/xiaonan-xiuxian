# 晓楠修仙

> 这份管什么：**入口** —— 怎么跑、改哪儿读哪份、当前规模与验证命令。服务与依赖看 `系统架构.md`，边界与导入看 `微服务边界规范.md`，玩法设定看 `核心设定.md`，写说明看 `说明模版.md`。

数据分两层：`data/<大类>/<组件>/{定义,规则,内容,展示}`，组件名与大类同名时不再多一层。每个组件有独立 `组件.json`，全局入口是 `data/基础/读取规则.json`，归属与布局见 [data/说明.md](data/说明.md)。

正式 JSON 是规则与内容的唯一主体；Python 负责严格读取、公共核心、玩法编排、命令接入和结果展示。

## 当前基线

本仓库以 `a7ea3fe0`（tag `v0-起点`）为素材基线，整理产物为 **v1**。v0 之前的一切——历史交付记录、施工方案、过程读数、兼容分支、一次性改写脚本、生成物——都不继承，只把仍有效的规则边界提炼进正式说明。

- **唯一来源**：组件行为以各自正式规则和组件说明为准；项目结构以本文件、`系统架构.md` 与 `微服务边界规范.md` 为准；运行时状态以实际装载结果为准。
- **无兼容**：正式运行路径只接受当前契约。旧字段、旧 JSON 形态和旧内部导入路径不做双读或隐式回退；当前外部协议行为与业务定义的失败处理按现行规则保留。
- **无历史**：维护目录里不留一次性改写脚本，历史改写只存在于 git 历史里；已清掉的东西由 `tools/架构审查/检查历史遗留.py` 守门，回来就红。
- **规则与判据**：规范里可机械判的条款逐条落到判据，唯一索引在 [tools/架构审查/说明.md](tools/架构审查/说明.md) 的「规则与检查的落差」表。
- **资源生命周期**：本地数据库、凭据、日志、`.runtime/` 和 `.venv/` 不属于可随源码清理的文件。

## 当前保留范围

```text
data/                       正式定义、规则、内容与展示 JSON（7 大类、37 个组件包）
database/                   游戏数据库与运行日志数据库，不进入版本库
.runtime/                   历史备份与控制台媒体，不进入版本库
game/core/                  39 个跨玩法公共微服务，按包注入（见 系统架构.md）
game/features/              50 个具体玩法微服务，不依赖命令协议
game/cmd/                   命令、按钮和 HTTP 触发组件
game/startup/               跨命令、跨核心服务的启动契约
game/config.py              从框架自定义项中解释游戏配置
game/app.py                 游戏微服务的唯一组合根
launch/                     Local、QQ、HTTP 与生命周期适配
message/                    通用消息协议
static/                     14 个展示页面：百科、控制台、战报、全境舆图、装配台、意境，以及八张工具页（补天 / 演阵台 / 万珍殿 / 灵宝谱 / 灵田 / 归元观 / 铜雀台 / 货架）
tools/                      游戏外校核与维护脚本（判据、测量、验收通道）
tests/                      行为与数据契约测试
```

当前数据文件清点为 **2820 份 JSON**，其中 **37 份组件清单**；正式装载结果为 **2783 文档、3687 实体、408 资源池**，注册 **184 条命令、10 条守卫规则**；`game/cmd` 下 **49 个二级命令组件（通用 28、专属 20、后台 1）**。这些数字由 `tools/架构审查/检查文档计数.py` 与现状逐项核对，漂了会红。

天道后台和公开地图是两个独立二级组件：前者只服务开发者管理台，后者通过 `game/features/ditu` 取得 `game/core/world` 提供的只读地图快照与文字概况。`game/core` 放跨玩法公共微服务，`game/features` 放具体玩法微服务，`game/cmd` 只负责命令、按钮和 HTTP 触发，`game/app.py` 是唯一组合根。完整清单与装配顺序见 [系统架构.md](系统架构.md)。

`launch/config.py` 只解释框架自身的项目、监听、日志和路由配置。数据库、控制台凭据及其他业务环境变量必须进入 `config.custom`；游戏侧需要类型转换或校验时统一在 `game/config.py` 完成，不得向框架 `Config` 增加业务字段。

**意境**是后加的一层战斗内强化：不占修行槽位，六条路各管一个战斗子系统，九阶覆盖式。买到的阶是常驻（进场即生效），
战斗里另有一层从零往上爬的动态档、上限同样是买到的阶。升级用的点数叫道行，来自境界突破到头（阶价 1/2/4/6/9/13/18/25/34，
二十个境界对应九阶、所以只发九次），升到一阶就是激活。数据在 `data/战斗/内容/意境/`，命令入口是 `意境`（看 · 升 · 修），
微服务在 `game/features/yijing`。

## JSON 驱动边界

> 本节是**速览**：目录约定的权威在 `data/说明.md`，所有权与依赖的权威在 `微服务边界规范.md`。

- `data/<大类>/<组件>/定义` 声明底层概念、字段和编号规则（组件名与大类同名时省略组件那一段）。
- `data/<大类>/<组件>/规则` 声明运行规则和结算顺序。
- `data/<大类>/<组件>/内容` 保存可引用的正式实体与资源池。
- `data/<大类>/<组件>/展示` 保存战报等展示契约。
- `data/基础/读取规则.json` 声明每个组件的相对路径、正式文件属于哪个数据集、采用哪种结构以及建立哪类索引。
- `data` 不保存数据库、备份或运行媒体；数据库进入 `database`，备份和控制台媒体进入 `.runtime`。
- Python 只固定读取这一份引导文件，不硬编码功法、气机、道路等业务目录；其他微服务按数据集、实体类别或资源池取得数据。
- 所有代码级微服务使用包顶层公共契约，禁止跨目录导入内部引擎、运行模型或加载实现；详见 `微服务边界规范.md`。
- 消息业务统一使用 `user_id`；QQ 的 OpenID 和群聊目标只在 `launch/adapter/qq_protocol` 内解释，回复统一通过 `reply_target`，不向业务层泄露传输目标字段。
- 校核、评分和平衡只在 `tools/` 中运行，不进入游戏进程、存档、抽取和战斗裁定。
- 说明**跟随所属数据**：组件说明写这一包的行为（`## 功能` + `## 数据集`），领域说明只讲数据形态与分组，两层各管各的、不重复。

## 启动

Windows：

```bat
start.bat
```

Linux 或 Docker：

```bash
bash start.sh
```

两个脚本都会在启动前建立并验证 `.venv`，依赖缺失时自动安装 `requirements.txt`；验证失败会重建，不使用已损坏的解释器。

证书目录 `certs/` 不用事先建：程序启动时会自己建出来。**用 HTTP 还是 HTTPS 由证书实际在不在决定**——
没配 `SERVER_SSL_CERTFILE` / `SERVER_SSL_KEYFILE`，或配了但文件还没放进去，就以 HTTP 启动
（后者会打一条告警告诉你怎么启用）；两个文件都在才走 HTTPS。

服务地址取自 `.env` 的 `SERVER_HOST` 与 `SERVER_PORT`（模板 `.env.example` 为 `0.0.0.0:8845`，本机 `.env` 为 `0.0.0.0:8443` 并配 `SERVER_SSL_CERTFILE` / `SERVER_SSL_KEYFILE`，所以浏览器访问用 `https://127.0.0.1:8443`；未配证书时才是 `http://127.0.0.1:<端口>`）。公开全境舆图为 `/world-map`，百科为 `/baike`，天道后台为 `/game-console`，战报页为 `/battle/<战报编号>`，装配台为 `/assembly`，意境页面为 `/yijing`。地图只展示世界 JSON 解析结果，不触发 QQ 命令或游戏行为。玩家命令以运行时帮助注册表为唯一公开清单，状态守卫根据人物是否创建及当前行为、队伍、控制状态统一决定能否执行。天道后台命令保持隐藏，HTTP 登录密码由 `.env` 中的 `WEB_CONSOLE_PASSWORD` 单独提供。

游戏进程不加载 `tools`，也不执行游戏外评分、校核和平衡脚本。

## 打包发布

```bat
.venv\Scripts\python.exe -X utf8 build.py
```

把**游戏本体与 `data/`** 拷进 `BUILD/`——**只放代码与数据**：`.md` 说明一律不进包（要留档加 `--含说明`），
包内只有 `game/`、`launch/`、`message/`、`static/`、`data/`、`main.py`、启动脚本、`requirements.txt`、`.env.example`
与一份机器可读的 `构建信息.json`（含首次部署步骤与不进包清单）。**包内的运行期状态也会剔掉**：
`launch/runtime/server.lock`（单实例锁）不随包走——它跟包覆盖过去会去顶服务器上正被占用的锁，
Windows 下复制会当场报文件占用；程序启动时自己建。打包器还会拦下任何混进包的 `*.lock` / `*.db` / `*.bak`。

默认带**部署自检**：把 BUILD 拷到临时目录、先删掉 `database/log/.runtime`、再按全新部署启动一次，
确认程序自己会建运行期目录。更新时把 `BUILD/` 内容复制覆盖过去即可——`database/`（玩家存档）、
`.env`（每台机器不同的端口与密钥）、`log/`、`.runtime/`、`certs/` **都不进包**，所以替换永远碰不到它们；
首次部署的唯一人工步骤是把 `.env.example` 复制成 `.env`。
开关：`--跳过自检`、`--含工具`、`--含测试`、`--含说明`、`--压缩`。

## 验证

游戏本体只保留 `tests/` 中的行为与数据契约测试；一切架构审查、边界检查、目录与命名校核都属于维护工具，统一放在 `tools/`，不进入游戏进程。

```powershell
.venv/Scripts/python.exe -X utf8 tools/全量核对.py        # 必过 45 项，并发跑（推荐入口）
.venv/Scripts/python.exe -X utf8 tools/验收/发布验收.py    # 慢通道，发布前手动
```

`全量核对.py` 是**必过项的唯一入口**：每支在独立进程里并发跑、各自计时、末尾给一行总账，任一失败整体非零退出。它覆盖架构判据、行为验证、语法与单元测试。慢通道（语料与各类对照、基准回归）合计十几分钟，属**发布验收**，不进必过项。下面这些单跑命令只在定位问题时用。

- **架构判据**（`tools/架构审查/`）：`检查边界.py`（26 项：动态导入边界、框架反向依赖、跨服务导入内部实现、硬编码数据目录、第二套 JSON 读取、微服务包必备文件、中文标识符、文件编码、重复定义、写死机器路径、被忽略却仍在索引里的文件等）、`检查卡形.py`（13 支卡形检查并发总入口）、`检查数据驱动.py`、`检查规则层.py`、`检查战报展示.py`、`检查静态资源.py`、`检查文档计数.py`、`检查历史遗留.py`；全表与「规则 ↔ 判据」索引见 `tools/架构审查/说明.md`。
- **行为验证**（`tools/`）：`验证规则层.py`、`验证契约引擎.py`、`验证组件契约.py`、`验证物品契约.py`、`验证控制台媒体.py`、`验证驱动器派发.py`、`验证QQ传输开关.py`、`验证QQWebSocket.py`、`验证QQWebSocket关闭码.py`、`验证QQ双驱动器生命周期.py`、`验证启动顺序.py`。
- **报告与测量**：`全量数据审查.py`、`卡面说明审查.py`、`渲染战斗文本.py`、`机械化盘点.py`。

`pytest` 是开发期工具，不在 `requirements.txt` 中，需要单独安装：`.venv/Scripts/python.exe -m pip install pytest`。单元测试由 `tools/跑测试.py` 分片并发跑，并在每个进程内用临时数据库隔离，不触碰真实存档。

全部检查都必须为 0 越界。修改 `game/` 或 `launch/` 后应先运行必过项，再运行测试。改动源码后若结果与预期不符，先清除对应目录的 `__pycache__`：陈旧字节码会掩盖源码改动。

字段契约的书写约定见 [data/schema编写规范.md](data/schema编写规范.md)，战斗文本的书写约定见 [data/战斗/内容/文本规范.md](data/战斗/内容/文本规范.md)。
